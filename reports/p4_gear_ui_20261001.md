## 三、两条缺陷（本次发现并修）

### ① `hero_upgrades` 校验目录缺陷 ⇒ 装备阶升级机制被**整表关死**

- **现象（冒烟跑 1）**：`[HamletRoot] hero_upgrades 校验失败 ⇒ 装备阶升级机制关闭（opt-in；如实上报）`
- **根因**：`externalTreeIds` 只列铁匠铺两条 ⇒ `abomination.transform#1..4` 的先决树 `guild.skill_levels` 被判**悬空** ⇒ 整表失败 ⇒ 机制关死（玩家点不动、日志里只有一行"关闭"）
- **修法（唯一真值 = `buildings.json`）**：`BuildingsConfig.TreeIds`（全部建筑树 id，实测 20 条）⇒ `HamletRoot.Gear.cs:101` 与 `ExpeditionComposition.cs:252` 改用之
- **前后对照**：`校验失败 ⇒ 机制关闭` ⇒ **`装备升级树已加载并校验通过：135 树 / 645 等级 ／ 外部树目录 20 条 ✓`**

### ② 组合根覆盖缺陷 ⇒「Hamlet 买了阶、一出征就被覆盖清零，回城自动存档再把空表写盘」（用户授权一行修）

- **位置**：`ExpeditionComposition.cs`（旧写法无条件 `new HeroGearState()`）
- **修法**：`var gear = ExpeditionContext.Gear ?? new HeroGearState();`（`:126`）⇒ 与 Hamlet UI / 存档 / 投影**共用同一实例**
- **取证**：组合冒烟（买阶 ⇒ 出征 ⇒ 回城自动存档）落盘原文见 §四 ③

## 六、deviation（如实标注）

1. 🔴 **拖动阈值本身无法 headless 复验**（引擎 drag 需要真实鼠标移动）⇒ 本件证据 = ① 两端**都已接线**到引擎内建 API（源 `_GetDragData` ＋ 目标 `_DropData`）② **落孔入口**已跑（`--hamlet-gear-drop` 走的就是 `_DropData` 的同一个 `HeroDropped` 回调）③ 点击兜底可跑
2. 🔴 **③ 的「退出重进」半今日不可验** ⇒ 见 🆕 `O-106`：`SaveController.Load` **生产调用 0 处**（`rg -n 'Load\(' darkest/scripts` 只命中定义 `SaveController.cs:91`）⇒ 存档**只写不读**。本件把**写侧**做到位（落盘原文含 `Weapon: 2`），**读侧**（启动读档）不在 `M6u` 授权内 ⇒ 归属存档 / `P4 ①`
3. ⚠️ 组合冒烟会**循环**（回城后新城池实例再读一次 `--hamlet-embark`）⇒ 读数里出现多轮循环（实测 8 轮）；这是**冒烟旗标语义**，不是产品行为 ⇒ 用 `--quit-after` 收口
4. ⚠️ `HamletRoot.Build.cs`：`--hamlet-embark` 的提前 `return` **移到方法末尾**（否则组合冒烟在买阶之前就切场景 ⇒ 装备阶冒烟整段被跳过；同族坑见 `MainMenuRoot.cs:50` 的注释）✓
5. ⚠️ 孔 / 方块的**视觉**取模板 tscn（缺模板 ⇒ 代码回落构建，不崩、不静默）；美术细化留 UI 域后续
6. ⚠️ 金币口径**保持不动**（750/1750/3000/6000 与当前经济产出差约 250 倍）⇒ 冒烟用**公开 API** 播种（`Economy.AwardContent` / `HeirloomStock.Add`）；数值改动走策划请单
