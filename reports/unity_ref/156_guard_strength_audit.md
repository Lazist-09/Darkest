## 4. 🔴 而这条审计**也暴露了修复它的难点** —— 且我实测确认了**极限**

```
📊 **要让它能区分【手写】与【插值】** ⇒ 必须让两种形式【不同形】：
   · 现状：插值 `string.Join(" / ", legalTargets)` ⇒ `enemy_hp / enemy_resist`
     ⇔ 手写（我上轮改回的那个）**也写成** `enemy_hp / enemy_resist` ⇒ ⚠️ **同形**
   · ✅ **已做修法**：把插值分隔符改成**全角**（` ／ `，与 `UnlocksConfig` 一致）
     ⇒ 则**手写若用半角** ⇒ 不同形 ⇒ ✅ **断言能区分** ✓
   ⇒ ⚠️ **代价**：改报错文案的一个字符 ⇒ ✅ **零行为** ✓
   🎖️ **判据（第 287 条）**：**"要区分'手写'与'插值'——
      先让它们【不同形】；同形时任何断言都区分不了"** ✓

🔴🔴 **而我实测确认了这条判据的【极限】**：
   · **破坏实验 A**：插值 ⇒ **手写半角** `enemy_hp / enemy_resist`
     ⇒ ✅ **防线【红了】**（**不同形**）✓
   · **破坏实验 B**：插值 ⇒ **手写全角** `enemy_hp ／ enemy_resist`
     ⇒ 🔴 **防线【仍绿】**（**同形**）⚠️
⇒ 🎖️ **即：换分隔符只能挡住"手写用了旧分隔符"，
   挡不住"手写恰好抄了新的那一种"** ⇒ ✅ **这是【断言法的固有极限】** ✓
   📌 **判据（第 289 条）**：**"我把'两处同形'改成'不同形'了 ——
      但【对方也知道新形式】时呢？（形式区分不是根治）"** ✓
      ⇒ ✅ **根治只能靠【只有一处书写】**（即：报错读常量，而非两处各写）——
         **而那已经是现状**（`string.Join(legalTargets)`）✓
      ⇒ 🎖️ **所以：那处【源码】已根治；而【测试断言】永远只能验'当前形态'"** ✓
```
