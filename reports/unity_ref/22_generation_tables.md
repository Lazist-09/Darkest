## 1. 🎖️🎖️ `generation` 是**任务生成系统** —— 5 个子键各司其职

```
`generation` 的 5 个子键：**`number`** · **`dungeon`** · **`difficulty`** · **`type`** · **`rewards`** ✓
⇒ 🎖️ **即：参考项目会【按城镇访问次数、玩家等级、地牢解锁进度】自动生成任务** ✓
   🔴 **而我方【整块没有】** —— 我方 `quest_reward` 只有 `dungeon_types` + `amount_table` ⚠️
   📌 这正是 `PLAN_adoption §4` 说的"**A8 是 P17（M14 Quest 层）的载体**" ✓
```

### ① `number` —— 每次进城给几个任务

```
`number_of_quests_per_town_visit_table` = **[2, 5, 7, 8, 9, 10, 11, 12]**（8 档）✓
⇒ 🎖️ **即：进城次数越多，可选任务越多**（2 → 12）✓
   📌 而我方 `unlocks.json` 那边有"名册上限/招募数"的曲线 ⇒ **同族的"随进度增长"设计** ✓
```

### ② `dungeon` —— 地牢解锁门槛

```
`generated_dungeons`：
   `crypts` 需完成 **2** 个任务 · `weald` **3** · `warrens` **4** · `cove` **4** ✓
`max_number_of_generated_quests_per_dungeon` = **4** ✓
⇒ 🎖️ **地牢按"完成的任务数"逐个解锁** ✓
```

### ③ `difficulty` 与 `restriction` —— 等级 → 难度

```
`generated_resolve_level_difficulties`：
   等级 `[0,1,2]` ⇒ 难度 **1** · `[2,3,4]` ⇒ 难度 **3** · `[4,5,6]` ⇒ 难度 **5** ✓
   🔴 **注意 `2` 与 `4` 落在两档里**（区间重叠）⚠️
   🎖️ 而**架构 `#471` 早已裁过这个歧义**（"取靠后档"，且**它处在代理量链内部**）
      ⇒ ✅ **本件实测的正是那三档** ⇒ **与架构的裁定逐项相符** ✓
`restriction.difficulty.resolve_level_threshold_table` = **[2, 2, 3, 4, 5, 99, 99]**（**7 项**）✓
   🔴 **末两项是 `99`** ⇒ 📌 **那是"不限制"哨兵** ✓
   🎖️ 而 `§10.2 ⑥` 说分队**撤回了「99 = 禁止」的猜测**、证明它是**等级上限**
      ⇒ ✅ **本件与之一致**（`99` = 不限制）✓
```

### ④ `type` —— **每地牢 8 档的"可选任务类型"表**

```
`available_quests_table` ⇒ **4 个地牢**（`crypts`/`weald`/`warrens`/`cove`）✓
   每个 **8 档** · 每档条数 **[1, 4, 6, 8, 8, 8, 8, 8]** ✓
   🎖️ **逐档递增**：档 0 只有 1 种 → 档 1 有 4 种 → 档 2 有 6 种 → 档 3+ 固定 8 种 ✓
   每项的形状：`{type, chance, length}` ⇒ 例 `{type: "explore", chance: 1, length: 2}` ✓
   🔴 **4 个地牢的第 3~7 档【完全相同】**（我逐档比过）⚠️
      只有**档 0~2 有差别**（`crypts` 档 2 有 6 种，与 `weald` 相同…）
      ⇒ 📌 即：**这张表其实只有前 3 档有信息量** ✓
```

## 3. 🔴 而有两处**我方与参考不同**

### ① `dungeon_types`：我方给 4 种，参考给 **2 种**

```
我方 `dungeon_types`：**4 个地牢每个都是 `["bust","portrait","deed","crest"]`**（全给）⚠️
参考 `heirloom_type_map`：
   `crypts`  **`["bust", "crest"]`**  · `warrens` **`["portrait", "crest"]`**
   `weald`   **`["deed", "crest"]`**  · `cove`    **`["portrait", "deed"]`** ✓
⇒ 🔴 **4 个地牢【全部不同】**（我方"每个地牢给全部 4 种"，参考"每个地牢只给 2 种"）⚠️
   🎖️ **而这条正好解释了 A11 的一个观察**：
      A11 实测**参考里 `crest == bust` 的等级 18/99，而我方只有 2/99** ⇒
      📌 **因为参考按地牢只给 2 种传家宝，`crest` 是 4 个地牢的【公共项】** ✓
      （`crypts`/`warrens`/`weald` 都含 `crest`，只有 `cove` 不含）✓
   ⇒ 📌 **对采用的意义**：🔴 **"每个地牢给全部 4 种"会稀释地牢特色** ⚠️
      参考的设计是"**地牢 ↔ 传家宝**"有**配对关系** ⇒ 这是**设计意图** ✓
      ⇒ ✅ **按用户指令"数值采用参考" ⇒ 应当改成 2 种** ⇒ **归策划确认** ✓
```
