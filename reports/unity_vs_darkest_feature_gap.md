# Unity 移植版 vs 当前 Darkest（Godot）项目 · 功能缺口分析

> 对照对象：
> - `F:\GithubPro\Darkest-Dungeon-Unity`（Reinisch/Darkest-Dungeon-Unity，Unity 2017，485 .cs / 6.4 万行，README 自述"近完整复刻"）
> - `F:\GithubPro\Darkest`（Godot 4 + C#，192 .cs / 约 3.6 万行，截至 2026-09-26）
>
> 结论：Unity 版是**功能范围参照**（也是架构反面教材，见其 `docs/ARCHITECTURE-STUDY-GUIDE.md`）；当前项目约 **50% 完成度**——战斗核心 + 地牢探索压力机制已可玩，但**城镇养成纵深、元层系统（存档/剧情/多人）、完整物品/怪物内容**仍是空壳。

## 三、当前项目相对 Unity 版的优势（反向亮点）

- **架构更干净**：无 6000 行 `RaidSceneManager` God Object，无 416 处 UI 直读全局；分层（core/data/sim/scene/ui）清晰。
- **数据驱动 + 加载期 fail-fast**：每个 JSON 有强类型 Config + 校验；数值迭代只改 JSON。
- **测试纪律强**：xUnit 内核零 Godot，全量 **763 例**；双工程构建隔离。
- **战斗核心（位置驱动）实现质量高**，可作为后续系统的稳定底座。

> 建议：把 Unity 版当**功能清单**（哪些机制该有），**不要**当架构范本（其 God Object / 全局耦合是明确反模式，其自带 `docs` 也这么写）。

## 四、建议补齐优先级（按"长线循环闭环"排序）

1. **存档系统** —— 否则无法长线，所有养成无意义。
2. **周循环 + 装备/技能 0-4 阶升级**（H-1/H-2/H-3）—— 城镇养成纵深，游戏驱动力核心。
3. **完整物品系统 `items.json` + 道具 buff** —— 背包从"口粮容器"升级为策略维度。
4. **怪物内容扩充 + 敌人类型（C-4）+ 增援** —— 战斗深度。
5. **剧情 / Boss / 旁白** —— 叙事闭环（最大工作量，可最后做）。
6. **战斗特效补全**（Poison / Capture / Summon / Control / Shuffle）—— 机制丰富度。
7. **手写地牢图 D-8 + 光照掉率 D-9** —— 探索层收尾。
8. **多人**（可选，工程量大，建议放最末或独立立项）。
