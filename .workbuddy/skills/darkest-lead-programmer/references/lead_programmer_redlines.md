## 2. Godot 节点生命周期（易爆点）

- `_Ready()` 内**不得直接切场景**：父节点正增删子节点 ⇒ `Parent node is busy adding/removing children` 并 exit 1 ⇒ 必须 `GetTree().CallDeferred("change_scene_to_file", path)`。
- 同类：`_Ready` 内增删子节点、`QueueFree` 后立即访问。出处 O-74 地牢层入口（架构收进 blueprint §9.14）。

## 4. 提交纪律（附 C.1，实证事故）

- 提交前 `git status --porcelain` 看清单；大文件(>1MB)/外来目录（参考副本、缓存、导出物）先看再决定。
- `git add -A` 非默认安全；参考目录写进 `.gitignore`（`Example/`、`**/Darkest Dungeon/`、`*.csd`、`*.csm`、`*.depotcache_*`）。
- 误提交：`git reset --soft HEAD~1` → `git restore --staged <外来>` → 重提交 → `git reflog expire --expire=now --all` + `git gc --prune=now` 回收；校验 `git show --stat HEAD | Select-String <外来>` 须 0 命中。
- 提交信息不用 ASCII 双引号（用「」或不用）——PowerShell 截断致静默失败；根治：写文件再 `git commit -F <文件>`（无 BOM UTF-8）。

## 5. 三角窗口投递模板（主程序收件箱 = 主程序窗口.txt）

```markdown
### 轮次：<日期> · <一句话主题>
- **我做了什么**：<≤3 行>
- 🔴 **需要你做什么**：<逐条、可执行>
- **阻塞 / 待裁定**：<有就写；无写「无」>
- **权威在哪**：<doc/ 具体文件 + 章节>
```

- 写对方窗口 = **先读全文 → 拼接 → 用 write 整体写回**（幂等、不夹带命令、不重复）。
- 清空自己窗口前确认每条已处理/已转写 doc；没确认就清 = 丢交接项。
- 写入失败立即重读补写，当轮不滞留；只有 read 回读能证明信在窗口里。

## 6. 复测报告 9 字段（reports/*.json，缺 D/E 基线不成立）

1. 判据 A1 单场：胜率≥85% / 死门≤0.4 / 阵亡≤0.1 / 回合4~6
2. 判据 A2 run：完成率[40,70]（含撤退口径，撤退即放弃作诊断）
3. 实测 D（我方每回合对敌总伤害）
4. 实测 E（敌方每回合对我方总伤害）
5. 我方自愈总量/场（HealEvent 求和÷场数）
6. SP 存量/花费(治疗·增援)/待命次数/成功增援次数
7. 口径健康度：敌方命中各槽分布(1号位占比<50%)+池外移动占比
8. KPI 七项：士气触底/虚弱/死门/撤退/美德/折磨/位移
9. 多场曲线：每场结束存活人数/HP%/士气%
