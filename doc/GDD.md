### 0.1 核心爽点（双轨）✅

**决策：绝境翻盘 + 精密操作，两者都要。**

- **绝境翻盘**：眼看要崩，靠换人 + 鼓舞 + 死门硬扛把局面撑回来。由士气/虚弱/死门系统承载。
- **精密操作**：通过位移、站位、角色安排的设计取胜。由位置系统与技能绑定承载。

> 设计后果：数值不能太随机（会毁掉精密操作），也不能太确定（会毁掉翻盘的戏剧性）。
> **后续所有数值设计都要同时服务这两条**，任何一边过强都要回调。

### 0.2 四层核心循环 ✅

| 层级 | 时长 | 玩家在做什么 | 核心张力 |
|---|---|---|---|
| **秒级**（一次决策） | 几秒 | 看行动序列 → 选技能 → 预判位移结果 | 打不打得到？推不推得动？ |
| **分钟级**（一个回合） | 1~2 分钟 | 维持阵型 + 管理全队士气 | 这一轮是补输出还是救士气？ |
| **场次级**（一场战斗） | 8~12 回合 | 崩溃管理：换人 / 鼓舞 / 死门硬扛 / 撤退决策 | 撑得住还是要撤？ |
| **长线**（远征循环） | 数十场 | **接任务 → 出发 → 战斗 → 回城 → 养成 → 再出发** | 这一趟值不值得？带谁去？ |

> ✅ **长线循环（用户拍板）：远征循环**——接任务 → 打 → 回城 → 养 → 再出发。
>
> 这也意味着这些系统**迟早都要有**：招募渠道（§3.7）、营地/战前士气恢复（§3.2.1）、
> 遗物与经验传承（§3.7）、角色养成。**切片阶段全部不做**，但设计时要留接口。
>
> ⚠️ 提醒：远征循环是四种候选里**最重**的一种（需要任务生成、地图/列表、城镇养成、资源经济）。
> 与你选的"先做出来再说"和"垂直切片优先"存在张力——
> 建议切片阶段**完全不碰长线**，等单场战斗的手感确认后再展开。

### 0.3 技能栏 ✅

**决策：战前从技能池选带 N 个（暗黑地牢式）。**

- 每个角色拥有一个 **9 个技能**的技能池，**战前从中选带 5 个**进战斗。
- 战斗中能用哪些，还要再过三道限制：① 施法者所在位置（§1.2）；② 目标位置的占用情况；③ 使用限制（CD / 每场次数）。
- 这让"战斗外配装"成为一层独立决策，重玩性高。

> ⚠️ **工作量提醒**：9 技能 × 每角色。切片 4 个角色 = 36 个技能，6 个角色 = 54 个。
> 建议切片先做 **4 个角色**，或临时把池降到 **6 选 4**，验证手感后再扩到 9。
>
> ⚠️ **设计硬要求**：每个角色的技能**必须覆盖他在各个位置时的可用性**。
> 否则玩家把角色推到某个位置后，会发现一个技能都放不出来——这是位置绑定技能最容易翻车的地方。
> 建议每个角色至少保证：**在战斗位 4 个位置上，各有至少 1~2 个可用技能**。

## 1. 核心玩法：位置驱动的战斗

### 1.1 编队与位置 ✅

- 我方 **6 个位置**（2 支援位 + 4 战斗位）；敌方 **4 个战斗位**。
- **镜头布局（已确认）**：

```
镜头中： [辅6] [辅5] [战4] [战3] [战2] [战1]  ←空气→  [敌1] [敌2] [敌3] [敌4]
```

- 我方 1 号位与敌方 1 号位**在屏幕中央隔"空气"对峙**，编号**由中间向两侧递增**。
- 支援位 5、6 在更外侧，**平时不进镜头**，只在被使用（换位 / 被攻击）时入镜。
- 每条位置槽位有且仅能是以下三种状态之一：有一个角色 / 空 / 被**障碍**占据。
- **障碍的本质 ✅：一个「不会行动、只有血量的占位角色」。**

| 能力 | 障碍 |
|---|---|
| 占据槽位（槽位三态之一） | ✅ |
| 参与位移交换链（§1.3 已定：撞上即交换） | ✅ |
| 主动行动 / 攻击 | ❌ |
| 拥有血量，可被攻击 | ✅ |
| 血量归零 → 消失 | ✅ **立即触发向中靠齐填补**（§1.6） |

- **✅ 障碍完全当敌人处理**（用户拍板）：能被打、能触发"范围内非空"的技能可用性、算技能目标。
  - ⚠️ 由此必须明确：**胜利条件仍以"敌方单位全部死亡"为准，障碍不计入**。
    否则打碎障碍会影响胜负判定。`[待确认：写进胜利条件]`
  - ✅ **障碍的结算（用户拍板）**：**AOE 会波及障碍**（范围技能打到它掉血），但**debuff 不生效**（障碍免疫眩晕/流血/属性减益等状态——"一块墓碑不会晕"）。

- **障碍来源 ✅**：**关卡预置 + 敌人技能生成**。
  - 关卡预置：战斗开局就存在的地形（墓碑、塌陷、路障）。
  - 敌人技能生成：部分敌人能在战斗中造出新障碍，把战场越挤越窄。
- ⚠️ **规则已变更**：此前写的"玩家不能主动清除障碍"作废——障碍既有血量，就可以被打掉。
  - 这让障碍从"纯地形"变成**可清除的挡路者**，位移系统的素材也更丰富。
- `[待确认：障碍是否阻挡远程技能（既然是"占位角色"，打它是否像打角色一样正常结算？）]`
- `[待确认：障碍能否被 AOE 误伤 / 是否吃 debuff / 是否占"敌方目标位"影响技能灰显判定]`

> 完整规则见 `modules/formation.md`

### 1.2 技能的目标方式（核心差异点）

- 技能绑定**位置范围**：如「我方 2、3 号位」「敌方 1、2 号位」。**范围是"可选目标池"，不是"命中范围"**（#178）。
- 技能能用的前提是施法者**自己站在指定位置**（位置即技能可用性门槛）。
- **在范围内选取目标 ✅（#178，用户拍板）**：
  - **单体技能**（无 `aoe` 标签）→ 在范围内的**非空位置中选一个**目标（暗黑地牢式）；
  - **AOE 技能**（带 `aoe` 标签，如横扫 / 精神震荡）→ 命中范围内**全部**非空位置；
  - 若范围内**全空** → 技能灰显；**部分非空** → 只对非空位置生效，不浪费、不落空。
- **双段技能**（双连击 0.55×2 / 连射 0.5×2）→ **同一目标打两段**，目标只选一次（#179）。
- 技能带有**种类标签**，至少两轴：
  - 距离轴：近战 / 远程
  - 伤害轴：物理 / 精神

> 设计意图：位置不是"站位"，而是**技能的资源与约束**。
> 换位置 = 换技能组 = 换角色定位；而在范围内**选目标**这一层，正是「精密操作」爽点的落点。
>
> ⚠️ **纪律提示**：`范围 ≠ 命中全部`。实现方若把单体技能做成"范围内全命中"，劈砍会变成 0.9×2、敌方精准射击会变成 0.9×4，数值全盘失真（该口径已废，见 `open_issues.md` O-38）。

### 1.3 位置可变：位移是核心 ✅

**决策：位置可变，位移可推多格，全部通过「逐级交换」实现。**

1. **粒度：可推多格**，由技能指定格数。
2. **实现方式：逐级交换链**。从 4 到 1 = `4↔3` → `3↔2` → `2↔1`；被推者沿路与目标链上每个单位依次交换，最终抵达目标位置，中间单位各后退一格。
3. **角色不可位移到空位置**——位移只能通过交换完成，不能"走进"空格。
4. **障碍当作角色处理**：撞上障碍 = 与障碍交换位置（角色到障碍另一侧，障碍落到角色原位）。
5. 技能模板必须包含 `位移效果`（推 / 拉 / 交换 / 自我移动）。
6. 属性表必须包含 **位移抗性**。

> **关键设计后果**：位移永远不产生空位，阵型长度恒定——位移改变的是**顺序**而不是**间距**。
> 好处：阵型永远可读，UI 不用处理"空洞"；也让 §1.6 的向中靠齐只在死亡时触发。
> 代价：位移无法"把队伍拉散"，破坏力主要体现在打断敌方技能可用性上。

### 1.4 支援位：纯支援位 ✅

**决策：支援位角色只能使用「对友方的增益类技能」，不能攻击敌人。**

| 能力 | 支援位角色 |
|---|---|
| 攻击敌方 | ❌ **不能** |
| 治疗 / 增益 / 减益（含回士气） | ✅ 可以 |
| 每回合回士气（站在支援位即有） | ✅ 有 |

- **站在支援位的角色每回合回士气**，并可主动给战斗位角色回士气。
- 替换语义 = **交换位置**，不是下场。
- **敌方只有部分单位能触及支援位**（远程 / 精神 / AOE），命中时镜头短暂移过去。
  - 支援位**不能还手**，所以这条不是可选项而是必需品——否则支援位就是绝对安全区。

> ✅ **这条决策顺带解决了「6 打 4 人数优势」风险**：
> 我方真正能输出的只有 4 个战斗位 vs 敌方 4 位，**压力对等**。支援位提供的是续航与士气管理，不是火力。
> 这也让"支援位被打到"极其致命——他没有反击能力，只能靠位移和队友保护。

#### 1.4.1 换位 / 增援规则 ✅

**决策：统一为一条「增援」操作——由战斗位角色发起，把支援位角色调进战斗位。**

```
战斗位角色 A 发起「增援」（消耗 A 的本次行动）
  → A 指定：支援位角色 B + 目标位置 X
  → 若 X 有人 → B 与 X 上的角色【交换位置】
  → 若 X 为空 → B【直接进入】X
  → 结算后触发【前移 / 向中靠齐】（§1.7）
```

要点：

- **发起者是战斗位角色**，被调动的是支援位角色。支援位角色不能自己往上冲。
- **不设冷却**。代价 = 发起者消耗本次行动。
  - 用户原担心"怕太自由"，但：支援位回士气只对虚弱者有效（§1.4）+ 换位要吃掉一次行动，
    "反复跳反"的收益已经被抽掉了，再加冷却只是叠床架屋。
- **「不能攻击」是位置限制，不是角色限制**（§1.4）：支援位角色一旦被增援进战斗位，**立刻可以输出**。
- **增援范围 ✅：任意战斗位**。自由度高，阵型调整能真正解题；代价已经由"消耗发起者行动"承担。
- ✅ **支援位角色被增援进战斗位后，立即在该战斗位上行动，技能组随之切换**（位置限制，#41b）：增援是换到指定槽位，不存在"永久/临时"之分。

> ✅ **澄清（用户纠正了我的理解）**：**位置槽位是固定的**，不随人数增减而变化。
> 增援操作就是"指定一个固定槽位，让支援位角色过去"——
> 该槽位**有人则交换，无人则直接进入**，仅此而已。
>
> ~~此前我以为"空位被靠齐立即填补，导致进入空位分支失效"~~ —— 这个冲突**不成立**：
> 增援是玩家**主动指定槽位**，绝大多数情况下槽位上都有人（走交换分支）。
> "无人则直接进入"只是兜底分支（比如靠齐填不上时），不需要额外时序规则。

### 1.5 敌方编队：只有 4 个战斗位 ✅

**决策：敌方只有 4 个战斗位，无支援位。**

直接后果（必须处理）：

1. **敌方编号只到 4**：所有"敌方 5、6 号位"的技能目标无效，技能设计要重排。
2. **"切后排"战术消失**：敌方没有需要优先处理的后排支援单位 → 深度缺口必须用别的方式补（见下）。
3. **我方 6 人对敌方 4 人**：人数优势明显，但敌人**单体强度已放松到 ≈ 战士**（#124，非「强于」），压力改由「前后排配置 + 位移技能 + 敌方无士气/虚弱/死门」的不对称制造，而非面板碾压。
4. 敌方死亡后其位置变空 → 技能打空位的规则必须明确（打空 = 浪费一回合？还是智能重定向？）。

✅ 已定：深度由「敌方内部前后排」配置补上（§1.5.1），大型敌人占多格 / 增援型召唤切片不做。
✅ 已定：空位不打空——技能只命中范围内非空位置（§4 结算），优先级表只在可用技能中选。

#### 1.5.1 深度补偿方案 ✅

**决策：三项全做**——增援/召唤 + 大型敌人占多格 + 敌方内部前后排。

| 方案 | 内容 | 系统成本 | 切片阶段 |
|---|---|---|---|
| 敌方内部前后排 | 4 位内再分前后，后排放高威胁远程/施法者，"切后排"在敌方内部重新成立 | **低**（纯配置） | **做** |
| 大型敌人占多格 | Boss 占 2~3 格，是地形压力也是位移大目标 | 中（需槽位多占规则） | **切片不做**（用户拍板延后） |
| 增援 / 召唤 | 敌人死亡后有新单位填位，战斗位不会被打空 | 高（需召唤时机 + AI） | **延后到切片之后** |

> ✅ 范围已收窄：**切片阶段只做「敌方内部前后排」一项**（大型敌人延后）。
> 这意味着敌方深度完全压在"前后排配置"上——敌人设计必须靠**配置**而不是**新机制**撑住变化。
> 切片阶段**只做 1 套**敌方编成（#106，先把手感做出来）；多套编成留待切片通过后补以验证深度（早期风险表曾建议 3~4 套，但 #106 已收敛为 1 套）。

### 1.5.2 超时增援 ✅（新增，取代"固定回合上限"）

**决策：战斗没有硬性回合上限。打到一定回合仍未分出胜负（胜利 = 敌人全部死亡；失败 = 我方全灭），敌人开始呼叫增援，填满其空位。**

```
战斗进行到第 N 回合仍未结束
  → 敌人呼叫增援
      → 新单位填入敌方的空位（若没有空位 → 给在场敌人上增益，不扩编，§1.5.2 已定）
  → 之后每隔 M 回合再来一波（M 待数值阶段定）
```

- **触发回合 ✅：第 6 回合**起仍未分出胜负，敌人开始呼叫增援。
- **增援强度 ✅：随机**，且**只填满空位**（敌方仍是 4 位上限，不扩编）。
- 设计意图：**用压力递增代替计时器**。玩家拖得越久局面越糟，但不至于"时间到就判负"那么粗暴。
- 这条同时也是**防苟活的真正闸门**：
  §3.5 已定"战斗位全是虚弱者也不判负"，玩家理论上可以缩着不打；
  但敌人会持续补位，缩着只会让局势恶化——拖延本身变成惩罚。

> ✅ **漏洞已补（用户拍板：改为上增益）**：
> 「增援只填满空位」原本有死角——**玩家一个敌人都不杀就不会有空位，增援永远不触发**，
> "完全不输出、只龟缩"反而不受压力。
>
> 修正后的完整规则：
> ```
> 第 6 回合起仍未分胜负 → 敌人呼叫增援
>     · 有空位 → 填入随机强度的新单位
>     · 无空位 → 改为给【在场敌人】上增益（+攻 / +速），不扩编
> ```
> 好处：压力照涨，且**不打破 4 位上限**，技能目标映射与 UI 都不用改。
>
> 另外提醒：**第 6 回合偏早**。若正常战斗节奏是 8~12 回合，第 6 回合会让增援成为**常态**而非"打太慢"的信号。
> 建议实测后再定；若战斗普遍能在 6 回合内解决，说明敌人太弱，问题在数值不在增援时机。
- ⚠️ 注意：这与 §1.5.1 里"延后"的**增援/召唤**不是一回事。
  之前延后的是"敌人死亡后立刻有新单位填位"（战斗内持续补充）；
  现在这条是**超时才触发**的压力机制。切片阶段建议**只做超时增援**，死亡补位继续延后。
- ✅ 触发回合已定 **第 6 回合**（见上）；无空位 → 改为给在场敌人上增益（不扩编，已在 §1.5.2 正文定）。
- 增援强度 = 随机、频率 / 每波人数留待数值阶段细化（不影响切片手感验证）。

### 1.6 向中靠齐 ✅

**决策：角色死亡或离场（且无人替换）时，后方角色立即向 1 号位方向靠齐。空位只会留在队伍最后面。**

- **触发时机**：死亡 / 离场时**立即**。正常位移走的是交换链，不产生空位，因此不触发靠齐。
- **虚弱角色不参与前移**：健康角色跨过他向前补位，虚弱者留在后面。
  - 原因：否则"换人保护"会失效——前面一死，虚弱者又被顶回战斗位挨打。
- **敌方对称执行**：敌人死亡后同样向中靠齐。
- ✅ 靠齐时遇障碍按 #114/#117 处理：撞上即与障碍交换位置，不会"卡死"（障碍当占位角色参与交换链）。

> 副作用提醒：靠齐会让"战斗位全空"几乎等同于"全队覆灭"（人少时靠齐后仍占着 1、2 号位）。§3.5 的失败条件需要按这个重新校准。

### 1.7 位移与替换的边界

- **✅ 最外侧单位被向外推**：**位移失败，该单位不动**（边界即硬墙）。
  - 副作用：最外侧成为相对安全的位置，玩家会有意识地把脆皮放到边缘。这本身也是一种策略。
- ✅ 靠齐遇障碍同上：交换处理（#114/#117）。
- ✅ 靠齐时后方全是虚弱角色 → **留空位不补**，恢复后不自动前移（#115，避免"换人保护"失效）。
- 敌方是否拥有同等位移能力？
- 能否主动推动障碍本身？

### 2.5 行动顺序 ✅

**决策：由速度属性排序决定行动顺序。**

- 新增**速度**属性。

> ⚠️ **我的反对意见（记录在案）**：随机浮动会削弱「精密操作」爽点的地基——玩家精心排好的顺序会被骰子打乱，失败时容易归因为运气。
> ✅ **已采纳收窄到 0~10%**（`combat_math.md` §9 也标记为最该动的一条）。另一条缓解建议「只在同速区间内生效」（先按基础速度分档，档内再随机）保留，待实测后视手感决定是否进一步实施。
> 另一条硬约束：**UI 必须显示行动序列**（哪怕只是本回合的），否则随机浮动会让玩家完全无法规划。

- **眩晕结算 ✅：跳过本次行动**（该单位本回合不行动，眩晕状态随即结束）。
- **破平局 ✅：速度相同时，按位置靠前者先行动**（编号小的先动，#80 阵营内规则）；**跨阵营同速 → 我方先动**（#168：编号相同则固定阵营序，我方先于敌方）。
- **减速 debuff ✅：按固定值扣减**（如 速度 -X），不做百分比。
  - 理由：基础速度带随机浮动（§2.5），若减速再走百分比，两层乘法会让实际速度难以预估。

### 3.2 士气崩溃判定

- 士气降到 **0** → 触发判定：
  - **大概率**：折磨（负面状态）
  - **小概率**：美德（正面 buff）
- ✅ **判定结束后，士气【留在 0】**（原"初始化回 50"已作废）。
  玩家必须靠手段（鼓舞 / 暴击 / 击杀 / 支援位回复）把他从 0 拉回 50。
- ✅ **折磨持续到士气回到初始值 50**；**美德持续到战斗结束或士气再次归 0**。
  美德中再次归 0 → 消除美德 → 士气回初始 → 重新判定。详见 `modules/morale.md` §8。
- ⚠️ **判定按「事件」触发而非「状态」触发**：只有「士气从 >0 降到 0」才判定；已停在 0 时挨打不重复判定。
  ✅ 已定：判定按事件触发（只有「士气从 >0 降到 0」才判定），已停在 0 时挨打不重复判定。
- **美德概率由角色固定属性（韧性）+ 装备系统决定**（美德率 = 10% + 韧性÷2，#56/#116），角色之间可以不一样。
- **不设保底**：连续触发折磨是完全可能的。
- **折磨 / 美德的具体 buff 池 ✅ 已选定**，详见 `modules/morale.md`。
  - 折磨池（3 个）：恐惧 / 自私 / 失控
  - 美德池（4 个）：勇猛 / 坚韧 / 振奋 / 专注
  - ⚠️ 美德 4 个 vs 折磨 3 个**数量不对等**，且美德触发概率本就低。切片阶段建议美德**先做 2 个**（勇猛 + 振奋）。

> ⚠️ **设计立场（用户明确）**：纯随机本身就是对玩家的惩罚。设计目标**不是**降低随机的痛苦，而是**让玩家在战斗中有意识地主动控制士气**。
>
> → 由此产生一条硬约束：**可控的士气手段必须足够强、足够可靠**（支援位鼓舞、士气类技能、装备），否则玩家无从"控制"，随机惩罚就会变成无解的挫败。

### 3.3 濒死 → 虚弱 → 归队

```
HP 归零
  → 不死亡，士气直接置为最低值，并立即触发一次 §3.2 判定
  → 进入【虚弱状态】
       · 可与支援位角色交换位置
       · 每回合回升士气，直到士气 >= 初始值
       → 离开虚弱状态，HP 恢复为 **最大血量的 10%**（起手值，可调）
```

- 虚弱状态下**可以行动**，但带显著减益：

| 减益项 | 数值 | 状态 |
|---|---|---|
| 造成的伤害 | **-50%** | ✅ |
| 速度 | **-30%** | ✅ |
| HP | 锁定为 1（归队前不回复） | ✅ |

> 设计意图：保留「赌一把继续用他 vs 换下去」的决策，这是「绝境翻盘 + 精密操作」双轨爽点的最佳载体。

- **士气回升速率 ✅**：

  ```
  每回合士气回升 = 基础值 + 支援位相关加成 + 韧性相关加成
                 （结果受【最高值】上限约束）
  ```

  数值已定：**每回合回升 = 10 + (健康支援位队友数 × 5) + (韧性 ÷ 20)，上限 25。**
  节奏：独自躺着约 5 回合归队；有 2 个健康队友陪着约 2~3 回合。详见 `modules/morale.md` §8。

  | 组成 | 说明 | 状态 |
  |---|---|---|
  | 基础值 | **10** | ✅ |
  | 支援位加成 | 每个**健康**支援位队友 **+5**（虚弱者不算） | ✅ |
  | 韧性加成 | **韧性 ÷ 20** | ✅ |
  | 最高值 | **25** | ✅ |

  > 设计意图：让"把人换到支援位"真正加速恢复——他把后背交给了队友，健康队友越多他定得越快。
  > ✅ **虚弱者之间互相陪伴不算数**：只有健康队友提供加成，避免"全员虚弱互相奶"的怪圈。
  >
  > ⚠️ 注意与 §1.4 的联动：**支援位人越多回得越快**，所以"全员缩支援位"确实能加速恢复，
  > 但代价是**没有任何输出**（§1.4），敌人可以随便打。这个自我平衡是成立的。

- ✅ **虚弱状态下每次受伤，除了死门判定，还会【扣士气 -5】**（每回合最多 1 次，#157 已定值）。
  - 效果：抵消甚至倒扣他正在回升的士气 → **延长虚弱时间**。
  - 设计意图：挨打不只是"赌一次生死"，还会让你更晚归队，形成
    **挨打 → 更晚归队 → 更容易再挨打**的压力链。
  - 与"物理伤害不掉士气"区分开：虚弱时挨打更疼（任意类型伤害都 -5）。

### 3.4 死门机制（真正死亡的唯一途径）✅

**新增机制：**

- 角色拥有 **死门抗性**，为**固定上限值**，语义为**存活概率**（值越高越难死）。
- **处于虚弱状态时受到任何伤害 → 立即进行死门判定。** 伤害来源包括但不限于：
  - 直接攻击
  - 持续伤害类 debuff（流血等）
  - **护卫替别人承受的伤害**（§buff 7.1）
  - 位移撞墙 / 撞击障碍：**位移本身不产生伤害**（撞墙=位移失败不动，撞障碍=与障碍交换，见 #117），因此**不触发死门**
- 判定：存活概率 = 死门抗性。**扛住则继续存活，未扛住则死亡**。

> ✅ 方向已确认：死门抗性 = 存活概率。原字面描述「判定成功 = 死亡」已废弃，避免玩家把"抗性高"理解成"更容易死"。

设计约束（已立为决策 #123）：

- **死门抗性受 debuff 影响**（#123，用户拍板更硬核）：处于「折磨」状态（恐惧 / 自私 / 失控任一）的单位，死门抗性 **-10%**（起手值，可调）。
  > ⚠️ 我的反对意见保留在案：这会形成「被折磨 → 死门抗性降低 → 更容易死」的绝望螺旋，与既有随机层数叠加，挫败感更强。用户明确接受此代价。

推论与后果：

- **角色会真死** → 必须有角色补充渠道（招募 / 新兵池），否则连败后无法继续。（切片阶段不做招募，死亡直接结束该局，见 §3.7）
- 支援位只有 2 个，**换人名额有限** → 死亡一定会发生，这是设计意图（用户明确）。
- 死门判定让"虚弱"从一个安全状态变成**高压状态**，玩家会强烈想换人 → 与 §0.1「绝境翻盘」爽点强耦合。

### 3.7 死亡与招募 ✅

**决策：永久死亡 + 有招募渠道。**

| 规则 | 内容 |
|---|---|
| **永久死亡的触发** | ✅ **角色真死即永久损失，与战斗胜负无关** |
| **遗物 / 经验传承** | ✅ 死亡后**保留部分遗物或经验**传承给队伍（具体比例与形式待设计） |
| **招募渠道** | ✅ 存在（具体形式待设计） |
| **复活事件** | ✅ 用户设想存在"将死亡角色复活"的事件，但**切片阶段不做** |
| **死亡是否损失装备 / 等级** | `[待确认]`（切片不做装备，暂时无影响） |

> ✅ 歧义已裁决：**赢了也死**，但损失被"传承"部分补偿。
> 这条既保住了死门的威慑力（不会因为赢了就复活而无顾忌地送人），又不至于让损失过于血本无归。
> ⚠️ 待设计：传承的具体比例、传承给谁、是否受角色定位影响。**建议切片阶段不做**，只记机制。

> ✅ **切片范围**：招募渠道、复活事件、传承系统**切片阶段都不做**，死亡在切片里直接结束该局。

### 3.5 战斗结束条件 ✅

**决策：战斗位角色全部死亡（且支援位无人可补）→ 失败。**

```
战斗位出现空缺
  → 若支援位有健康（非虚弱）角色 → 紧急补位，战斗继续
  → 若支援位只剩虚弱者 / 无人 → 战斗位空 → 失败
```

> ✅ 用户立场：**必须防止"全员缩在支援位苟活"**。若虚弱者可以无限堆在支援位而不判负，玩家就能靠不停换人无限拖下去，整套压力系统会失效。
>
> ✅ **已裁决（用户拍板）：不算判负，直到全灭才输。**
>
> 重新评估后我接受这个裁决，因为苟活的代价其实是自付的：
> 全员虚弱 = 全员 **HP 锁 1 + 输出 -50% + 速度 -30%**，且任何一击都要过死门判定。
> 这不是苟活，这是**在刀尖上站着**——玩家撑得住是本事，撑不住直接团灭。
>
> 防无限拖延的真正闸门是另外两条：支援位**可被部分敌人触及**（§1.5）+ 虚弱者士气回满后自动归队（§3.3）。

### 3.6 撤退机制 ✅（新增）

**决策：战斗中保留撤退选项，撤退需要判定。**

```
玩家发起撤退（团队统一指令，全员一起撤）
  → 进行撤退判定
      · 判定成功 → 退出战斗，全队 -10 士气（已定，#43）
      · 判定失败 → 全队 -5 士气（已定，#43），本回合不可再发起撤退，下回合可再试，战斗继续
```

- 撤退是**止损通道**，也是「绝境翻盘」的另一面：玩家可以选择不赌。
- **撤退判定 ✅：混合式（#169 已定具体公式）**——基础成功率由**速度对比**决定，再叠加随机。

  ```
  我方平均实际速度 = mean(我方存活单位实际速度)
  敌方平均实际速度 = mean(敌方存活单位实际速度)
  基础成功率 = 50% + (我方平均 - 敌方平均) × 4%
  钳制在 [15%, 85%]
  实际成功率 = 基础成功率 + uniform(-10, +10)
  钳制在 [5%, 95%]
  ```

  > ✅ **公式已由策划拍板（#169 / O-11）**：速度差每 1 点换算 ±4% 成功率，速度对比主导结果；
  > ±10% 随机（#46）只做扰动。**UI 必须显示撤退成功率的具体数字**（ui_spec 必显 #2）——
  > 玩家看到"68%"就可以围绕它规划（先杀掉最快的敌人再撤）。公式放 tuning.json 可配置，默认示例即上值。

- **撤退的士气代价 ✅（起手值）**：撤退成功 → **全队 -10**；撤退失败 → **全队 -5**。
  - 用户已定，后续数值迭代可改。
- **撤退范围 ✅（#118）**：**团队统一行动**——全员一起撤，非单人脱离（与「退出战斗 + 全员减士气」语义一致）。
- **撤退重试 ✅（#118）**：失败**当回合不可再发起**，下回合可再试；代价为本回合全队 -5 士气。既保留每回合止损通道，又防无限刷判定。

> ⚠️ 我的提醒曾建议"撤退做成确定性判定"（方案：我方平均速度 ≥ 敌方平均速度则成功）。
> 用户拍板保留 **±10% 随机**（#46），本公式已在两者之间取平衡：
> 速度差 ×4% 让"先杀最快敌人再撤"的策略性成立，±10% 保留最后一层紧张感。
> 本作随机层数维持「命中 / 暴击 / 折磨判定 / 死门判定 / 撤退判定」五层的现状（已登记）。

## 4. 战斗结算流程（草案）

```
回合开始
  → 按速度属性排序生成行动序列
每个单位行动：
  技能释放
    → 目标位置合法性检查（施法者站位 + 作用范围内的占用情况）
        · 作用范围内【全部为空】→ 技能灰显，不可释放
        · 作用范围内【部分非空】→ 只对非空位置生效，不浪费、不落空
    → 命中判定：闪避概率
    → 暴击判定：成功 → 伤害加成 + 友方士气提升
    → 伤害计算：物理防御 / 韧性（精神类伤害走韧性减免，见 §2.2）
    → 附加效果判定：眩晕 / 流血 / 属性减益（各自过对应抗性）
    → 位移结算（推动 / 拉动 / 交换，过位移抗性）
    → 士气变动结算（伤害 / 暴击 / 击杀 等来源）
    → 若目标处于虚弱状态且本次受伤 → 触发死门判定（§3.4）
回合结束
  → 持续伤害 / buff 结算（同样可触发死门判定）
  → 虚弱角色士气回升判定
  → 检查失败条件（§3.5）
```

- 士气的具体增减来源表：见 §3.2.2（已定起手值，#119 系列）。
- **每一步的算式（命中 / 伤害 / 暴击 / 附加效果 / 位移 / 士气 / 死门）**：见 `modules/combat_math.md`（本节省略公式，只写流程顺序）。
