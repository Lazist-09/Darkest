# 士气系统（模块）

> 主文档：`GDD.md` §3。本文件装士气系统的完整细节与 buff 池。

## 1. 框架

| 项 | 值 |
|---|---|
| 数值范围 | 0 ~ 100 |
| 初始值 | 50 |
| 满值（100） | 触发**士气高涨**：给自己上一个**美德效果（持续整场）+ 给全队加士气** → 自身士气回归正常（50） |
| 触底（0） | 触发**崩溃判定**：大概率折磨 / 小概率美德，然后**士气留在 0**（§8.1，靠手段慢慢爬回 50） |
| 波动幅度 | **小幅**——常规战斗稳定在 40~60，崩盘只在极端情况 |

## 2. 士气增减来源表（起手值）

| 事件 | 变动 | 作用对象 |
|---|---|---|
| 打出暴击 | +5 | 全队 |
| 击杀敌人 | +10 | 全队 |
| 受到**物理**伤害 | **0**（不扣士气，#157） | — |
| 受到**精神**伤害 | **-8**（被精神暴击 **-12**） | 本人 |
| 队友进入虚弱 | -8 | 全队 |
| 队友死亡 | -15 | 全队 |
| 政委「战场鼓舞」 | +15 | 单一目标 |
| 撤退成功 | -10 | 全队 |
| 撤退失败 | -5 | 全队 |
| 站在支援位（每回合） | **+3** | 本人（§1.4）。存在但不抢戏，不足以诱使玩家把健康角色塞支援位养士气 |
| 士气冲满 100 | **+10** | 全队（一次性） |
| 虚弱状态下受伤（任意类型） | **-5** | 本人（每回合最多 1 次；§2 上方说明里的例外） |

> ✅ **规则重写（#157，用户拍板）：士气是精神状态，物理伤害不掉士气，只有精神类攻击才掉。**
>
> 原设计（受击必 -3，后改为 50% 概率）有两条硬伤，本次一并解决：
> 1. **与「小幅波动、稳定在 40~60」冲突**——8~12 回合累计 -24~-36，单靠挨打就能把人打崩；
> 2. **与嘲讽结构性冲突**——坦克站 1 号位 + 嘲讽 = 挨打次数最多 → **必然第一个崩**。
>
> 改为「只有精神伤害扣士气」后的连带好处：
> - **干掉一层随机**：原「50% 概率触发」这层完全无法预判的随机消失（本作 10 层 → 9 层）；
> - **嘲讽不再反噬**：坦克挨物理打不掉士气，不再需要任何封顶；
> - **施法者成为明确战术目标**：唯一的士气压力源在敌方 4 号位（最深处），
>   "突破前排切掉施法者 = 解除士气压力" —— 敌方前后排深度这才真正成立；
> - **主题自洽**：被刀砍不动摇意志，被恐惧低语才动摇。
>
> ⚠️ **唯一例外：虚弱状态**下受到任何伤害仍 -5（每回合最多 1 次）。
> 见 `combat_math.md` §5.1 的说明——若要求完全统一，可改为「仅精神伤害」，但虚弱期会明显变短。
>
> ⚠️ **新风险**：现在只有施法者一个精神伤害来源，若玩家开局秒掉他，整场不掉士气。
> 缓解：恐惧低语 CD 2 → 1（见 `skill_data.md` §5）。需 Monte Carlo 验证「士气触底 ≥1 次/场」。

## 3. 可控士气手段（硬约束）

| 手段 | 类型 | 切片 |
|---|---|---|
| 支援位「鼓舞」 | 战斗中 · 主动 | 做 |
| 角色自带士气技能 | 战斗中 · 主动 | 做 |
| 暴击 / 击杀奖励 | 战斗中 · 被动 | 做 |
| 战前 / 营地恢复 | 战斗外 · 准备 | **延后**（需营地场景） |

> 用户立场：纯随机本身就是惩罚，设计目标是让玩家**主动控制士气**。
> → 因此这四条必须**够强、够可靠**，否则"控制士气"就是空话。

## 4. 崩溃判定

- 士气触底（降到 0）→ 触发崩溃判定 → **大概率折磨 / 小概率美德**。
- **✅ 判定后士气【留在 0】**，不再初始化回 50（见 §8.1 冲突已裁决）。
- **美德概率 = f(韧性 + 装备)**，切片阶段装备不做，只用韧性。
  - ✅ **属性改名：韧性**（0~100）。**美德概率 = 10% + 韧性 ÷ 2**。
    - 韧性 30 → 25%；韧性 60 → 40%；韧性 100 → 60%。区间宽、好调。
- **不设保底**：连续折磨是可能的（用户明确，理由：随机本身是对玩家的惩罚）。
- HP 归零也会**立即**触发一次判定（§3.3），随后同样留在 0。

> ⚠️ **必须处理的衍生问题：重复判定**
> 士气留在 0 之后，若规则是"士气 = 0 就判定"，会导致每回合无限触发判定。
> **建议实现（待确认）**：判定由**事件**触发而非**状态**触发——
> 只有「士气从 >0 降到 0」这一**下降事件**才触发判定；已处于 0 时继续挨打不重复触发。
> 也就是说，士气停在 0 是安全的，危险的是"再次被打到 0"。

#### 4.0 ✅ 崩溃余烬（由既有规则推导，待确认）

把上面几条合起来，其实已经能推导出一套自洽的防重复判定规则，**不需要新增任何概念**：

```
士气降到 0
  → 触发崩溃判定 → 进入【崩溃余烬】状态（折磨 或 美德），士气留在 0
  → 余烬期间：士气不会再触发判定（无论挨多少打）
  → 士气慢慢爬升……
      · 【折磨】→ 士气回到 50 时折磨结束，同时【恢复可判定资格】
      · 【美德】→ 美德继续挂着；若士气（升上去之后）再次降到 0 → 美德消除 → 重新判定
```

**妙处**：折磨结束的时机（士气回到 50）与"恢复可判定资格"的时机**正好是同一个点**。
不需要额外的计时器或标记位，规则自洽且好实现。
>
> 另一后果：士气停在 0 期间，**折磨会一直生效**（§8），直到玩家把他拉回 50。
> 这让"崩溃"从一次性的坏事件，变成一段**需要被主动终结的低谷期**——我认为这是好事。

### 4.1 折磨的生效方式 ✅（关键）

**折磨不是硬封禁，而是「概率触发的特殊状态」。**

```
角色获得折磨状态（如「自私」）
  → 该状态本身不直接禁止任何行为
  → 每当玩家做出对应动作时，按概率【触发一次】特殊结果
      · 自私 → 每次被治疗 / 鼓舞时，有概率拒绝这一次
      · 恐惧 → 每次使用技能时，有概率拒绝释放
      · 失控 → 每次攻击时，有概率随机更换目标
```

> ✅ 这个设计解决了我此前的担心：**它不是掐断救火手段，而是让救火变得不那么可靠**。
> 玩家可以多试几次，崩溃是"变贵了"而不是"没救了"。与 §3 的硬约束不冲突。

- ✅ `[已定]` **统一一个概率**，后续数值迭代可调。**暂定 33%**（每三次翻车一次）。
  - 细分默认值：自私 33% / 恐惧 33% / 失控 33%（失控建议后续降到最低档）

## 5. 折磨池 ✅（3 个）

| 名称 | 触发时机 | 特殊结果 |
|---|---|---|
| **恐惧** | 使用技能时 | 有概率拒绝释放。**技能灰掉，必须重选；不消耗行动**（玩家可以换个技能继续） |
| **自私** | 被治疗 / 鼓舞时 | 有概率拒绝这一次（本次治疗 / 鼓舞无效） |
| **失控** | 攻击时 | 有概率随机更换目标（可能打到队友） |

- ✅ `[已定 #123]` **折磨降死门抗性**：处于「折磨」状态（恐惧 / 自私 / 失控任一）的单位，死门抗性 **-10%**（起手值，可调）。
  > ⚠️ 我的反对意见：构成「越倒霉越容易死」的绝望螺旋，与随机层数叠加。用户拍板要更硬核，接受此代价。

### 5.1 失控的兜底：支援位角色改为「捆缚」✅

**问题**：支援位角色没有攻击技能（§1.4 位置限制），被判定出"失控"会空转。

**决策（用户拍板）**：支援位角色被判定出失控时 → 改为 **「捆缚」：无法行动**。

> 用户理由：为了防止伤害队友。
> 捆缚对支援位的效果等价于"这一轮他没有提供支援"，惩罚成立且无需新增规则。

- ✅ `[已定]` **战斗位保留「随机攻击」**（用户拍板，未采纳我的建议）。

  > ⚠️ **风险记录在案**：失控会让玩家的集火计划被骰子推翻，还可能打伤队友。
  > 本作已有「命中 / 暴击 / 崩溃判定 / 死门 / 撤退 / 折磨触发」六层随机，
  > 再叠加"攻击目标不可控"这一层，失败归因很容易滑向"游戏在搞我"。
  > **缓解建议（不强制）**：
  > 1. 随机目标**排除支援位队友**（只可能打到同为战斗位的队友）——保住不能还手的奶妈；
  > 2. UI 在角色处于「失控」时**明确标注**，让玩家能提前规避（别让他去打）；
  > 3. 失控的触发概率**取折磨池中最低**的一档。
  > 切片实测若反馈负面，优先砍这条。

## 6. 美德池 ✅（4 个）

| 名称 | 效果 |
|---|---|
| **勇猛** | 伤害 +25%，免疫恐惧 |
| **坚韧** | 死门抗性 +20% |
| **振奋** | 每回合给全队回士气 |
| **专注** | 暴击率 +15%（与"暴击回士气"形成正循环，注意滚雪球） |

### 6.1 美德的两个来源

| 来源 | 持续时间 | 说明 |
|---|---|---|
| **崩溃判定**的小概率结果 | 同下 | 厄运中的转机：从 0 爬回来的路上 |
| **士气冲满 100** 的奖励 | 同下 | 玩家主动经营士气的回报 |

**两个来源的美德持续时间一致**（均按 §8：持续到战斗结束或士气再次归 0）。
区别只在**获取方式**：一个是赌出来的，一个是经营出来的——这比用时长区分更干净。

> ⚠️ 范围提醒：美德 4 个 vs 折磨 3 个，数量不对等。**切片阶段建议美德先做 2 个：勇猛 + 振奋**。

## 7. 士气高涨（满值 100）✅

```
某角色士气达到 100
  → 给自己上一个【美德效果】（随机抽取），持续到【战斗结束】或【自身士气归 0】（§8）
  → 给全队 **+10 士气**（#151，与战场鼓舞 +15 形成梯度）
  → 自身士气回归正常（50）
```

- 与「崩溃判定」给的美德是同一套池子，持续时间规则也相同（§8）。
- ✅ `[已定]` **随机抽取**（用户拍板）。

  > ⚠️ 影响：玩家无法围绕满值做规划，"把士气喂到 100"从**战略资源**降级为**彩票**。
  > 与 §3「让玩家主动控制士气」的硬约束存在张力——但美德本身是纯收益，随机只是"惊喜大小不定"，可接受。
- ✅ `[已定]` **美德不叠层，一个角色最多 1 个。**
  已有美德时再次冲满 100 → **保留旧美德，只结算"给全队加士气"**。
  理由：若"新的替换旧的"，玩家会不敢再冲满（怕洗掉好的美德），反而抑制经营士气的动机。
- ✅ `[已定 #151]` **给全队 +10 士气**（与战场鼓舞 +15 形成梯度）。

## 8. buff 持续时间 ✅（改为绑定士气，取代"3 回合"）

**决策：折磨与美德的持续时间不再按回合计，而是绑定士气曲线的状态。**

| 状态 | 持续到 | 备注 |
|---|---|---|
| **折磨** | **该角色士气回到初始值（50）** | 士气越低陷得越久，把人拉回来就是治疗崩溃本身 |
| **美德** | **战斗结束** 或 **该角色士气再次归 0**（先到为准） | 美德要"守得住"才留得下 |

```
美德中（士气已回初始 50）
  → 若士气再次降到 0
      → 【消除美德 buff】
      → 士气再次初始化回 50
      → 重新走一次崩溃判定（折磨 / 美德）
```

> ✅ 我的评价：这比"3 回合"好得多——它把 buff 时长从**计时器**变成了**士气曲线的函数**。
> 玩家能做的最直接的两件事（拉士气、别再挨打）同时也是解除折磨的手段，因果关系一目了然。
>
> 🔴 **但存在一个必须解决的冲突（见 §8.1）**。

### 8.1 ✅ 冲突已裁决：判定后士气【留在 0】

原冲突：§4 曾写"判定后士气初始化回 50"，与"折磨持续到士气回初始值"直接矛盾（折磨会瞬间结束）。

**裁决（用户拍板）：判定后士气留在 0，靠手段慢慢爬回 50。**

| 方案 | 结果 |
|---|---|
| **A. 留在 0**（✅ 采用） | 崩溃成为一段真实的低谷期，鼓舞/暴击/击杀有了明确用武之地 |
| B. 回 50，折磨改固定回合 | 未采用 |
| C. 回中间值 25 | 未采用 |

**连带修正**：§4 中的"士气初始化（回 50）"已作废，改为**留在 0**。

- ⚠️ 由此产生的"重复判定"问题，见 §4 的衍生问题说明（建议按事件触发而非状态触发）。

## 9. 虚弱者的士气回升

```
每回合回升 = 10 + (站在支援位的【健康】队友数 × 5) + (韧性 ÷ 20)
           → 上限 25
```

| 参数 | 值 |
|---|---|
| 基础值 | 10 |
| 每个健康支援位队友 | +5 |
| **韧性**加成 | 韧性 ÷ 20（韧性 100 → +5） |
| **上限** | **25** |

- 虚弱者之间**互不提供**加成（避免"全员虚弱互相奶"）。
- 节奏估算：独自躺着约 **5 回合**归队；有 2 个健康队友陪着约 **2~3 回合**。
  → 这条把"支援位还有几个健康人"变成了**可量化的救援速度**，很好。
