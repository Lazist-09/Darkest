## 0. 定位：**用户明确要的形态**

```
🔴 用户原话：「我不要所谓的随机事件，而是类似奇观一样的那种【可交互物体】」
⇒ 即：**场景里放着的【实体物件】**，玩家**主动去碰它**，而不是"系统弹一个二选一"
⇒ 🔴 与"事件节点"的根本差别：
   · 事件节点 = 【随机事件】（到了就弹，二选一）      ← 现状（#272）
   · Curio     = 【场景里的物体】（玩家去/不去、空手/用道具）  ← 目标
```

🔴 **而 §1 的 DD 资料显示**：Curio 的乐趣**不在随机**，而在——

> 🔴 **"正确道具 ⇒ 100% 确定的好结果"** ⇒ **玩家要去【记住/猜出】哪个道具对哪个物件** ✅

## 1. DD 的 Curio（**wiki 原文，照抄用**）

### 1.1 基本规则

| # | 规则 |
|---|---|
| ① | **可交互物体**，🔴 **不阻挡通行**（与 `Obstacle` 不同） |
| ② | **位置**：**房间**（一个房间最多 1 个）或 **走廊**（可多个） |
| ③ | **交互方式**：**空手（By Hand）** 或 **使用一个补给品**（火把 / 圣水 / 骷髅钥匙 / 铲子 / 解毒剂 / 绷带 / 草药…） |
| ④ | 🔴 **每个 Curio 有两张表**：**【空手结果表】**（有概率，含坏结果）+ **【各道具的改写结果】**（**通常 100% 好**） |
| ⑤ | **受影响的只有"当前选中的那个英雄"**（所以"派谁去碰"是决策） |
| ⑥ | **结果种类**：战利品（传家宝/金币/宝石/饰品/日志）/ 士气 ± / 治疗 / 流血 / 瘟疫 / 疾病 / buff·debuff / 加·减怪癖 / 光照 ± / 侦察 / **召唤战斗** |

### 1.2 🔴 关键设计（**这是 Curio 的灵魂**）

| # | 设计 | DD 的体现 |
|---|---|---|
| **①** | 🔴 **每个道具"改写"成确定结果** | `Heirloom Chest` + **骷髅钥匙** ⇒ **100% 传家宝 ×4**<br>`Heirloom Chest` + **解毒剂** ⇒ **100% 传家宝 ×3**<br>`Heirloom Chest` + **空手** ⇒ 75% 传家宝 ×2 **／ 25% 流血或瘟疫** |
| **②** | 🔴 **同一个 Curio 对不同道具有不同值** | 上例：**钥匙(×4) > 解毒剂(×3) > 空手(×2 但有风险)** ⇒ **玩家要选"用哪个"** |
| **③** | **"用错道具"也有确定结果（坏的）** | `Decorative Urn` + **铲子** ⇒ **100% 得【负怪癖：愧疚】**（"什么人会亵渎死者？"）<br>⇒ 🔴 **所以"记错了"是有代价的** ✅ |
| **④** | **Curio 有【类型标签】**（用于"强制交互"匹配） | `Treasure` / `Body` / `Worship` / `Haunted` / `Torture` / `Knowledge` / `Food` / `Drink` / `Reflective` / `Unholy` |
| **⑤** | **强制交互** | 有怪癖/疾病/折磨的英雄会**自动空手碰**某类 Curio（**绝不用道具**）⇒ ⚠️ **危险**；某些还会**私吞战利品**（Kleptomaniac） |
| **⑥** | **结果描述带叙事** | "The crate contains stashed heirlooms!" / "What sort of person defiles the dead?"<br>⇒ **不是"获得 2 个传家宝"，而是一句话** ✅ |

### 1.3 典型 Curio（样例，供参照）

| Curio | 空手 | 正确道具 ⇒ |
|---|---|---|
| **Crate（木箱）** | 75% 传家宝 ／ 25% 空 | — |
| **Discarded Pack（丢弃的背包）** | 60% 补给+金币+日志 ／ 20% **侦察** ／ 20% 空 | — |
| **Sconce（壁灯）** | **100% 火把** | — |
| **Shambler's Altar** | 100% 无事 | **火把 ⇒ 召唤 Shambler（Boss 级）** |
| **Stack of Books** | 22% 正怪癖 ／ 17% 日志 ／ 22% 士气+25 ／ 11% 负怪癖 ／ 11% **光照−25** ／ 17% 空 | **火把 ⇒ 士气 +100**（"销毁知识，背负罪责"） |
| **Eldritch Altar** | 40% 士气+25 ／ 10% 减负怪癖 ／ 50% 空 | **圣水 ⇒ 100% 减一个负怪癖** |
| **Heirloom Chest** | 75% 传家宝×2 ／ 25% 流血·瘟疫 | **钥匙 ⇒ ×4** ／ **解毒剂 ⇒ ×3** |
| **Altar of Light** | **100% buff（到扎营）+20% DMG** | **圣水 ⇒ 同 buff 但 +30% DMG** |
| **Confession Booth** | 50% 士气+15 ／ 25% 金币+饰品 ／ 25% 减负怪癖 | **圣水 ⇒ 100% 士气 −30** |
| **Decorative Urn** | 44% 宝石+饰品 ／ 22% 瘟疫 ／ 7% 疾病 ／ 22% 空 | **圣水 ⇒ 宝石+饰品 ×4** ／ ⚠️ **铲子 ⇒ 100% 负怪癖** |
| **Alchemy Table** | 50% 瘟疫 ／ 25% 金币 ／ 25% 空 | **草药 ⇒ 金币×2** ／ **火把 ⇒ 光照回满** |

🔴 **看出规律了吗**：
```
🔴 **"好道具"通常不是最贵的那个**（草药/圣水/解毒剂 便宜；钥匙贵）
🔴 而**同一个 Curio 对不同道具有【不同等级的好结果】** ⇒
   ⇒ **玩家要在"省道具"和"拿更多"之间权衡** ✅
```

## 2. 🔴 我们要做的（**三条同时成立**）

### 2.1 目标形态

```
🔴 Curio = 地图房间里的一个【可交互物体】
   玩家走到该房间 ⇒ 看到物件 ⇒ 选择：
     · 【空手碰】      ⇒ 走【空手结果表】（有概率，含坏结果）
     · 【用一个道具碰】 ⇒ 走【该道具的确定结果】
     · 【不碰，直接走】⇒ 🔴 **允许**（与 #258 的"事件不许跳过"不同 —— 见 §3）
```

### 2.2 🔴 与 `#272` 的关系（**不是推翻，是嵌入**）

```
🔴 #272 我定的"事件节点 = 必然代价 + 可选收益"（空手有代价、搜刮有额外代价）
⇒ 🔴 **那正好就是 Curio 的【空手结果表】** ✅
   · "必然代价" = 空手碰有概率出坏结果 ✅
   · "可选收益" = 用对道具 ⇒ 确定的好结果 ✅
⇒ ✅ **所以 #272 不需要推翻，它成为 Curio 框架的一个特例** ✅
   —— 而差别是：**从"二选一"变成"三选一（空手/道具/走开）"，且【结果由道具决定】**
```

### 2.3 🔴 与 `#258`「事件不许跳过」的关系（**必须改**）

```
🔴 #258 定：事件节点【不允许跳过】（否则"没有代价，退化成免费资源点"）
⇒ 🔴 而在 Curio 框架下：**"走开"是【合理选择】** —— 因为
   · Curio【不阻挡通行】（DD 原文①）⇒ **它就是可选的**
   · 而"空手碰"已有代价（概率）⇒ **不需要用"强制"来造代价** ✅
⇒ ✅ **裁定：Curio 允许【不碰】**，而 `#258` 的"不许跳过"**作废**（其目的已由"空手有概率"达成）
```

| **2** | **废弃营地**（Discarded Pack 位） | `Scrounging` | 50% **+2 柴火** ／ 30% **侦察** ／ 20% **全队 −5 士气** | — |

| # | 检查 | 我们是否满足 |

## 4. 与"节点表"的关系（`expedition_nodes.json`）

```
🔴 现状：expedition_nodes.json = 4 个【事件节点】（ev_supply_cache / ev_firewood_pile / ev_shrine / ev_corpse）
⇒ ✅ 改造：**同一批数据，从"事件（type=event）"改为"Curio（type=curio）"**
   · 新增字段：`curio_type`（类型标签）· `bare_hands`（空手结果表）· `item_results`（道具 ⇒ 确定结果）
   · 保留：`cost`（若有必然代价—— 见 #272）
⇒ ⚠️ 而**"事件节点"这个形态【保留】**（不删）—— 因为**契约里"每步二选一"仍需要一种无战斗节点**
   ⇒ 🔴 但**M7.6 拓扑下，节点由【房间】决定**（`EventNodeIdForRoom`）
      ⇒ **Curio 就挂在"房间"上**（DD 原文②：房间 1 个 / 走廊多个）✅
```

🔴 **落点建议**：
```
· `data/expedition_nodes.json`：`type: "event"` → **`type: "curio"`**（并加 `curio_type` / `bare_hands` / `item_results`）
· `ExpeditionSession.ResolveEventNode` → **`ResolveCurio(roomId, heroId, itemUsed?)`**
· UI：**进房间 ⇒ 显示物体 + 三个按钮（空手 / 用道具 ▾ / 走开）**
```
