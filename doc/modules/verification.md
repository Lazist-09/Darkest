# 阶段 3 验收标准（可玩性验证方式）

> 本文档回答 **1-7 可玩性验证方式**：垂直切片这场 4v4 战斗，**怎样算「设计成立、值得往下做」**。
> 决策来源：#119 验收口径 / #120 平衡验证 / #121 系统触发 KPI / #122 手感指标。
> 切片范围见 `state.md` 本期不做 + #97（2 角色先跑链路，但 #110 已定 6 人满编 4v4）。
>
> **角色边界（#123）**：本文档是**策划交付的验收规格**，由**实现方 / 测试方**执行验证。策划（AI 搭档）**只负责定义标准**，不负责实现原型、不跑 Monte Carlo 模拟、不手动试玩验收——那是实现期的工作。

---

## 1. 验收总口径（#119 · 设计意图验证型）

切片「通过」必须**同时**证明两件事，缺一不可：

1. **破局可行**：存在一条取胜路径，且胜出靠的是**决策**（位置 / 位移 / 士气经营 / 集火取舍），而非纯运气。
2. **系统真触发**：士气崩 / 虚弱 / 死门 / 撤退这些核心系统在**实战中真正发生且影响战局**——不是纸面数字、不是只能靠手动构造场景才出现。

> 反对「只验工程跑通」：规则跑通无死锁只是及格线，不证明双轨爽点成立。
> 反对「纯数据验收」：胜率达标也可能「能赢但无聊」，手感必须人工补验（见 §4）。

---

## 2. 平衡验证（#120 · 随机模拟 Monte Carlo）

**方法**：写对战脚本，自动跑大量随机/半随机对局，用胜率分布反推数值。

| 项 | 设定 |
|---|---|
| 场数 | **≥ 300 场**（区间 200~500，越多越稳） |
| 玩家策略 | **半随机**：在「合法技能 + 合法目标」内按权重随机选（含位移 / 集火 / 鼓舞）；另跑一版**基线 AI**（优先打最低血 / 优先击杀支援位）做对照 |
| 敌人策略 | 用 `enemy.md` §5 的固定优先级表 + 少量随机（与实机一致） |
| 胜率可接受区间 | **40%~70%**（硬核受苦定位：不能必输、也不能轻松碾压） |
| 强制记录 | 胜率、平均回合数、各角色平均输出、死门致死数、士气分布直方图、各技能使用率 |

**反推规则**：
- 胜率 **< 40%** → 敌方压力偏强（#124「单体 ≈ 战士」基准下）或我方数值 / 技能起手偏低 → 上调我方或下调敌方。
- 胜率 **> 70%** → 「绝境翻盘」(#11) 难触发，敌人偏弱 → 上调敌方压力（增援时机 #69 / 强度 #71 优先）。
- 平均回合 **< 6 或 > 18** → 节奏偏离 8~12 目标（见 `character.md` §5.2），调伤害 / 血量。

> ⚠️ 风险 5（6 人 vs 4 人人数优势稀释压力）主要在此暴露：若模拟显示胜率虚高，先查是否「人数碾压」而非「决策取胜」。

## 3. 系统触发 KPI（#121 · 频率达标）

用 §2 的模拟日志统计，**单场平均**需达到以下下限（全部为「自然发生」，非构造）：

| KPI | 单场下限 | 验证什么 |
|---|---|---|
| 士气触底（归 0 并崩溃判定） | **≥ 1 次** | 士气曲线不是摆设，折磨/美德链路能跑 |
| 虚弱（HP 归零→虚弱） | **≥ 1 次** | 虚弱状态、回升、死门前置可达 |
| 死门判定（虚弱受伤） | **≥ 3 次** | 死门是常态压力点，不是稀有事件（6 人队下应较频繁） |
| 撤退可触发 | **≥ 1 次（整场统计）** | 止损通道存在、UI 显示成功率、失败可重试(#118) |
| 美德 / 折磨各出现 | **≥ 1 次（整场统计）** | 崩溃双向结果都可达，非单向惩罚 |
| 位移实际使用（推/拉/交换/突进/后撤） | **≥ 2 次** | 位置是活的操作维度，非装饰 |

> 若某 KPI 长期为 0 → 对应系统可能被数值/AI 压死，回查 `morale.md` / `formation.md` / `enemy.md` 起手值。

## 4. 手感 / 策略深度验收（#122 · 定 3 指标人工评）

Monte Carlo 管「能赢 / 系统活」，手感必须**人工打**后评分（1~5 或 通过/不通过）：

| 指标 | 判定标准 | 通过线 |
|---|---|---|
| **① 有意义的位置决策** | 玩家每回合需要考虑「推/拉谁、是否换人、站位影响技能可用性」，而非无脑集火 | 多数回合存在 ≥ 1 个非显然的位置抉择 |
| **② 无单一无脑最优解** | 不同局面需要不同应对：集火 / 位移 / 鼓舞 / 撤退有真实取舍，不存在「永远先 X」 | 试玩中未出现贯穿全场的唯一最优动作 |
| **③ 单场时长** | 节奏落在暗黑地牢式紧凑区间 | **8~15 分钟** |

**附加观察项（不强制，但记录）**：
- 撤退是否真有「止损 vs 赌翻盘」的意义，还是纯丢士气；
- 敌人 AI 是否**可预判**（#86），精密操作是否成立；
- 是否出现「老虎机感」——五层随机（命中/暴击/折磨/死门/撤退 #46）是否让玩家归因于运气而非决策（呼应风险 2/3）。

> 手感验收由设计者 / 测试者实机打 ≥ 5 局后填下表（见 §5）。

## 5. 阶段 3 验收清单（完成时逐条打勾）

- [ ] **§2 模拟跑通**：≥ 300 场，胜率落 40~70%，日志齐全
- [ ] **§3 KPI 达标**：士气崩 / 虚弱 / 死门 / 撤退 / 美德折磨 / 位移 全部达下限
- [ ] **§4 手感**：3 指标人工评通过，附加观察无致命问题
- [ ] **无软锁**：撤退重试循环、全虚弱死循环、增援卡死均无
- [ ] **无数值溢出 / 异常**：士气不越界 [0,100]、HP 不负数、位置不越槽
- [ ] **试玩报告产出**：含胜负、系统触发日志、手感评分、反推的数值调整建议

## 6. 本验收要顺带验证的设计风险

| 风险 | 怎么被本验收暴露 |
|---|---|
| 风险 2 · 士气负反馈螺旋 | §3 士气崩频率 + §4「老虎机感」观察：若崩后必连锁全崩，调美德保底/鼓舞权重 |
