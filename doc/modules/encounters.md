## §2 ✅ A. 具名编成目录（**8 条 · 用【意图】命名**）

> 🔴 **每条一句话说明"它想逼玩家做什么"**（主程序要求）✅ · 🔴 **原型全部来自 `units.json`**（不发明）✅

| id | 编成（槽 1→4） | **它想逼玩家做什么** |
|---|---|---|
| `enc_standard_line` | melee · melee · archer · caster | **基准线**：与现模板同形，作为对照 ⇒ 玩家先学会"标准解法" |
| `enc_poke_front` | melee · melee · melee · archer | **三近战压前**：前排承伤压力大 ⇒ **逼你别全堆输出** |
| `enc_backline_pressure` | melee · archer · archer · caster | **双弓**：后排持续输出 ⇒ **逼你处理后排**（位移/突进） |
| `enc_full_ranged` | archer · archer · caster · caster | **无肉盾**：敌人很脆但输出高 ⇒ **逼你速攻**（拖久必崩） |
| `enc_skirmish` | melee · archer · caster · archer | **混合**：三条线都有 ⇒ **逼你分配注意力**（不能只解一种） |
| `enc_elite_two` | caster · caster · melee · melee | **双法系**：法术压力叠加 ⇒ **逼你打断 / 抢节奏** |
| `enc_swarm` | melee · melee · melee · melee | 🔴 **极端**：四近战 ⇒ **逼你 AOE / 位移 / 换位**（单体解法会崩） |
| `enc_glass_cannon` | caster · caster · caster · caster | 🔴 **极端**：玻璃大炮 ⇒ **逼你【先手】与【目标选择】**（谁先死决定胜负） |

```
🎖️ **而 8 条的设计逻辑（一句话）**：
   **前 6 条 = 【三种原型的位置排列】**（**同一批敌人，不同阵型 ⇒ 不同解法**）·
   **后 2 条 = 【极端单色】**（**用来测"单一解法能不能通吃"**）✅
⇒ 📌 **即：多样性来自【阵型】，而不是来自【更多种类】** ——
   而那**在只有 3 原型的条件下，是唯一诚实的做法** ✅（**并已登记"解冻后扩原型"**）
```

```

```
