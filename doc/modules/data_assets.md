## 1. 🔴🔴 核心裁定：**两份形态，各管一层**（不能"全换成 `.tres`"）

```
🔴 **我们不能把 `data/*.json` 全换成 `.tres`** ——
   因为 **`Resource`（`.tres`）需要 Godot 运行时** ⇒ 🔴 内核用了它就【不是零 Godot】❌
   ⇒ 而没有零 Godot ⇒ **内核无法 headless 跑** ⇒
     🔴 **我们会失去：xUnit 全量测试（470+ 项）· 蒙特卡洛探针（A1/V10/Anomaly）· 确定性复现** ⚠️
     而这四样【正是本项目全部判据的根基】。
```

✅ **正解 = 两份形态，各管一层**：

| 层 | 形态 | 谁读 | 为什么 |
|---|---|---|---|
| 🔴 **业务数据** | **`darkest/data/*.json`** | **内核（零 Godot）** | **可 headless 测、可蒙特卡洛、可确定性复现** ✅ |
| 🔴 **表现数据** | **`darkest/resources/**/*.tres`** | **表现层（Godot `Resource`）** | **可在编辑器里可视化调、可 Inspector 改** ✅ |

🔴 **纪律**：**同一份数据的两个视图，必须靠【生成/导出】而不是【手抄】**
```
❌ 手抄两份 ⇒ 必然不一致（而"不一致"正是本项目最贵的一类 bug：`#244`/`#302`/`#308`）
✅ 正解：**以 `data/*.json` 为【唯一真相】，`.tres` 由它【生成】**（或 `.tres` 只放"纯表现"、
   不放任何业务数值）✅
```

### 1.1 与 DD 的差别（**为什么不照抄 DD 的统一形态**）

```
DD：**单一引擎 + 一座 `.darkest` 数据山** ⇒ 可以【统一形态】✅
我们：多了一条【内核零 Godot】的约束
⇒ 🔴 那条约束【不是负担，而是我们 470 项测试 + 蒙特卡洛的根基】✅
⇒ ✅ **不能为了"形态整洁"牺牲它** —— 那是拿【可测性】换【整洁】❌
```

## 2. 🔴 分工（与四角协议对齐）

```
策划师   ⇒ **产数据资产**：写 `data/*.json` 的【内容】+ 验收字段表（怎么测）
架构师   ⇒ **卡死契约**：`data_schema` 的【字段/类型/校验 P1~P27】+ 读取接口
主程序   ⇒ **写"通用解释器"**：读数据 → 灌进运行时（**不写业务判断在解释器里**）
UI 设计师 ⇒ **表现数据**：`resources/**/*.tres`（Theme / 布局常量 / 视觉规范）
```

🔴 **一句话**：**引擎是解释器、内容是数据、扩展靠加文件不靠改代码** ——
**而我们的"加文件"落点是 `data/*.json`（业务）+ `resources/*.tres`（表现）** ✅

## §N 🔴 `buff_defs` 六个"填了没人消费"字段的裁定（`#408` —— 架构两问 + 我加一问）

> 🔴 **背景**：主程序用【消费面普查】（`#404` 认可的方法）查到 `buff_defs.json` **6 个字段被解析但不被消费**。
> 🎖️ **而那次普查【又证明了它有用】** —— 它已经挖出 4 处（RosterCap / RookieLevel / ReliefCost / MoraleRestore），
> **这是第 5~10 处** ✅

### N.1 ✅ 问一：本期【没有】驱散 / 净化机制

```
🔴 **裁定：没有** ⇒ **维持"约束 + 预留"** —— 而**我要改一处**：
   ① ✅ **"正面 buff 不可驱散"的校验规则【对】**（**它是一道【防火墙】**：
      防止将来加正面 buff 时被误驱散）✅
   ② 🔴 **但"`negative`(8) 与 `dispellable=true`(8) 数字完全同形"是一个【危险信号】** ⚠️
      ⇒ 📌 即：**`dispellable` 现在是【冗余的】**（**它恒等于 `polarity == negative`**）⚠️
      ⇒ ✅ **裁定**：**保留 `polarity`（它是真数据）· 而 `dispellable` 标注为【派生 + 预留】** ✅
         —— 即：**"能不能驱散" = `polarity == negative`**（**不需独立字段**）✅
      ⇒ 🔴 **而将来若有"可驱散的【正面】buff"**（如"狂乱"）⇒ **才需要独立字段** ⚠️
   ⚠️ **而"数字同形"这件事本身值得记**：**两个字段恒等 ⇒ 其中一个必然是【冗余】** ——
      而**数据里看不出谁是"真数据"**（**需要一个裁定**）✅
```

### N.2 ✅ 问二：`hooks` **可以长期作为"行为说明"存在**

```
✅ **采纳架构的建议** —— 理由：
   ① ✅ **`hooks` 是【行为说明】，而实现的真相在【别处】**（`duration.type` / `TargetPreference` /
      `tuning.guard_redirect`）⇒ 📌 **那它与"两处真值"不同**：
      **两处真值 = "两处都真"**；**而这里是【一处说明 + 一处真相】** ✅
   ② 🔴 **但必须守两条**（架构已提，我加强）：
      · **标注"仅说明、不参与行为"** ✅
      · 🔴 **不得写【实现里没有的行为】** ⚠️
      🎖️ **而它举的正例很好**：`virtue_inspired` 写着 `VALUE MISSING -> O-27` · `bound` 写着 "slice no trigger"
         ⇒ **那是【如实标注】的好样板**（**它说的是"我还没实现"，而不是"我实现了"**）✅
⇒ ⚠️ **而"要求唯一真相（实现读 `hooks`）"⇒ 我裁【不做】** ✅
   📌 **理由**：**它会把"散文"变成"通用触发器语言" = 一个新机制** ——
      而**我们现在该做的是【闭环收口】，不是加新机制** ✅（**同 P3 的处置**）✅
```

### N.3 ✅ 问三：`class` ⇒ **删**；`timing` ⇒ **删**

```
🔴 **`class`（恒 `buff`×21）⇒ 删** —— 理由：
   ① 🔴 **无区分度 ⇒ 它是【纯噪声】**（**填了、校验读、只有一种值**）⚠️
   ② ⚠️ **而"假设将来要扩"不是保留它的理由** ——
      **"将来扩"时再加字段，比"现在留一个恒定的"便宜** ✅
      （**同"未使用的东西不留"的判据：能不能回答"它为什么在"**）✅
   ③ ✅ **而"分类"的真实需求（AI 目标偏好 / 抗性 / UI 图标）⇒ 应由【别的字段】表达** ⚠️
      （**`polarity` 已表达"正/负"；而"控制/dot"应由【行为】表达，不是【标签】**）✅
🔴 **`timing`（空 · 0/21 + 设计文档 0 提及）⇒ 删** ✅（**与架构建议一致**）
```

### N.4 🎖️ 而架构立的【字段四分类】我确认（**它是一条通用规矩**）

```
✅ **每个 `data/*.json` 字段必须归入四类之一**：**行为 / 约束 / 说明 / 空** ✅
   ⇒ 📌 **理由（架构原话，我完全同意）**：**"填了却没人消费"会同时骗两种人** ——
      **填的人以为在生效；读的人以为它是行为** ⚠️
⇒ 🎖️ **而它是【纪律 V】的邻居**：
   · **V** = **"展示值 ≠ 消费值"**（**玩家看得见的谎**）
   · 🔴 **本条** = **"填了 ≠ 生效"**（**开发者看得见的谎**）⚠️
   ⇒ 📌 **共同形状**：**一个东西【看起来在工作】，而【没有消费方】** ✅
   ⇒ ✅ **所以处置也类似**：**给每个字段写明【它的消费方是谁】** ✅
```
### N.5 🔴🔴 **更正：我用了两把尺子** —— 裁定 **(A) 删 `dispellable`**（`#409` —— 架构抓到）

```
🔴 **架构抓到的**：我在 `N.1`（`dispellable`）与 `N.3`（`class`）**用了不同的尺子** ⚠️
   · **`class`**：**恒定值 ⇒ 删**（**"将来扩时再加，比现在留一个恒定的便宜"**）✅
   · 🔴 **`dispellable`**：**恒定派生值 ⇒ 我却说"保留 + 标注"** ❌
   ⇒ 🔴 **而它读出了断言原文**（`BuffDefsConfig.cs:189-190`）：
      ```csharp
      bool polarityOk = b.Polarity == Negative ? b.Dispellable && b.Class == Buff
                                              : !b.Dispellable && b.Class == Buff;
      ```
      ⇒ 🔴 **校验【强制】`dispellable == (polarity == Negative)`** ⇒ **它【只可能取派生值】** ⚠️
   ⇒ 按我 ③ 的尺子（**"删掉它，别人能不能从别的字段算出同样的值？"**）⇒ **能** ⇒ ✅ **它也是冗余** ✅
```

#### ✅ 裁定：**(A) 删 `dispellable`**

```
✅ **按同一把尺子：删** —— 理由：
   ① 🔴 **一致性优先**：**同一轮里两把尺子，比"错一次"更糟** ⚠️
      —— 因为它让**判据本身【不可预测】**（**别人无法从先例推出结论**）✅
   ② ✅ **"能不能驱散" = `polarity == Negative`**（**派生，不需独立字段**）✅
   ③ ✅ **将来要"可驱散的正面 buff"（如"狂乱"）⇒ 再加回** ✅
      —— 📌 **而那时它是【真数据】**（不是派生）⇒ **加回来是对的** ✅
⇒ 🎖️ **而这正是架构的原话**：「**少一处"看起来是信息、其实是派生"**」✅
```

#### 🎖️ 而架构那条【同义反复的识别】我要立为判据

```
🔴 **它写**：「**否则它就是一句同义反复**：**只可能取派生值 + 强制等于派生值**」✅
⇒ ✅ **判据**：**若某校验【只能取派生值，又强制等于派生值】⇒ 那条校验【什么都没保证】** ⚠️
   —— 它**看起来在防错，其实防的是一个不可能发生的事** ✅
   ⇒ 📌 **同族**：**纪律 X（判据工具必须"该红时红"）** ——
      **"永远不可能红"的校验，等于【没有校验】** ⚠️
```
