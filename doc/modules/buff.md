# Buff / Debuff 系统（模块）

> 设计目标（用户明确）：**后续还会不断加新 buff，系统必须极端易于维护。**

## 1. 核心思路

**一个 buff = 一组「修改器」+ 一组「钩子」+ 一条「生命周期」规则。**

加新 buff = **加一条数据**，不改任何代码。
只有出现**全新种类的机制**（比如"复制一个单位"）时才需要写代码，届时新增一种修改器/钩子类型即可。

```
buff
 ├── 修改器（Modifiers）：持续生效的数值或状态改变
 ├── 钩子（Hooks）：在特定时机触发的一次性行为
 └── 生命周期：什么时候挂上、什么时候消失、能不能叠加
```

## 2. 数据表结构（示例）

```yaml
- id: guard                      # 守护
  名称: 守护
  功能: 支援
  图标: guard.png

  生命周期:
    持续时间: { 类型: 回合数, 值: 3 }
    叠加:     { 规则: 刷新, 上限: 1 }     # 刷新 / 叠层 / 不叠加
    驱散:     { 可被驱散: true, 阵营: 友方 }

  修改器:
    - { 类型: 属性修正, 目标: 物理防御, 运算: 加, 值: 10 }

  钩子:
    - 时机: 友方受到伤害前
      条件: 目标在守护范围内
      效果: 伤害重定向到自身
```

> 加一个新 buff，就是往这张表里加一条。**这就是"极端易于维护"的具体含义。**

## 3. 修改器类型（Modifiers）

| 类型 | 说明 | 例子 |
|---|---|---|
| **属性修正** | 加 / 乘 某个属性 | 物理防御 +10；伤害 ×0.5；速度 -30% |
| **状态标记** | 开/关一个布尔状态 | 无法行动、无法攻击、免疫恐惧、嘲讽、隐匿 |
| **伤害修正** | 对"造成伤害 / 受到伤害"做增减 | 造成伤害 +25%；受到伤害 -50% |
| **概率修正** | 改命中率 / 暴击率 / 触发概率 | 暴击率 +15%；死门抗性 +20% |

> 属性修正的**运算顺序**要定死，否则同样的 buff 组合会算出不同结果。
> 建议：`最终值 = (基础值 + 所有加法修正) × 所有乘法修正`，**加法先于乘法**。

## 4. 钩子（Hooks）

| 时机 | 用途 |
|---|---|
| 回合开始 / 回合结束 | 持续伤害（流血）、每回合回士气（振奋） |
| 行动前 / 行动后 | 无法行动（捆缚）、行动后额外效果 |
| **受到伤害前** | **伤害重定向（守护）、护盾吸收、受到伤害增减** |
| 受到伤害后 | 触发死门判定、反弹伤害 |
| 造成伤害前 / 后 | 伤害加成（勇猛）、吸血 |
| 被治疗 / 被鼓舞前 | **拒绝这一次（自私）** |
| 使用技能前 | **拒绝释放（恐惧）** |
| 位移时 | 位移抗性之外的一次性位移效果 |
| 士气变动时 | 士气衰减减半 |
| 进入虚弱 / 死亡时 | 触发连锁效果 |

> 现有设计里已经用上的：**自私**（被治疗前）、**恐惧**（使用技能前）、**捆缚**（行动前）、**振奋**（回合开始）。
> 钩子清单是**可扩展**的——未来需要新时机就加一个，不用改已有 buff。

## 5. 叠加规则 ✅

**决策（用户拍板）：按 buff 是否限时来区分。**

| buff 类型 | 再次获得时 | 说明 |
|---|---|---|
| **有时限的**（如 3 回合） | **刷新**时长 | 刷新后强度不变，避免"叠三层数值爆炸" |
| **无限时的**（整场战斗） | **叠层**，但有**上限** | 无限时的 buff 若不叠层，重复获得就完全浪费 |

- ✅ **叠加层数上限 = 2 层**（定案 #159）。
  理由：1 层等于浪费（重复获得无收益）、3 层以上容易数值爆炸；2 层是"值得叠但不失控"的档位。

> ✅ **已裁决（用户拍板）：美德不叠层，上限 1 个。**
> 一个角色同时最多拥有 1 个美德。
> - ✅ `[已定]` **已有美德时再次冲满 100 → 保留旧美德，只结算"给全队 +10 士气"**。
>   理由：若"新的替换旧的"，玩家会不敢再冲满（怕洗掉好的美德），反而抑制了经营士气的动机。

> ⚠️ **（原风险记录）** 美德是"整场战斗"类型，按上面的规则本会叠层，
> 一个角色反复冲满士气就能堆出多个美德，强度失控。**此风险已由"上限 1"解除。**

## 5.1 驱散 ✅

**决策：负面 buff 可被驱散，正面 buff 不可被驱散。**

- 驱散成为**对抗折磨的一条出路**——玩家可以用净化技能主动终结崩溃，而不是只能干等士气爬回 50。
  这与 §morale「让玩家主动控制士气」的硬约束方向一致，我认可。
- 正面 buff 不可驱散：自己的美德不会被拆，敌方增益也拆不掉。
- ✅ `[已定 #159]` **驱散规则（定案）**：

  | 项 | 结论 |
  |---|---|
  | 消耗行动 | ✅ **消耗施法者本次行动** |
  | 驱散数量 | **1 次 1 个**（不做群体驱散，保住"净化"的稀缺性） |
  | 成功率 | **100%** —— 不再加第 10 层随机（见 `combat_math.md` §9） |
  | 可驱散 | 仅**负面 buff**：折磨（恐惧 / 自私 / 失控）、眩晕、捆缚、流血、属性减益 |
  | **不可驱散** | 正面 buff（美德 / 守护 / 护盾 / 各类增益）、**虚弱状态本身**、死门 |

> ⚠️ **虚弱不可被驱散**——否则"治疗 + 驱散"能直接跳过整个虚弱 / 死门系统，切片的核心压力就没了。
> ⚠️ 我方目前**没有驱散技能**（4 原型 36 技能里一个都没有）。它现在是**预留接口**，不做也不影响切片。

## 6. 生命周期（持续时间）

本作已有三种，正好可以统一进这个字段：

| 类型 | 用于 |
|---|---|
| 回合数 | 常规 buff（如守护 3 回合） |
| **直到士气回到初始值** | **折磨**（§morale 8） |
| **整场战斗 / 直到士气归 0** | **美德**（§morale 8） |
| 永久 | 极少，如角色固有特质 |

> 这三种已经覆盖了现有全部 buff，说明这个字段的表达力够用。

## 7.1 守护类 buff 详解 ✅（用户选定 3 个）

### 护卫（Guard）

| 项 | 内容 |
|---|---|
| 类型 | 正面 buff（挂在保护者身上） |
| 钩子 | **友方受到伤害前** |
| 条件 | 受伤者在**守护范围**内 |
| 效果 | **伤害重定向到保护者自身**；同时给被守护者 **+微量士气**（起手 +3，可调，#136） |

> ✅ **#136 守护 buff 重定义**：守护 = **替被守护者挡刀（护卫）+ 给被守护者 +微量士气**。护卫机制保留，不是取消。
>
> ✅ 这条与位置系统**天然咬合**：守护范围用位置表达（如"相邻的己方位置"），
> 于是"把敌人推开一点，他就护不住了"成为可行战术——位移又多一重用途。
>
> ✅ **已裁决（用户拍板，推翻前一条）：护卫重定向过来的伤害，照常触发死门判定。**
>
> 用户在看清逻辑链后明确：**虚弱状态下受到的任何伤害都要过死门**，包括：
> - 直接攻击
> - 持续伤害类 debuff（流血等）
> - **护卫替别人承受的伤害**
>
> ~~"不触发死门"~~ → 已作废。此前的"无敌肉盾"漏洞随之解除。
>
> 这条同时意味着：**让虚弱的角色去护卫 = 让他去赌命**。
> 这正是护卫机制该有的重量——他不是免伤盾，他是在替你挨刀。
> ✅ **护卫的 4 条边界已全部裁决（#159）**：
>
> | # | 议题 | 裁决 |
> |---|---|---|
> | 1 | 虚弱的保护者替人挨打，是否触发死门 | ✅ **触发**（用户已拍板，见上）——让虚弱者护卫 = 让他赌命 |
> | 2 | 被保护者被位移**推出守护范围**的瞬间，这次伤害还算不算 | ✅ **在"伤害结算时"实时判定范围** —— 推出去了就不算被守护。这让"推开被守护者"成为破护卫的正当战术 |
> | 3 | 保护者**同时守护多人**，多人同时受伤怎么结算 | ✅ **按行动顺序逐个结算**，保护者**每回合最多重定向 1 次**（超出部分不再挡）。避免一次 AOE 让他替全队挨打而暴毙 |
> | 4 | 重定向后的伤害是否**再算一次**保护者的防御 / 抗性 | ✅ **要算** —— 否则护卫等于自杀，没人敢用 |
>
> ✅ **新增第 5 条（与 #156 护盾保持一致）：护卫只重定向【物理类攻击】。**
> 精神类攻击**无法被替挡**——恐惧只能自己承受。理由同护盾：盾牌挡刀不挡恐惧。
> ⚠️ 这条是我顺着 #156 的逻辑推出的建议，**未单独立为决策，可推翻**。

### 护盾（Shield）

| 项 | 内容 |
|---|---|
| 类型 | 正面 buff |
| 钩子 | **受到伤害前** |
| 效果 | **抵挡 N 次物理攻击**，次数归 0 后消失（#156，**不是**吸收固定点数） |
| 叠加 | 有时限 → 刷新；无限时 → 叠层（上限 2，#159） |

**数值**：铁壁 = **2 次，CD 4**（`skill_data.md` §2 坦克 #5）。

| 规则 | 结论 |
|---|---|
| 抵挡什么 | **仅物理类攻击** |
| 精神类攻击 | ❌ **穿透护盾**——伤害照常结算、士气照扣 |
| 持续伤害（流血） | ❌ 不消耗次数（不是"攻击"，每回合独立跳血） |
| AOE | ✅ 消耗 1 次（一次 AOE 算一次攻击） |
| 位移 / 自我伤害 | ❌ 不消耗次数 |
| 被抵挡的后果 | **完全无效**：不扣 HP、不触发死门、不触发虚弱 |

> ✅ **为什么"按次数"而不是"按点数"（用户拍板）**：
> 按点数时护盾对"高频低伤"和"低频高伤"的价值差极大，平衡难调；
> 按次数则**每次都是完整抵挡一次攻击**，手感干脆、数值好算，也让"先骗掉护盾再打要害"成为可行战术。
>
> ✅ **为什么只挡物理**：盾牌挡得住刀，挡不住恐惧。
> 与 #157「只有精神伤害降士气」**同向强化**——施法者成为唯一能同时绕过护盾又打击士气的威胁。
>
> ⚠️ 我的提醒：按次数抵挡**在数值上偏强**（一次抵挡可能免掉 10+ 点伤害）。
> 2 次 / CD 4 是保守起手值，实测若偏强，优先**降到 1 次**或**CD 提到 5**，不要改成点数吸收。

### 标记（Mark）

| 项 | 内容 |
|---|---|
| 类型 | **负面 debuff（挂在敌人身上）** |
| 效果 1 | 被标记者受到**某些技能的攻击时**，受到更多伤害（+X%） |
| 效果 2 | **吸引敌方注意**——更容易被我方攻击（影响玩家决策）或更容易被攻击（影响 AI） |

> ⚠️ **"吸引敌方注意"的方向必须明确**（用户描述里有两种读法）：
> - **读法 A**：标记让**我方 AI/玩家**更倾向于打他 → 这是**集火信号**，服务"精密操作"爽点；
> - **读法 B**：标记让**敌方 AI** 更倾向于打被标记者 → 这其实是"嘲讽敌人"，逻辑上很怪（我方给敌人上 buff 让他打自己人？）。
>
> ✅ **已裁决（用户拍板）：两者都要。** 标记同时具备：
> 1. **加伤**：我方某些技能对被标记者造成更多伤害；
> 2. **改 AI**：敌方 AI 更倾向于攻击被标记者（或者说，被标记者更容易"挨打"）。
>
> ⚠️ 我的提醒：一个 debuff 同时管"我方输出"和"敌方 AI"两边，平衡点会很难找——
> 加伤数值稍高就会成为必带 debuff。建议**加伤幅度保守**（如 +15~20%），把主要价值放在**集火引导**上。
> 另外，既然它会改敌方 AI，就与 §enemy 的"固定优先级表"耦合了，
> 需要在 AI 配置里留一个"标记权重"字段，否则无法实现。
