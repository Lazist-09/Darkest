## 0. 三条「DD 印证我们走对了」（保留，别被带偏）

| # | 结论 |
|---|---|
| **0.1** | **#198 自适应增援弹性 ≈ DD 的 Stalling 惩罚**——DD：判定"拖延回合"＝存活敌人 ≤2 且该回合全队只用 0~1 个**主动技能**；连续 **3 回合** → 全队加压，再 1 回合 → **刷援军**；**用 2 个主动技能可随时重置**。我们独立设计的 #198 与之同构 → **方向验证** |
| **0.2** | **我们的信息透明度高于 DD**——DD 的撤退成功率**不显示**（实际 70% + 每次失败 +5%）；DD 的"被 Mark 者挨打"是**隐藏概率**（67→87%）。我们显示精确数字 + 敌方目标偏好**固定可预判** → 更贴我们自己的「精密操作」定位 |
| **0.3** | **DD 的"折磨"丰富度来自战斗外**——7 种通用 Affliction 的几十条 act-out 大多发生在**地牢探索**（拒绝摸奇物/拒绝进食）。我们只有战斗内，**3 种（恐惧/自私/失控）是合理的切片化，不必扩到 7 种** |

## 1. 立刻采纳的 7 条（#202–#208）

### 1.1 眩晕抗性递增（#202）🔴 直接解决既有待确认项

| | 内容 |
|---|---|
| **DD 原值** | 被眩晕的单位跳过回合后获得 **+50% 眩晕抗性，持续 1 回合**；该 buff **在该单位回合开始时消失**；若在 buff 仍在时**再次被晕 → 再叠 +50%**（→100%、150%…），**直到该单位终于获得一个"未被晕的回合"** |
| **我们的现状** | 眩晕抗性**固定** 30~45%，无递增。→ 文档待确认项原文：**"眩晕概率 30~40% 是否偏高（配合眩晕抗性后实际 21~28%）→ 控制链强度"** |
| **对齐规格** | ① 新增临时状态 **「眩晕抗性递增」**：每次**成功施加眩晕**后 **+50%**，**可叠加**；<br>② **清除条件**＝该单位完成一次**未被眩晕**的行动（与 DD 同）；<br>③ 实际概率沿用我们的**乘法口径**（`技能概率 × (1 − 抗性)`）：抗性 = 基础值 + 递增值，**上限 100%**（100% 时实际概率为 0，即自然免疫）；<br>④ 递增是**临时状态**，不写入单位基础属性 |

> ✅ **为什么这条特别值**：它是**控制链过强的经典解**，且比"直接免疫"优雅——**玩家仍可尝试，但收益递减**，
> 而且它把"控场"从"无限锁"变成"**抢节奏**"。我们的待确认项可以直接关闭。

### 1.2 连续未命中补偿（#203）

| | 内容 |
|---|---|
| **DD 原值** | 每个技能在全部修正结算后还有**隐藏 +5 ACC**（→ **显示命中率 ≥95% 即必中**，且**任何技能至少 5% 命中**）；**第一次之后每连续一次未命中，额外 +4 ACC**（隐藏） |
| **我们的现状** | 命中 clamp **[55,100]**，**无补偿** |
| **对齐规格** | ① 每单位维护**连续未命中计数**（命中即清零）；<br>② **命中补偿 = max(0, 连续未命中 − 1) × 4**（第一次不补，第二次 +4，第三次 +8…）；<br>③ **仅作用于命中判定，不改变面板显示值**（DD 是隐藏的——玩家不该能算它）；<br>④ 结果仍 clamp 到 100 |

> ✅ **为什么值**：`review.md` 的 TOP 失败点之一是**"老虎机感"**；连续 miss 是最容易激怒玩家的随机事件。
> **成本极低（一个计数器），收益极高（手感）**，且**隐藏**所以不破坏"精密操作"。

### 1.3 Mark（标记）机制落地（#204）

| | 内容 |
|---|---|
| **DD 原值** | Mark **本身不提供任何数值**；由**特定技能**对带 Mark 目标追加伤害：Sniper Shot **+50~100%**、Collect Bounty **+90%**、Hound's Rush **+60~100%**、Thrown Dagger **+25~40%**、Pistol Shot **+25~50%**；部分同时加暴击（**+9~13%**）。<br>**敌方 AI**：被 Mark 的英雄挨打概率 **67~75%（Apprentice）/ 75~80%（Veteran）/ 80~87%（Champion）**；**Mark 本身不可被抵抗**（但施加技能可能 miss） |
| **我们的现状** | 🔴 `buff.md` §标记 **已裁决"加伤 + 改 AI"（用户拍板"两者都要"）**，但 **`buff_defs.json` 里根本没有这个 buff、也没有技能施加** |
| **对齐规格** | ① `buff_defs` 新增 **`mark`**：`polarity: negative`、`duration: 3 回合`、`stack: refresh`、`dispellable: true`、**无数值**（纯标记）；<br>② **加伤**：技能数据可声明 `bonus_vs_marked_percent: N`（**起手 +25%**，乘法阶段）；<br>③ **改 AI**：敌方 AI 候选池内若含**带 mark 的我方单位** → 按 **#187 的权重制**提高其权重（起手 ×2）；<br>④ **不可被抵抗**（施加技能本身仍可 miss）；<br>⑤ **起手落地上游**：**政委【督战】追加 `mark` 效果**；**起手受益技能 2 个**：**军医【致命注射】、政委【处决令】**（两条 `missing_hp` 收割技能）声明 `bonus_vs_marked_percent: 25` |

> 📌 **术语澄清（防止再次误传）**：**"失血收割"不是某一个技能**，而是 **#173/#195 记录里对两条 `missing_hp` 收割技能的通称**：
> **军医【致命注射】（×0.6）+ 政委【处决令】（×0.7）**。
> 本文件与 `feat_pack_03` 初稿曾误写为"**战士【失血收割】**"（**该技能不存在**）——若在 `data_schema` / `m3_skills_units` 里看到这个错名，那是**本错误的下游扩散**，需一并更正。

> 🔴 **与「嘲讽」的职责必须划清**（否则两个机制打架）：
> - **嘲讽 taunt**＝我方的**防守**手段：敌人**被迫**打我（坦克吸收）
> - **标记 mark**＝我方的**进攻**手段：**我方引导集火**点名（输出放大）
> - 敌方给我方上 mark → 是**威胁点名**（我该优先解掉/移动被点名者）

### 1.4 DoT 三条硬规则 + 补施加者（#205）

| | 内容 |
|---|---|
| **DD 原值** | ① **DoT 完全无视 PROT**；② **暴击施加的 Bleed/Blight 时长 +2 回合**；③ **DoT 在目标回合开始时结算**；④ DoT 致死**不留尸体**；⑤ DoT 每回合伤害**本身不能暴击** |
| **我们的现状** | 流血 = 固定 **3 点 × 2 回合**；**没有任何技能施加流血**（已登记缺口）；暴击不延长；结算时机未明确 |
| **对齐规格** | ① **流血伤害不受物防减免**（我们本来就是固定值 3，需在文档里**明确写死**这一点）；<br>② **暴击施加的流血：时长 2 → 4 回合**；<br>③ **流血在「目标回合开始」结算**（不是回合结束）——这决定"能否在被 DoT 打死前先行动"；<br>④ **流血的每回合伤害不可暴击**；<br>⑤ **补施加上游**：**战士【突刺】追加流血 3×2**、**军医【致命注射】追加流血 3×2**（起手值）<br>⑥ **与 DD 不同**：我们流血致死走**死门链**（敌人无死门→直接死），**保留我们的系统** |

### 1.5 死门 Recovery 减益（#206）

| | 内容 |
|---|---|
| **DD 原值** | 死门中：**−10 ACC / −25% DMG / −5 SPD / 承受压力 +33%**；<br>**被治疗脱离后** → **Death's Door Recovery**：**−2 ACC / −5% DMG / −1 SPD / 承受压力 +10%**，**持续到任务结束**，**多次进出死门不叠加** |
| **我们的现状** | 死门是**一次性判定**（存活/死亡）；脱离后**无任何惩罚**（归队 HP = 10%） |
| **对齐规格** | ① 新增状态 **「死门后遗症」**：**死门存活并归队后**获得；<br>② 效果（按我们的量级折算）：**受到伤害 +10%** · **命中率 −5** · **速度 −1**；<br>③ **持续到本次战斗结束**（切片无跨战斗；DD 是"到任务结束"）；<br>④ **不叠加**——多次进出死门只保留一层（防死亡螺旋）；<br>⑤ UI：必须显著标注（`ui_spec.md` §5） |

> ✅ **为什么值**：DD 的这条让死门**有记忆**——"活下来但付出了代价"。
> 否则死门退化成"只是一条血线"，与我们的硬核定位不匹配。

### 1.6 条件解锁技能（#207）

| | 内容 |
|---|---|
| **DD 原值** | 技能可带**前置条件**：Flagellant *Redeem* **需自身 HP < 40%**；另有形态限制（Abomination 仅人形态）、站位限制 |
| **我们的现状** | 🔴 **完全没有**这类设计（只有站位 + CD + 每场次数） |
| **对齐规格** | ① 技能数据新增可选 `requires`：`self_hp_below_percent: N` / `target_hp_below_percent: N` / `self_weak: true` / `self_deaths_door: true`；<br>② 不满足 → **灰显**，原因字串进 tooltip（沿用 `ui_spec` §4 既有机制）；<br>③ **起手落地 2 个**（不新增技能）：<br>　· 战士【殊死一搏】→ `self_hp_below_percent: 50`（"殊死"主题完美契合）<br>　· 军医【致命注射】/ 政委【处决令】→ `target_hp_below_percent: 50`（处决类技能的点名逻辑） |

> ✅ **为什么值**：它给**濒死状态一个正反馈**——血少反而解锁强力选项。
> 这直接服务"硬核受苦"定位，且**成本极低**（一个字段 + 灰显判断）。

### 1.7 AOE 暴击的团队结算 —— 先查是不是 bug（#208 前置）

| | 内容 |
|---|---|
| **DD 原值** | 一次 AoE 打出多个暴击时，**士气（stress）治疗与暴击 buff 只结算一次**；打尸体不触发（除非 AoE 同时命中至少一个活体） |
| **我们的现状** | `morale_events.critical_strike_dealt`＝**全队 +5**、`scope: team`；**#166 只裁定了"AOE 精神 + 暴击 → 仍 −5/目标（折扣优先）"，没有裁定"全队 +5 是否按目标数重复结算"** |
| **要做的事** | 🔴 **先核对**：若 AOE 暴击按**每个命中目标**各结算一次 `critical_strike_dealt`，则一次横扫暴击会给全队 **+5×N** —— **这是隐性 bug**。核对后按 DD 规则**明确为"只结算一次"** |

## 2. 暴击情绪链完整照抄（#209）—— **修正 #157**

| 环节 | DD 原值 | 我们的现状 | 对齐规格 |
|---|---|---|---|
| **被暴击** | 自身 **+10 stress**；**队友各 50% 概率 +5** | ❌ 无（#157 定"物理不掉士气"） | **自身 −10 士气**；**队友各 50% −5** |
| **打出暴击** | 自身 −3；队友各 25% −3 | ✅ 已有：**全队 +5** | **维持现状** |
| **暴击治疗** | **治疗量翻倍** + 被治疗者 **−4 stress**；概率**固定不受修正**：**单体 12% / 多目标 5%** | ❌ 无"暴击治疗"概念（我们治疗不吃倍率） | **治疗量 ×2** + 目标 **+4 士气**；概率 **单体 12% / 多目标 5%**（固定，不受任何修正影响） |
| **AOE 暴击** | stress 治疗与 buff **只结算一次** | ⚠️ 待核对（#208） | **只结算一次** |

### 🔴 对 #157 的修正（必读）

> **#157 原文**：「物理伤害不掉士气，**只有精神**掉」——目的是让"物理 vs 精神"**一眼可分**
> （`ui_spec.md` §6 明确依赖它：玩家靠这个区分判断"这一下掉不掉士气"）。
>
> **本决策的处理**：**物理伤害仍不掉士气**，新增**一个有名字的例外**——
> **「被暴击」= 震慑**：它掉士气，但**它不是"物理伤害掉士气"，而是"暴击的情绪冲击"**。
>
> **必须同步的可读性补偿（否则 §6 的设计前提被破坏）**：
> - 「被暴击」的士气变化用**独立视觉标识**（建议**橙色 +「震慑」字样**），与
>   **精神伤害的紫色**明确区分；
> - 玩家要能一眼读出三种情况：**普通物理打中（不掉士气）** / **精神伤害（掉，紫）** / **被暴击（掉，橙·震慑）**。
> - `ui_spec.md` §6 的"物理 vs 精神必须可分"**升级为"三态可分"**。

> ✅ **DD 的数值比例可参照**：被暴击的**痛感 3.3 倍于**打出暴击的快感（自身 +10 vs −3）。
> 我们采用**照抄绝对数值**（自身 −10 / 队友 50% −5）：我们的士气条是 0~100（DD 0~200），
> 但我们的**单次士气数值本来就比 DD 大**（如"击杀敌人"我们给全队 +10，DD 只给击杀者 50% 概率 −3 stress），
> 所以照抄绝对数值与我们的既有量级一致。

## 3. M7 方向：压力长线化（#210，仅登记方向）

| | DD 做法（确切数值） |
|---|---|
| **战斗伤害会治，压力不会** | "Unlike combat damage, stress is not fully healed when finishing a mission." |
| **回城封顶** | 回 Hamlet 时压力**上限压到 100**（低于 100 的部分原样保留） |
| **清除靠花钱 + 占时间** | Tavern / Abbey：基础减压 **45 / 55 / 65**（三档场所），**每次访问 37.5% 概率触发正负副作用**；空闲一周仅 **−5**（建 Puppet Theater 后 −15） |
| **Affliction 跨任务保留** | 任务结束（无论成败）Afflicted 仍是 Afflicted；必须治疗清除 |
| **撤退/放弃本身加压** | 战斗内撤退成功 **每名英雄 +25**（受各种修正放大）；放弃远征 **+20 且不受任何修正、且不触发 resolve 判定** |
| **心衰** | 压力到 **200** → 强制进死门；**已在死门则直接死亡**（无视死亡抗性）；Virtuous 则改为移除美德、压力归 0 |

**为什么这对我们重要**（结构性）：
> 我们把士气做成**单场**资源 → **战斗必须够长**（8~12 回合）KPI 才触发得了。
> DD 因为压力是**长线**资源，单场战斗可以只打 **3~6 回合**。
> **这不是错，而是一个有代价的选择**——M7 若把士气长线化，战斗节奏与 KPI 定义都要跟着重定。

**M7 需一并定义的**：① 战后压力如何保留（DD 是封顶 100）；② 清除渠道（花钱/占时间）；③ KPI「士气触底/美德/折磨」是否改为**跨战斗统计**；④ 与"单场 8~12 回合"目标的关系。

## 4. 刻意不同（DD 有，我们**不抄**，及理由）

| # | DD 机制 | 我们不抄的理由 |
|---|---|---|
| **4.1** | **尸体（Corpse）**：死亡留尸体**占位挡路**，必须花技能清（暴击致死/DoT 致死不留尸体） | 我们靠**「向中靠齐」**（`formation.md` §3）——阵型永远整齐、**UI 可读性更好**，且与"阵型长度恒定"的核心承诺一致。<br>⚠️ **但登记一个问题**：我们失去了"死亡的位置代价"——靠齐其实是在**帮玩家**补位。是否需要一个等价物，待议 |
| **4.2** | **光照计（Light Meter）**：越暗 → 怪物 ACC +12.5 / DMG +25~30% / 暴击 +5~6%、压力倍率 ×1.4~1.5，**但战利品额外掉率最高 95%** | **这是 DD 最精妙的一层（玩家自选难度换收益）**——但属于**远征层**，切片无元层。<br>📌 **登记为 M7 首选候选之一**（见 #210 的取舍） |
| **4.3** | **DD 的绝对数值尺度**：英雄 HP 17~63、杂兵 HP **6~15**、武器伤害 3-26 → **一击杀杂兵**、战斗 3~6 回合 | 照抄会让战斗缩到 3~6 回合 → 我们的**单场**士气 KPI 七项**来不及触发**（#197 已算过）。<br>✅ 只抄「**伤害/血量比**」的**方向**（把击杀击数从 5~6 压到 2~3），不抄绝对值 |
| **4.4** | **技能无冷却**，靠"每场次数"（Protect Me 3 次 / Solo 2 次 / Withstand 1 次）+ 持续 buff 3 回合 | 我们主用 **CD**。两者手感不同（CD＝轮转表；每场次数＝省着用）。**不是错**，但注意我们"每场 N 次"用得少——**可以多给几个强力技能配 `per_battle` 而不是 CD** |

## 5.5 潜行 Stealth（C-1，2026-09-18 补录）

### 5.5.1 四条核心规则（逐条附原文实据）

| # | 规则 | 权威原文 / 实据 | 我们的落点 |
|---|---|---|---|
| ① | 潜行者**不可被直接指定**（单体技能打不到） | wiki：*"prevents the affected character from being targeted directly"*；补丁：*"Stealthed monsters cannot be targeted by direct attacks unless that attack has the Bypass Stealth quality"* | `SkillTargetResolver.Resolve` 候选池剔除（带 `IBuffLedger` 时） |

## 5.6 地牢层：回头代价 + 重访刷新（D-1 / D-2，2026-09-20 补录）

> **为什么记在这里**：D-1/D-2 的**口径来源是 DD wiki**（探索压力轴），不是我们的发明；
> 但 DD 的光照刻度与我们的 `light.tiers` 不同 ⇒ 必须**换算**，这一条极易搞错（我们已踩过，见下）。

### 5.6.1 两条规则

| 规则 | DD 原文口径 | 我们的落地 |
|---|---|---|
| **D-1 回头代价** | 重走已探索的格**仍要付**光照/时间代价，只是比走新格便宜 | `DungeonWalker._visited`（**亲自站过** ≠ `_revealed` 见过）⇒ `TryStep(out wasRevisit)`；回头**额外**扣 `dungeon_layer.revisit_light_cost`（走廊格只补差额 `max(0, revisit − perTile)`，避免与段守恒重复计费） |
| **D-2 重访刷新威胁** | 反复走同一格会刷新威胁，**越黑越频繁**（wiki：光照 ≤50 ⇒ +2.5%；=0 ⇒ +5%） | `tuning.dungeon_layer.revisit.tiers`（**按暗 → 亮**，取首个命中档）；触发后**再掷一次**选 `battle` / `trap`；两次抽取**都写 `RngDraw`** |

### 5.6.2 🔴 刻度换算（**我们踩过的坑，务必先看这里**）

DD wiki 的 "+2.5% @ ≤50 / +5% @ 0" 用的是 **DD 自己的裸光照刻度**；
本项目的刻度是 `light.tiers`：`radiant 76-100 / dim 51-75 / shadowy 26-50 / dark 1-25 / black 0`（`enter_value` = 100）。

⇒ **直接照抄 `max_light: 50 / 0` 是错的**：光照 51..100 一档都不命中 ⇒ **完全不掷骰**（`RevisitSpawner` 在不命中任何档时提前返回）
⇒ **"亮着走一趟永远平安"**，D-2 在最常见情形下**静默失效**。这是我第一版真实数据里的实际缺陷。

**已加的两道门禁**（`TuningConfig.Validate`）：
1. `tiers` 必须**按暗 → 亮**（`max_light` 严格递增）—— `RevisitSpawner` **不排序**，乱序会静默错；
2. **末档必须 ≥ 满光照**（`light.enter_value`）—— 否则拒载（报错文案直接写明"静默失效"，见 `RevisitTiers_MustCoverFullLight_ElseRejected`）。

现取值（**全 `placeholder: true`，待 M8 内容层定实**）：`0 ⇒ 5%` / `25 ⇒ 4%` / `50 ⇒ 2.5%` / `100 ⇒ 0.5%`。

### 5.6.3 两层并存（**不是矛盾**）

| 层 | 文件 / 类 | "回头"口径 |
|---|---|---|
| **按段移动**（旧，M7.6 片②） | `expedition_map.json` 的 `move.revisit_cost` / `MapTraversal.Step` | "回头**更便宜**"（原样保留，自洽） |
| **瓷砖网格**（新，D-1 落点） | `DungeonWalker` / `ExpeditionFlow.TryStepTile` | 回头**必付**代价（DD 口径） |

|---|---|
| 眩晕递增 | 连续眩晕同一目标 → 实际概率逐次下降（+50% 递增），**出现一次未被晕的行动后清零** |
