# UI 信息清单与规格（模块）

> **为什么这份文档存在**：本作的 UI 不是皮，是**核心机制的一部分**。
> 位置驱动 + 10 层随机的设计下，玩家**能不能看见**直接决定他能不能做决策——
> 看不见行动序列 = 无法规划；看不见撤退成功率 = 又一次掷骰；技能灰显不准 = 位置系统白做。
>
> 主文档：`GDD.md` §1.1 / §2.5 / §3.6；关联 `formation.md` §6、`combat_math.md`。
> 决策：#160。所有规格为**切片最小集**，不做视觉美术，只定**信息**与**交互**。

> ② 旧设计里**独立的浮层**（详情框 #200、DevLog #199）**改为多功能框的分页** —— **少两套 UI 组件**，且与 DD 一致。

### 1.0 镜头规则 ✅（#223）

> **背景**：场景比视口宽——**支援位 5/6 在战斗位 4 之后的左侧，默认不在镜头内**。
> 因此镜头必须**跟着"当前需要你操作的东西"走**。

| # | 情形 | 镜头行为 |
|---|---|---|
| ① | **默认视野** | 框住 **战斗位 1~4 + 敌 1~4**；**支援位 5/6 在镜头左侧之外** |
| ② | 轮到我方**战斗位**行动 | **镜头不动**（已在视野内） |
| ③ | 轮到我方**支援位（5/6）**行动 | 🔴 **镜头左移到 5/6** —— 让玩家看清"是谁在行动" |
| ④ | 玩家**开始选择目标** | 🔴 **镜头移回目标区**（敌方 / 友方） |
| ⑤ | 支援位**被攻击 / 被治疗 / 被调动** | **镜头短暂移过去**（**不能"屏幕外掉血"**，§7 已有此条） |
| ⑥ | **增援两步**（#181） | 选 B（5/6）→ 套 **③**；选 X（1~4）→ 套 **④** —— **同一套规则，不另立** |
| ⑦ | 移动方式 | **平滑缓动，禁止瞬移**（与位移"逐格滑动"同一标准，§6） |

> 🔴 **核心是 ③④ 这一对**：`轮到支援位 → 镜头过去` / `开始选目标 → 镜头回来`。
> ⚠️ **位置色块（§1.3）不受镜头影响** —— 它是 HUD，**永远显示全部 6 个我方位**，即使 5/6 在镜头外。

### 1.1 C 区 · 当前轮次角色面板（DD 式）

| 项 | 内容 | 来源 |
|---|---|---|
| 头像 | 原型图 + **HP 条包框**（DD 式：血条嵌在头像框上下沿） | 表现层 |
| 身份 | 名字 · **原型名** | `units.json` |
| **技能横排** | 当前轮次角色的**携带技能（5 个）**；**当前选中项加边框**；**右侧「×」取消选择**（对应 #189 的"可取消重选"） | 装填集 + `SkillProjection` |
| HP | 数字 + 条（`28/40`）；**虚弱时锁 1 要可见**（`ui_spec` §5） | 投影 |
| 士气 | 数字 + 条（`62/100`）+ **≥85 金色 / ≤15 红色**预警 | 投影 |
| **属性块** | **我们的 12 项**：攻 · 物防 · 速 · 闪避 · 暴击% · 韧性 · 眩晕抗 · 流血抗 · 减益抗 · 位移抗 · **死门抗** | `units.json` |
| 状态 | 状态角标（虚弱 / 死门 / 折磨 / 美德 / 护盾×N / 守护） | `IBuffLedger` |

> ⚠️ **DD 的属性块是 6 项（ACC/CRIT/DMG/DODGE/PROT/SPD），我们是 12 项**——因为我们的抗性体系更细。
> **建议：6 项核心（攻/物防/速/闪避/暴击/韧性）常显，5 项抗性**折叠为一行小字**（避免面板过高）。

### 1.2 E 区 · 多功能框（DD 式分页）

| 页 | 内容 | 默认 |
|---|---|---|
| 详情 | **当前悬停 / 锁定的对象**完整详情——单位（含**敌方全暴露**，`ui_spec` §8.3）/ 技能 / buff | ⬜ |
| **日志** | **DevLog**（`logging.md` §6）：分级过滤 / 关键词 / 导出 | ✅ **默认页**（#222 用户定：开发期默认看日志） |
| 序列 | 行动序列（本回合 + **下回合预览**） | ⬜ |
| 编成 | 增援 / 换位的槽位视图（#181 两步：选支援位 → 选目标位） | ⬜ |

**交互**：
- **切换**：点击分页标签，或快捷键（建议 `Tab` 循环 / `1~4` 直选）。
- **锁定**：在战场**点击**一个单位 → 锁定到「详情」页（松开锁定后恢复跟随悬停）。
  > 这样"比对两个单位"不需要两个浮层——**锁一个、悬停另一个**，与 DD 一致。
- **切换分页不改变**当前选择 / 悬停状态。
- 🔴 **默认页为「日志」，但悬停/锁定时【不自动切页】** —— 尊重玩家的页选择。
  「详情」页标签上加一个**未读小点**，提示"当前有可看的详情"，玩家自己切。

### 1.4 🔴 DD 风格要素（v0.92 新增，`#251`）—— **可执行清单**

> **用户要求**："**模仿 DD 的 UI 进行现有 UI 的美化**"

#### 🔴 红线：能学"视觉语言"，不能抄"美术资源"

| | 能学 ✅ | 不能抄 ❌ |
|---|---|---|
| **内容** | **视觉语言**（描边 / 对比 / 色板关系 / 信息层级）· **信息组织方式**（条嵌头像框 / 角标状态 / 图标横排带选中框） | **DD 的美术资源**（图标 / 纹理 / 字体 / 立绘）—— **版权** |
| **理由** | DD 的 UI 好看，**主要来自"信息层级 + 对比度"这套工程做法**，而不是某个图标画得好 | 那套做法**可以直接学，且不需要美术资源** |

#### 第一步（**现在可做**，零美术资源，主程序即可完成）

| # | 要素 | 说明 |
|---|---|---|
| **1** | **文字 / 数字加【深色粗描边】** | DD 最关键的一条 —— 暗背景下**所有文字都有描边**，这是它"乱而可读"的根本 |
| **2** | **字号层级** | `HP 数字` > `技能名` > `属性小字`；**同一屏内不超过 3 级** |
| **3** | 🔴 **HP / 士气条【嵌进头像框的上下沿】** | DD 的标志性做法（不是独立的两根长条）—— 省空间，且"人和他的状态"绑定在一起 |
| **4** | **选中态** | 技能选中 → **亮边框**；目标选中 → 高亮；**取消用「×」**（#221 已定） |
| **5** | **对比度** | 面板底色**压暗**、可交互项**提亮**；灰显项**降饱和**（不是降透明度——暗色下透明度会看不清） |
| **6** | **状态用角标不用文字** | 虚弱 / 死门 / 折磨 / 美德 / 护盾×N → **图标角标**（文字说明走详情页） |

#### 第二步（**需要美术产出**）

图标 / 纹理 / 字体 / 动效（缓动曲线、伤害数字漂浮、镜头推移）。

> ⚠️ **与 M7.5 的依赖**：**光照计条（火把条）**属 DD 顶部那条 —— 它在 **M7.5 做光照计时**才需要。

### 1.5 🔴 用词固定：「一场」= 「一趟（远征 / run）」（v0.92）

> **用户用词**："一场游戏可能有**多场战斗**" / "HP **一场**结束后能恢复"
> ⇒ 用户的"**一场**" = 文档里的「**一趟（远征 / run）**」✅

| 词 | 定义 |
|---|---|
| **趟（run）** | 一趟远征 = **N=6 场战斗** |
| **场** | 单场战斗 |
| **HP** | **一趟结束（回城）后完全恢复** ✅ |
| **士气** | **一趟结束后完全不恢复** ✅（#245） |

> ⚠️ **若"每场战斗后 HP 也恢复"被采纳 ⇒ 会摧毁 M7 核心机制**（#227「HP 跨战斗保留」）——
> 故本条**显式写死**，有歧义时以本条为准。

### 1.6 🔴 技能快览 tooltip（**位置色块**）✅（#222 —— 这正是 #182 缺的那块）

> **背景**：#182 已定「技能按钮上**不内联**使用要求文字，位置要求改由**悬浮**承载」——
> 本节就是那个悬浮的规格：**用颜色直接把"我能站哪、我能打哪"画出来**，比文字快得多。

**内容只有三部分**（快扫用；完整数值走 E 区「详情」页）：

```
① 技能名
② 摘要（一行）：距离轴 · 伤害轴 · 倍率 · 限制    例：近战·物理 1.0 · CD 2
③ 位置色块（见下）
```

**位置色块配色**（🔴 **方格顺序 = 屏幕左右顺序**，支援位在最左）：

```
我 6 5 │ 4 3 2 1 │ 敌 1 2 3 4
  ⬜🟡 │ 🟡⬜⬜⬜ │ ⬜🔴🔴⬜
  └支援┘ └─ 战斗位（前→后）─┘
```

> ⚠️ **不是 1→6**：方格必须与画面上单位的左右位置一一对应（支援位在战斗位 4 之左）。
> `6 5 │ 4 3 2 1` 之间的**分隔线**标出**支援位 / 战斗位的分界**，玩家一眼能看出"这是支援位技能还是战斗位技能"。
> ✅ **色块不受镜头影响**（§1.0）：即使 5/6 在镜头外，色块仍**显示全部 6 个我方位**。

| 颜色 | 含义 | 数据来源 |
|---|---|---|
| 🟡 **黄色** | 技能要求的**自身站位**（"我要站这里"） | `self_slots` |
| 🔴 **红色** | **目标范围内的敌方位置**（攻击技能） | `target.side = enemy` 的 `slots` |
| 🔵 **蓝色** | **目标范围内的友方位置**（支援/治疗技能） | `target.side = player` / `any_ally` / `team` |
| ⚪ **灰色** | **范围外**（不可选、不可站） | 其余 |

**判定优先级**：某位置同时满足多条时 → **黄 > 红/蓝 > 灰**（自身站位优先显示，它最影响"能不能用"）。

**边界补充**：

| 情形 | 显示 |
|---|---|
| **AOE 技能** | 目标位置用**红色加粗边框**，并在摘要里标 **AOE**（与"池内选一"区分） |
| `team` / `any_ally` | 全部友方位 **🔵 蓝**（`any_ally` 与 `team` 的差别看摘要：`team` 标"全队"） |
| `self` / 自我位移 | 自身位 🟡；`move_range` 另在摘要标"移动" |
| 池外「移动」 | 自身位 🟡 + **±N 格**用 🔴（它是"可交换的目标位置"） |
| 造成伤害 vs 无伤害 | 摘要里轴写清（`物理`/`精神`/`无`）——**精神轴要变色**（`ui_spec` §6） |

> ✅ **为什么用颜色而不是文字**：`review.md` 风险 #7——"UI 不把关键信息画清楚，**精密操作会退化成查表**"。
> 位置驱动的游戏里，**"我能站哪、我能打哪"是每回合都要判断的东西**，必须一眼可读、不能用文字描述。

## 2. 必显示信息清单（🔴 硬性要求，缺一项体验即崩）

| # | 信息 | 为什么必须 | 出处 |
|---|---|---|---|
| 1 | **行动序列**（本回合 + 下回合预览） | 速度带 0~10% 随机浮动，**看不见就无法规划** | GDD §2.5 |
| 2 | **撤退成功率的具体数字** | 看不到数字，撤退就只是掷骰；看到"68%"玩家才会想"先杀掉最快的敌人再撤" | GDD §3.6 |
| 3 | **技能灰显 + 原因** | 位置系统的全部张力都在这；灰了要说明"站位不符"还是"范围内无人" | formation §6 / GDD §1.2 |
| 4 | **命中率** | 玩家要能围绕概率做取舍 | combat_math §1 |
| 5 | **目标范围高亮** | 悬停技能时，高亮所有会被命中的位置 | GDD §1.2 |
| 6 | **位移预览**（谁会被推到哪） | 位移是核心机制，**必须能在按下前看到结果** | GDD §1.3 |
| 7 | **士气条**（0~100 + 数值） | 士气是核心资源，玩家要能读出"还差多少到 100 / 还有多少到 0" | morale |
| 8 | **HP / 护盾次数 / buff 图标** | 护盾按次数（#156），要能看出还剩几次 | 本文档 §5 |
| 9 | **位置编号** | 所有技能都绑位置编号，编号不可见 = 技能描述读不懂 | GDD §1.1 |
| **10** | 🔴 **剩余支援点（SP）** | #211 起支援位技能与增援都要消耗它。**看不见点数 = 玩家无法规划"这回合让哪个支援位动、攒还是花"** → 必须常驻显示（含**本回合恢复预览**） | GDD §1.4.2 |
| **11** | 🔴 **光照条（火把条）** | **M7.5 光照计**（`#258`）—— 🔴 **必须同时显示【当前值 + 档位 + 该档位给了敌人什么】**（如"Dark：敌 DMG +15% / 敌暴击 +3% / 掉落 +75%"）。<br>⚠️ **只显示一根条是不够的**：光照计的精髓是"**自选难度换收益**"⇒ **玩家必须能看见"变暗会换来什么、会付出什么"**，否则它不是决策（**同 `#240` 否决"事件可跳过"、`expedition.md` §5.5 ④ 的原则**） | m7_5 任务卡 §D0 · `#259` |
| **12** | **背包格子** | **M7.5 背包**（`#248`）—— 格数 **12**；每格显示物品与数量；**已用/总数常驻**。<br>🔴 **超格时必须明确提示"背包已满"**（否则"强制取舍"这条设计就失效 —— 玩家不知道自己在取舍） | `#248` · m7_5 任务卡 §D2 |
| **13** | 🔴 **侦察结果标记** | **M7.5 侦察**（`#258`）—— 侦察成功后，**下一个节点的类型必须可见**。<br>🔴 **且"已侦察"与"未知"必须有明确区分**（不是"显示一个默认图标"）—— 否则玩家分不清"我看清了"和"我没看清" | m7_5 任务卡 §D1 |

> ⚠️ **第 6 条最容易漏**：位移走"逐级交换链"，中间单位会各退一格。
> 若只显示"目标被推 1 格"，玩家无法预判连锁结果——**必须把整条交换链的结果都画出来**。

## 3. 信息层级（同时显示时谁压过谁）

```
1 级（永远可见）：  位置编号 · 单位存活状态 · HP · 士气
2 级（常驻小图标）：buff / debuff · 护盾剩余次数 · 虚弱标记
3 级（悬停/选中）：精确数值 · 命中率 · 伤害预估 · 目标范围 · 位移预览
4 级（结算时）：   飘字（伤害 / 士气 / 死门判定结果）
```

- **2 级图标数量上限 4 个**，超出折叠为「+N」，点开看全部（对应 `buff.md` §8.1）。
- 优先级：死门 / 虚弱 > 折磨 > 美德 > 眩晕 / 捆缚 > 流血 > 属性增减益 > 护盾。

## 4. 操作流

```
① 轮到我方单位 → 该单位高亮 + 镜头轻微推近
② 玩家点技能
      · 可用   → 进入 ③
      · 灰显   → 不可点（**按钮只显示技能名，不内联显示"使用要求/不可用原因"**，#182）
③ 显示目标范围高亮 + 位移预览 + 命中率
③b 【仅单体技能】范围内可点选具体目标（#178）：
      · 🔴 **候选目标必须高亮**（范围内非空位逐个高亮，供玩家点选）——这是必需项，不可省
      · 范围内多个非空 → 玩家点选其一，选中项高亮 + 显示该目标的命中率/伤害预估/位移预览
      · 范围内仅一个非空 → 自动选中，可直接确认
      · AOE 技能（横扫/精神震荡）跳过本步：整个范围一起结算，不选单个目标
④ 玩家确认 → 结算
⑤ 结算反馈：伤害飘字 → 位移动画 → 士气飘字 → 状态变化（虚弱 / 死门 / 死亡）
⑥ 若触发死门判定 → **必须给一次明确的判定演出**（这是全作最紧张的一刻，不能悄悄结算）
```

- 🔴 **③b 是「精密操作」爽点的落点**（#178）：范围是**可选池**，单体技能必须让玩家能选中"打哪一个"。
  没有这一步，玩家就失去了"在敌 1、敌 2 之间选择"的战术决策，位置系统也退化成自动结算。
- 🔴 **"不显示使用要求" ≠ "不显示高亮"（#182 澄清）**：
  - **移除**的是②里技能按钮上的**使用要求文字**（"站位不符"这类规则说明书）；
  - **保留且必需**的是③b的**候选目标高亮**（选对象时哪些能打必须看得见）。
  - 🕓 **后续增强**：悬浮技能时高亮"该技能可用位置 + 攻击范围"——这是**技能自身站位/范围可视化**，与③b的选对象高亮是两件事，切片可先不做。
- **可撤销**：③/③b 阶段可取消重选（不消耗行动）。④ 之后不可撤销。
- **撤退**是常驻按钮，点开显示成功率 + 成功/失败的士气代价（-10 / -5），需二次确认。
- **增援**（§1.4.1 / #181）由战斗位角色发起，入口是技能栏旁的**一个**「增援」按钮：
  点按 → ① 高亮支援位 5/6 并选一个 → ② 高亮战斗位 1~4 并选一个 → 结算（两步间可取消）。

## 5. 状态显示规格

| 状态 | 显示方式 |
|---|---|
| **士气** | 横向条 + 数字。**接近 100 或 0 时变色预警**（≥85 金色 / ≤15 红色） |
| **虚弱** | 单位半透明 + 灰化 + 「虚弱」角标；HP 显示为 `1` 并加删除线示意"锁 1" |
| **护盾** | 单位外圈盾形图标 + **剩余次数数字**（#156，不是吸收量） |
| **守护** | 保护者与被守护者之间画一条连线（位置系统可视化，也让"推开就断开"看得见） |
| **嘲讽** | 敌人头顶「嘲讽」标记 + 指向坦克的箭头 |
| **折磨 / 美德** | 不同底色的角标；**美德要有明显正反馈**（光效/音效） |
| **失控** | ⚠️ **必须显著标注**（morale.md §5.1 缓解建议 2）：否则玩家不知道他会乱打队友 |
| **死门判定** | 结算时弹出**大字判定结果**（"死门 62% → 扛住了"），不能只飘个小数字 |

## 6. 结算反馈要求

| 事件 | 反馈 |
|---|---|
| 造成伤害 | 伤害飘字（**暴击用更大字号 + 不同颜色**）；暴击时全队士气 +5 要有可见提示 |
| **精神伤害** | **用区别于物理的颜色**（如紫/蓝）。🔴 **#209 起改为「三态可分」**，见下方警告 |
| **被暴击（震慑）** | 🔴 **独立标识**（**橙色 +「震慑」字样**）——#209 起"被暴击"会掉士气，必须与普通物理命中区分 |
| 士气变动 | 单位头顶飘 `+5` / `-8`，**上浮绿色 / 下沉红色** |
| 位移 | 沿交换链**逐格滑动**动画，不能瞬移（要能看清谁被挤到哪） |
| 死亡 | 倒地演出 + 立即触发**向中靠齐**并播放补位动画（formation §6） |
| 士气满 100 | 明显的"士气高涨"演出（美德获取是重要正反馈） |
| 士气归 0 | 崩溃判定演出 + 折磨名称，**让玩家知道发生了什么** |

> 🔴 **#209 起：从「两态可分」升级为「三态可分」**：
>
> | 情况 | 掉不掉士气 | 视觉 |
> |---|---|---|
> | **普通物理命中** | **不掉** | 常规伤害飘字 |
> | **精神伤害** | 掉 | **紫色** |
> | **被暴击（震慑）** | **掉** | **橙色 +「震慑」** |
>
> 玩家必须能一眼读出**这三种情况**——否则士气系统对玩家就是不可读的。
> **背景**：#157 原定"物理不掉士气"正是为了保证可读性；#209 加入了"被暴击"这个**有名字的例外**，
> 因此**这份视觉补偿是本决策的交付物之一，不可省**（`feat_pack_03` D7 已列为验收项）。

## 12. 🔴 表现层四项规格（`#315`）—— 动效 / 音效 / 描边材质 / i18n

> **触发**：架构的 **Godot 内置工具审计**（`godot_builtins_audit.md`）指出**四项不是纯实现、属设计口径**，
> 否则实现方只能自己编（= `#244`「规格缺口」的老路）⇒ 本节给出**口径**。

### 12.1 ④ 动效（`Tween` / `AnimationPlayer`）—— 🔴 **最小清单：只做 4 个**

```
🔴 原则：**动效只表达【发生了什么】，不表达"多严重"** ——
   严重程度由【数字 + 颜色】表达（那是静态视觉的事，§1.4 六条已定）
⇒ 因此动效要【短、克制、不抢信息】✅
```

| # | 时机 | 动效 | 时长 |
|---|---|---|---|
| **①** | **出现**（伤害数字 / 事件条目） | **短促上浮 + 淡出** | 0.3s |
| **②** | **受击**（单位） | **短促位移抖动 + 闪白** | 0.15s |
| **③** | 🔴 **士气崩溃**（进入折磨 / 死门） | **屏幕边缘暗角 + 该单位框变红** | 0.5s |
| **④** | **结算**（面板出现） | **淡入** | 0.2s |

🔴 **明确不做**（避免"好看但读不出信息"）：
**不做**常驻呼吸/待机动画 · **不做**转场过场 · **不做**技能特效（那属美术）
⇒ 📌 **并把话写死**：**动效不得延迟【玩家可操作的时间】**（**动画期间输入不得被吞**）✅

### 12.2 ⑤ 音效（`AudioStreamPlayer`）—— 最小 3 类 + 🔴 **无音源时的处理**

| # | 类 | 触发 |
|---|---|---|
| **①** | **命中**（**区分我方 / 敌方**） | 伤害结算 |
| **②** | **受击 · 死门** | 受击 / 进死门 / 阵亡 |
| **③** | **结算**（胜 / 败） | 战斗结束 |

🔴 **"没有音源时怎么办"—— 裁定：用【占位音】（程序生成的正弦/噪声短音）** ✅

```
🔴 理由：**"静音"会让"没做"和"做了但没声"无法区分**（
   而占位音让"接线是否通"当场可听）—— 与红线 21 同源：**不留不可分辨的状态** ✅
📌 且：**音源缺失时【必须能跑】**（不得因缺文件崩）
```

### 12.3 ⑦ 描边 / 暗角 / 闪白：🔴 **接受"用 `ShaderMaterial` 统一实现"**

```
✅ 裁定：**接受** —— 并把它写进本节作为 `ui_spec` 的【实现口径】✅
理由：① 目前是【20 处 `AddTheme*Override` 逐节点写】⇒ 改一处要改 20 处 ❌
     ② 而"深色粗描边"是**全局一致的视觉语言** ⇒ **材质正好** ✅
```

🔴 **而"视觉规范"仍属本节**（材质只是实现手段）：**描边宽度 / 颜色 / 暗角强度 / 闪白时长** ——
由 `ui_spec §1.4 六条` 定，**材质只是它们的一致实现** ✅

### 12.4 ⑩ i18n：🔴 **"M8.3 后做，但现在按【可 i18n】的方式写布局"**

```
🔴 关键：**i18n 反过来约束"锚点/容器/布局"** ——
   多语言文本长度不同 ⇒ **硬编码绝对坐标必错位** ❌
⇒ 所以"做不做 i18n"决定了【现在怎么写布局】：
   · 若"不做" ⇒ 可以用绝对坐标（省事）
   · 若"以后做" ⇒ 🔴 **现在就必须用【容器 + 锚点】**
```

✅ **裁定：M8.3 之后做 i18n，但现在【必须】用容器 + 锚点** ✅

> 📌 **一句话：i18n 的【文本】可以后补，但【布局方式】必须现在对** ✅
> ⇒ 这也让架构的 **(a) ② Theme+容器+锚点 / ③ 焦点+手柄** 与 i18n **一起排**（架构的建议顺序对）✅

### 12.5 附：`O-84`（表现层读数据）—— **确认架构的口径**

```
🔴 裁定：**表现层读数据一律 `FileAccess` / `ResourceLoader`；`System.IO` 只允许在【内核】** ✅
理由：**`BattleUi.ReadData()` 用 `System.IO` 磁盘路径 ⇒ 导出构建里 `data/*.json` 在 PCK 内
      ⇒ `File.Exists` 失败 ⇒ 抛异常 ⇒ 【单场战斗入口在发行版直接崩】** ⚠️
⇒ ✅ 这是 **`#307` 冻结之外的【正确性缺陷】** ⇒ **应立刻修**（架构的 (a) 顺序对）✅
```
