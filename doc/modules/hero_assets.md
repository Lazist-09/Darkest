## §1 这件事的定位（**先定性，再定方案**）

```
🔴 **用户要的不是"用它的美术"，而是【让我们的英雄资产接口长得像 DD mod 的形态】** ——
   这样**朋友以后加新的更容易**，而**最终他会做【我们自己的】原创** ✅
⇒ 📌 **所以"占位"是【一次性的验证载荷】**：
   **用它去证明"接口能装下一个真实英雄"** ⇒ **装得下 ⇒ 接口成立 ⇒ 以后填原创** ✅
   —— 而**不是"把它变成我们的资产"** ❌
```

🔴 **而这条定位【把版权风险降到最低】**：
```
✅ **可做**：**本地**放占位、**用它验证接口**、**用完即换** ✅
❌ **不可做**：**进 git**（= 分发）· **进构建产物**（`darkest/resources/**` 会被打包导出）· **发布** ❌
```

## §3 🔴 我们的接口（**对齐，但简化**）

### 3.1 核心裁定：**接口定义在【动作槽 → 帧序列】这一层，不绑定 Spine**

```
🔴 **为什么**：DD mod 用 **Spine（`.skel`/`.atlas`）**，而 **Godot 用 Spine 要第三方 runtime**
   （有授权与版本要求）⚠️ ⇒ **若接口绑定 Spine ⇒ 占位验证也做不了、原创也受限于该工具** ❌
⇒ ✅ **裁定**：**我们的接口只要求【"一个动作 = 一串帧 + 一个锚点"】** ——
   · **占位**：`.png` sprite sheet / 序列帧 + `AnimatedSprite2D` ✅
   · **将来**：朋友给 **Spine 或 PNG 或 3D 都行** ⇒ **接口不变** ✅
   ⇒ 📌 **那正是"接口"的价值：让【实现方式可换】而【调用方不用改】** ✅
```

### 3.2 🔴 建议的目录与数据形态

```
darkest/assets/heroes/<archetype>/          ← 🔴 按【我们的原型】分（warrior/tank/medic/commissar）
  ├ hero.json                              ← 🆕 **英雄资产清单**（数据，不是代码）
  ├ sprite/
  │   ├ idle.png         （或 idle_0.png … 序列帧）
  │   ├ combat.png       · walk.png · defend.png · attack.png
  │   ├ afflicted.png    · heroic.png
  │   └ camp.png · investigate.png
  └ portrait.png                            ← UI 头像（`ui_spec §15.1` 名册行要用）
```

🔴 **`hero.json`（🆕 数据契约草案 —— 架构定 schema；已落 `data_schema` **P31**）**：
```jsonc
{
  "archetype": "warrior",
  "pose_groups": ["A"],                    // 对标 DD 的 _A/_B（多套外观）
  "actions": {
    // 🔴 **每个"有帧的槽"都必须显式写 `anchor`**（或写 "inherit" 表示继承）——
    //    "省"可以，但要【写出来】（"我确实想过，它继承" ≠ "我忘了写"）
    "idle":      { "frames": ["sprite/idle.png"],      "fps": 8,  "loop": true,  "anchor": [0.5, 1.0] },
    "combat":    { "frames": ["sprite/combat.png"],    "fps": 8,  "loop": true,  "anchor": "inherit" },
    "walk":      { "frames": ["sprite/walk.png"],      "fps": 8,  "loop": true,  "anchor": "inherit" },
    "defend":    { "frames": ["sprite/defend.png"],    "fps": 8,  "loop": true,  "anchor": "inherit" },
    "attack":    { "frames": ["sprite/attack.png"],    "fps": 12, "loop": false, "anchor": [0.5, 0.95] },
    "afflicted": { "frames": ["sprite/afflicted.png"], "fps": 6,  "loop": true,  "anchor": "inherit" },
    "camp":      { "frames": ["sprite/camp.png"],      "fps": 4,  "loop": true,  "anchor": "inherit" }
  },
  "portrait": "portrait.png"
}
```

🔴🔴 **而"每槽显式 anchor"是【架构的裁定（`#345` 附），我采纳】**：
```
🔴 **规则（`P31` ④）**：**每个"有帧的槽"必须写 `anchor`，或显式写 `"anchor": "inherit"`** ✅
   理由（架构给的三条，我全部认可）：
     ① **锚点不一致会产生"肉眼才发现的错位/抖动"**（攻击帧要脚下对齐、受击帧常带位移）⚠️
     ② 🔴 **一"省"就得猜，而【猜错不在任何判据的红灯里】** ⇒ **不可解释的默认**（红线 21）⚠️
     ③ 而若改成"只要必需 5 槽" ⇒ **代码里要维护"哪些槽可省"的【特例表】⇒ 特例表会漂移**
        （**动作型 > 禁止型**，元准则 R1）✅
⇒ 📌 **而这条的由来值得记**：**是因为【本示例只在 `idle` 上写了 anchor】** ⇒
   **读者会照示例写 ⇒ 然后在加载期被门禁拒绝** ⇒ 🔴 **"文档教你写错的东西"** ⚠️
   —— **与 `#325` D6「两视图不手抄」同族：规格的示例 = 【事实上的第二份规范】** ✅
```

🔴 **纪律**：
```
① 🔴 **`frames` 必须是【引用】**（路径或 id），**不得内联定义**（与 `P26` 同一纪律）✅
② 🔴 **缺动作槽 ⇒ 【显式声明缺失】**（写 `missing_reason`），**不留静默默认** ——
   因为"没接上"与"不存在"必须能区分（红线 21 家族）✅
③ 🔴 **锚点必须显式**（见上 —— 每个有帧的槽都要写，或写 `inherit`）✅
④ 🔴 **占位必须标注**：`placeholder: true` + `source`（**有 placeholder 而缺 source ⇒ 拒绝加载**）✅
```

## §5 🔴 实施路径（**"接入一个作为接口保证"**）

```
① 🆕 **定接口**（本文 §3）⇒ **架构定 `hero.json` 的 schema + 加载门禁** ✅
② 🆕 **做一个"英雄资产加载器"**（内核零 Godot 只读数据；表现层读帧）⇒ **主程序 + UI 设计师** ✅
③ 🔴 **用【1 个】占位英雄验证接口**：
   · **只挑 1 个**（用户说"接入一个作为接口保证"）✅
   · **从 `borrow/` 抄出【最小的动作集】**（`idle`/`combat`/`attack`/`defend`/`afflicted`/`camp`）
     ⇒ 🔴 **放到被 gitignore 的占位目录**（不是 `resources/`）⚠️
   · **跑通"战斗里能看见它动"** ⇒ **接口成立** ✅
④ 🎖️ **然后请朋友做原创** ⇒ **填同一套槽** ⇒ **接口零改动** ✅
```

🎖️ **而这就是"接口保证"的意思**：
```
🔴 **接一个 ⇒ 证明接口能装下一个【真实体量的英雄】**（15 个动作槽 + 姿态组 + 装备图标）✅
⇒ 若装得下 ⇒ **朋友做原创时不会撞接口** ✅
⇒ 若装不下 ⇒ **现在改接口，比等原创做完再改便宜得多** ✅
```

## §7 🔴 技术选型口径（架构提请、我裁定，`#343`②）

```
🔴 **本阶段不引入任何【第三方动画 / 音频 runtime】**（Spine · FMOD 等）——
   理由：**"用了它" = "现在就把我们绑在那个工具上"** ⚠️
   ⇒ 🔴 **而绑定应【推迟到接口稳定之后】** ✅
⇒ ✅ **本阶段只用**：**`.png` 帧序列 + `AnimatedSprite2D`**（**Godot 内置**）✅
📌 **而接口定义在【"动作槽 → 帧序列 + 锚点"】层** ⇒
   **将来换 Spine / 换 3D / 换别的引擎实现，调用方【零改动】** ✅
   —— **那正是"接口"存在的意义** ✅
```

## §8 🔴 占位落点（**"防侵蚀"设计 —— 架构补，采纳**）

```
🔴 **风险不在"用占位"，而在【它会跟着构建 / 发行一起出去】** ⚠️
   而三条边界里，**第②条（不进构建产物）最容易被违反** ——
   因为**开发者的习惯是"把资源放进 `resources/` 让引擎直接读"** ⚠️
⇒ ✅ **正解（动作型 > 禁止型 —— `#341` 元准则的应用）**：
   🔴 **不是写"禁止拷进 `resources/`"，而是【让正确的路径成为默认】** ✅
   ```
   ① 占位目录 = **`darkest/assets/heroes_placeholder/`**（🔴 **也加进 `.gitignore`**）
   ② 🔴 **加载器显式支持"占位根目录"常量**（`HeroAssets.PlaceholderRoot`）
      ⇒ 占位资产**只从那里加载** ⇒ **"放对地方"是【唯一能跑的路径】** ✅
   ③ 而正式资产仍走 `darkest/assets/heroes/<archetype>/`（**进 git**）✅
   ⇒ 📌 **判据**：**占位资产若被错误拷进 `resources/` ⇒ 它不会被加载**（走不到那条路）⇒
      **错误做法【跑不通】而不是【跑得通但违规】** ✅
   ```
⇒ 📌 **一句话**：**把纪律做成"唯一能跑的路"，而不是"记得别走错路"** ✅
