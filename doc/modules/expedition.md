## 0. 定位

> **从「一场战斗好不好玩」→「一趟远征值不值得」。**

难度已在 #225 分成两层：

| 层 | 难度来源 | 目标 |
|---|---|---|
| **单场**（已通过） | **消耗**（掉血/掉士气），**不该是"死光"** | 胜率 ≥85% ／ 死门 ≤0.4 ／ 阵亡 ≤0.1 ／ 回合 4~6 |
| **跑图 / 远征**（**本文件**） | **损耗累积 + 资源决策** | **完成率 [40,70]** |

🔴 **为什么要做 M7（数据依据）**：切片实测 HP 曲线斜率仅 **−9.4pp/场**，`N=3` 时总损耗只有 **28%**
—— **"跑图层难度"这一层实际上是空的**（剩余 72% HP 走完，且失败几乎都来自"某场打输"而非"耗死"）。
**M7 的第一刀就是拉长 N，让损耗累积真正发生。**

## 1. 远征结构

```
远征 = 1 趟

  战 →［选路］→ 战 →［选路］→ 战 →［选路］→ 战 →［选路］→ 战 →［选路］→ 第 6 战
                                                                            ↓
                                                                         回城

· N = 【6 场战斗】
· 每场战斗结束（= 房间清空）后，可【扎营】
· 6 场走完 → 回城（完成）
· 任一环节中止（撤退 / 全灭）→ 提前回城（未完成）
```

   第 1~2 场   ×1.0

   第 5~6 场   ×1.25

#### 🔴 乘数施加对象：**【只作用敌 HP】**（v0.93 裁定，`#252`）

**架构建议 = 采纳**，理由比表面更硬：

```
A1 的两个"濒死类"指标余量都极小：
   死门 0.33 / 门槛 0.4    ← 余量 0.07
   阵亡 0.09 / 门槛 0.1    ← 余量 0.01  🔴
⇒ 提【敌攻击】会直接顶这两个 ⇒ A1 变红
⇒ 而提【敌 HP】主要拉长战斗，不加重单次伤害 ✅
```

#### ⚠️ 但必须同时加护栏：**回合数不得破带**

🔴 **两个口径的带不同，不能共用**（v0.94 补，`#253`）：

| 口径 | 回合带 | 现测 | 说明 |
|---|---|---|---|
| **单场**（A1 判定闸） | **4 ~ 6** | 5.36 | 一场战斗该多长 |
| 🔴 **链式**（一趟 6 场连着打） | **5 ~ 7** | **6.38** | 跨场累积 ⇒ 后段人更弱、打得更慢 |

**链式带的推导**：`链式 6.38 ÷ 单场 5.36 = 累积系数 1.19` ⇒ `单场带 (4~6) × 1.19 ≈ 4.8~7.1` ⇒ **取 5~7**。
🔴 **这 1.19 本身就是"累积在起作用"的证据** —— 若两者相等，说明跨场累积根本没发生。
**上沿取 7 而非 7.5**：因为目标是「**紧凑**」节奏（#230）——**上沿就是"累积过重"的报警线**。

**由此可加幅度**：

```
×1.10 → 6.38 × 1.10 = 【7.02】  ← 🔴 这是【模型推算】，且【已被实测推翻】
```

🔴 **v0.96/v0.97 实测结果：敌 HP 递进【全部撤销】**（`#255` / `#256`）：

| 口径 | ×1.0 | ×1.1 | ×1.1 + 眩晕15pp |
|---|---|---|---|
| **新队**（每档满编） | **5.77** | **6.59** | **6.88** |
| **链式**（带伤连打） | **6.38** | **10.45** | **14.96** |

🔴 **铁证在【新队口径】**：`5.77 → 6.59` ⇒ **每 +10% HP = +0.82 回合**
⇒ **×1.05 也有 6.18（破 A1 上沿 6）** ⇒ **唯一不破的是 ×1.0**
⇒ **×1.05 / ×1.1 / ×1.25 全部撤销。**

🔴 **为什么链式下更糟（+64% vs +14%）—— 虚弱与"敌 HP"互相喂养**：

```
带伤时，敌 HP +10% 的代价被【放大】：
  敌人多活 1 回合 → 敌方行动数增加 → 玩家掉更多血 → 【虚弱】（输出 −25%）
  → 清场更慢 → 敌人活得更久
⇒ "回合数 ∝ 敌 HP" 在【有虚弱 / 死门的系统里】不成立（非线性）
```

#### 🔴 链式回合判据：**废弃固定带 5~7**（v0.97，`#256`）

```
原 5~7 是【循环论证】推的（用当时的 6.38 ÷ 5.36 = 1.19，再乘 4~6）
⇒ 而数据说明：链式回合【本来就该逐档递增】（6.38 → 10.45 → 14.96）
⇒ 用一个固定带去卡每一档，与"越走越险"的设计【自相矛盾】
```

**改为**：

| 判据 | 值 |
|---|---|
| **第 1~2 场** | **≤ 6**（此时几乎无累积） |
| **最高档** | **≤ 9**（= 单场带上沿 6 × 1.5，给累积留空间） |
| **逐档递增** | ✅ **这是"越走越险"的正常表现，不是异常** |

#### 🔴 三条难度轴的实测结论（`#256`）

| 轴 | 回合影响 | 胜率影响 | 判定 |
|---|---|---|---|
| **敌 HP** | ❌ **链式 +64%** | ↑ 略 | ❌ **不可用（破两个回合带）** |
| **眩晕抗性 +15pp** | ✅ **几乎无（6.59→6.88）** | ❌ **无**（100% 不变） | ⚠️ **"不改回合"符合意图，但【也不降胜率】** |
| **敌攻击小幅 ↑** | ⚠️ 间接（经虚弱） | ✅ 直接 | ⏳ **唯一还能用的数值轴**，但幅度受 A1 濒死余量限制 |

#### 🔴🔴 判据级张力：**A1 与 A2 在数学上不可兼得**（v0.97，`#256`）

```
完成率 = p^6   （p = 单场胜率）
落 [40,70] ⇒ 取中 55% ⇒ p ≈ 0.90
而 p = 0.90 ⇒ 10% 场次要"输"
"输"只有两种：全灭 / 撤退 —— 代价都是【死人】或【频繁濒死】
⇒ 那正是 A1 在守的东西（阵亡 ≤0.1 = 几乎不死人；死门 ≤0.4）
```

| 判据 | 要求 | 余量 |
|---|---|---|
| **A1** | 单场胜率 ≥85% + **阵亡 ≤0.1（几乎不死人）** | 死门 0.33→0.4（+21%）· 阵亡 0.09→0.1（+11%） |
| **A2** | **6 场皆胜 [40,70]** ⇒ 单场胜率 **~0.90** | 需 p 从 0.983 压到 0.90 |

🔴 **"几乎不死人"与"10% 场次会输"互相拉扯，而 A1 的余量不够。**

### ⚠️ 另一条：**完成率对"策略撤退阈值"比对数敏感得多**

```
"输"= 全灭 或 撤退；而【撤退是策略选择】
⇒ 调 SemiRandom 的撤退门槛，完成率能从 90% 掉到 50%
⇒ 但那【不是难度】，是"策略变保守" ⇒ 用它降完成率是【自欺】
```

#### ✅ 结论与建议（`#256` / `#257` 已拍板）

🔴 **真正让"完成率"变成【玩家的选择】而非【数值的结果】的机制，是【光照计】**（M7.5）——
**在它落地前，硬把完成率压进 [40,70] 只能靠"数值变难"，而那必然破 A1 或破回合带。**

② 位移抗性【不动】（或最多 +5pp）
③ 减益抗性：待确认敌方是否有该字段

### 1.1 「完成」的定义 ✅

> 🔴 **完成 = 6 场皆胜**（与 `N=3` 的「3 场皆胜」同构）。

#### 🔴🔴 v1.14 修订（`#273`）：**完成 = 走完 6 步 ＋ 打赢 ≥3 场战斗**

> 🔴 **触发**：`#272` 加了"事件必然代价"后，V10 重跑显示 **保守档仍 100% 完成 + 0.00 补给** ❌
> **原因不是士气代价没生效**（6 个事件 × −5 = **−30 士气/趟**，生效了），
> 而是 🔴 **【士气低不影响完成率】** —— 因为"完成"只看"走完 6 步 + 不撤退/不团灭"。

```
根本问题：「走完 6 步」是【过程】，不是【目标】❌
⇒ 玩家可以【零代价走完】（全事件、只掉士气，而士气不影响成败）
⇒ 🔴 那不叫"完成"，那是【路过】
```

**修订后**：

```
🔴 完成 = 【走完 6 步】＋【打赢 ≥ 3 场战斗】（起手值，可调）
   · "打赢" = 敌方全灭（不含撤退）
⇒ "全事件"路线（0 战斗）【不可能完成】✅
⇒ 均衡（3 战）刚好达标 ⇒ 必须主动选战斗 ✅
⇒ 激进（5+ 战）超额 ✅
```

🔴 **这一刀同时解决两件事**：

| # | 解决 |
|---|---|
| **①** | **强制吃战斗损耗**（掉血）⇒ **不再是零代价通道** ✅ |
| **②** | 🔴 **让补给变得【必要】** —— 掉血 ⇒ 要扎营恢复 ⇒ **扎营要柴火/口粮** ⇒ **"摸黑搏补给"终于有理由** ✅ |

**⇒ "风险/收益"就此闭环；而士气仍是"跨趟"的事（`#245`）** ✅

> ❌ **不采纳的候选（主程序提议 (b)）**：「完成口径纳入士气（士气为 0 即中止/判负）」
> —— 🔴 **不采纳原形**：**"士气 0"是常见状态**（崩溃判定后"留在 0"，见 `GDD §3.2`）⇒ 会造出**大量中止** ❌
> ✅ **但采纳其【精神】**：**完成必须有"非过程"的条件** ⇒ 具体即上面的**战斗目标**。

**依据（已算）**：

```
切片 3 场皆胜 = 48%  →  反推单场胜率 p³ = 0.48  →  p ≈ 0.783
N=6 无恢复：0.783⁶ = 【23%】   ❌ 远低于 [40,70]
⇒ 需把单场胜率推到 p ≈ 0.89（+11pp）—— 这 +11pp 【只能来自战斗之间的恢复】
⇒ 🔴 所以「N=6」与「扎营」是一对，不能只做一个
```

### 1.2 结局与回城

| 结局 | 触发 | 回城后方 |
|---|---|---|
| **完成** | 6 场皆胜 | HP 完全恢复 · 🔴 **士气【完全不恢复】**（见 §1.2.2）· 清虚弱/死门后遗症 · 阵容满编 |
| **撤退** | 战斗内撤退成功 | HP 完全恢复 · **士气按 §1.2.1 惩罚** · 同上 |
| **全灭** | 我方全灭 | 同上，但 🔴 **无士气惩罚**（**人都没了，无人可罚**） |

#### 1.2.2 🔴 回城士气：**完全不恢复**（v0.87，#245）

> **用户拍板**：**(a) 回城士气口径 → 完成档也【完全不恢复】**；**(b) HP / (c) 状态 先不做**（一次只动一个轴，才能归因）。

```
回城（完成档）：
   HP    → 完全恢复
   士气  → 🔴 【完全不恢复】（保持跑图结束时的值）
```

🔴 **这等于完全照抄 DD 的压力模型**：

| | DD | 我们 |
|---|---|---|
| 战斗伤害 | 会治 | HP 恢复 ✅ |
| **压力 / 士气** | 🔴 **不会自己降** | 🔴 **回城也不恢复** |
| 清除渠道 | Tavern / Abbey（**花钱 + 占时间**） | ⚠️ **暂无**（M8 远征循环层） |
| 崩的形态 | 压力 200 → 心衰 | 士气 0 → 崩溃（已有） |

**为什么这条不是"更狠"而是"更对"**：

```
现状（完成 → 拉回 50）：
   一趟的士气损耗被【一笔勾销】 ⇒ 士气只是"单趟资源"
   ⇒ ⑯ 无信息量（恒 = 50）· 与 #210「压力长线化」的意图【相反】

改后（完全不恢复）：
   士气真正成为【跨趟资源】 ⇒ 与 #210 一致 ✅ · ⑯ 变成可用指标 ✅
   ⇒ 与"HP 会治、士气不会"这条 DD 核心对比【完全对齐】
```

🔴 **⚠️ 连带义务（必须写明）**：**士气完全不恢复 ⇒ 跨趟单调下降 ⇒ 最终必崩**。
而 **"崩"不是问题（那是硬核）——问题是【没有出口】**：DD 的出口是 Tavern/Abbey（花钱减压），
**我们 M7 范围 = 只做跑图闭环，没有花钱系统**。

✅ **M7 的处置（裁定）**：

| 项 | 定案 |
|---|---|
| **规则** | ✅ M7 **落**（回城不恢复士气） |
| **跨趟平衡** | ⏸ **M7 不验**（那是远征循环层的账）→ 留给 **M8**（配"减压渠道"） |
| **M7 验收** | ✅ **不变**：单趟 6 场完成率 [40,70] |
| 🆕 **诊断读数** | **连续 3 趟的士气曲线**（看累积斜率、看第几趟崩）——同 #225 把"单场"改"3 连战"的做法 |

> **严厉程度不写死**：按 E7 数据（一趟结束士气 ~44%）粗算净降约 6%/趟 ⇒ **约 8 趟才崩**，
> 比"3~5 趟"温和。**具体由复测给出，不用估。**

#### 1.2.1 撤退的士气惩罚 ✅

> **用户原话**："**全灭了人都没了哪来的惩罚？撤退就按照死亡人数对剩余角色进行少量缩放士气惩罚**"
> **v0.80 修订**："**固定值，分为有死亡/无死亡两个挡位，有死亡高一点点**"

```
撤退惩罚（只对【存活者】施加）——【固定两档】

   本趟【无死亡】→ −12
   本趟【有死亡】→ −15        （"高一点点"）

   · 只罚【存活者】（阵亡者不罚）
   · 在【撤退发生的那一刻立即结算】（沿用 #43 的事件式 `morale_events.retreat_success`）
```

| 项 | 定案 |
|---|---|
| **对象** | 🔴 **只罚存活者**（阵亡者不罚） |
| **分档** | 🔴 **两档固定值**：无死亡 −12 ／ 有死亡 −15（**不是按人数连续缩放**） |
| **方向** | 🔴 **有死亡 ⇒ 罚更高**（"高一点点"）|
| **结算时机** | **撤退发生的那一刻立即结算**；回城只是"不恢复满" |
| **基准值** | 士气区间 **0~100**、基准 **50**（`data_schema` `morale:{min:0,max:100,start:50}`） |
| **12 的来历** | DD「撤退成功 +25 压力」在 **0~200** 区间上 = **12.5%** → 我们 **0~100** 的等比 = **12** |

> 🔴 **被否决的方案（留痕，勿重提）**：策划曾提案"**死得越多、罚得越轻**"，理由是
> "死亡本身已付代价（战力损失 + 阵容缩水 + 拉低后续胜率），再叠士气重罚是双重惩罚"。
> **用户否决** —— 改为"**有死亡反而高一点点**"。
> **用户的逻辑更直**：**死了人说明队伍崩了，幸存者的心理创伤更大**（DD 亦是此方向，无"死亡减罚"）。
>
> ⚠️ **并推翻既有 #43 的字面值**：原「撤退成功全队 −10」是**固定值、且对全员**（含阵亡者）；
> 现改为**只对存活者 + 分两档**。`review.md` 风险 #5（"−10 接近一次崩溃，可能过贵"）随本次一并收口。

### 1.3 选路

每步给 **2 个节点**。**分两阶段落地**：

#### 阶段一（**M7 最小版 · 先跑通**）✅

| 节点 | 内容 | 回报／代价 |
|---|---|---|
| **普通战** | 标准损耗（**复用现有 3 原型敌人**） | 无额外 |
| 🆕 **事件节点** | 无战斗；🔴 **必然代价 + 可选收益**（见下） | 全队 **−5 士气**（必然）＋ 可选「搜刮」 |

> 🔴 **资源来源 =「事件节点」**（**不是**精英战）——这样**最小版不需要任何新敌人编成数据**即可跑通。

##### 🔴🔴 v1.13 重写：事件节点必须「**必然代价 + 可选收益**」（`#272`）

> 🔴 **原写法的缺陷**：我原写"**二选一风险：拿补给 ／ 全队 −士气**"—— **有歧义，两种读法都不成立**：
> ```
> (a) 拿补给免费   ⇒ 傻的才选另一个
> (b) 不拿无事     ⇒ 那"不拿"最优 ⇒ 事件变成【免费安全通道】❌
> ```
> 🔴 **实测印证（V10，`2026-09-13`）**：
> ```
> 保守（全事件 / 早提亮）→ 完成率 100% · 补给 0.00 份/趟
> ⇒ 【零损耗通道】—— 玩家永远选它 ⇒ 战斗与摸黑【都没有理由】❌
> ```

**规格（v1.13）**：

```
【事件节点】
① 🔴【必然代价】全队 −5 士气（赶路疲惫；**起手值**，tuning 可调）
② 【可选收益 · 二选一】
     A. 搜刮 → +2 补给，但【再 −5 士气】
     B. 直接走 → 无额外
⇒ "全事件"路线每节点 −5 士气 ⇒ 【有真实代价】✅
⇒ 而"战斗"路线给补给、士气代价结构不同 ⇒ 【两条路可比】✅
```

🔴 **为什么必须这样**：

```
事件若【无代价】⇒ 它是一条免费通道 ⇒ 玩家永远选它
⇒ 战斗与摸黑【都没有理由】⇒ 【光照计与选路同时失效】❌
⇒ 而"必然代价"让【选事件 = 用士气换安全】⇒ 那才是一个真实的取舍 ✅
```

#### 阶段二（**主流程跑通后再加**）⏳

| 节点 | 内容 | 回报／代价 |
|---|---|---|
| **精英战** | 🔴 **换一套敌人编成**（**非数值放大**） | 掉 **柴火 + 口粮** |

> **为什么精英战延后（用户拍板"暂不定，先跑通主流程"）**：
> ① 它需要**新编成数据**（`enemies.json` 增一档 + 选路时按节点类型取编成）；
> ② 它不该挡住主流程（普通战 + 事件 + 扎营 + 回城）；
> ③ 而**资源来源已有替代**（事件节点）⇒ **主流程不依赖精英战** ✅
>
> **精英战为什么"换编成"而不是"数值放大"**：数值放大只是"更硬"，**换编成才是"更难的题"**（逼玩家换技能 / 换站位）。
> ⏳ **编成内容待设计**（§6.10）。

## 3. 扎营 ✅（照抄 DD 两阶段）

> 🔴 **触发**：每场战斗之后（**战斗结束 = DD 的"已清空的房间"**）。
> 🔴 **许可**：消耗 **1 份柴火**。

### 3.1 阶段一 · 食物阶段（照抄 DD 四档）

| 档 | 消耗口粮（6 人） | 效果 |
|---|---|---|
| **Starve** | **0** | 🔴 **全队 −20% HP、−15 士气** |
| **Half** | **3** | 无效果 |
| **Full** | **6** | 全队 **+10% HP** |
| **Feast** | **12** | 全队 **+25% HP、+10 士气** |

> 🔴 **`Starve` 是这一层的精髓**：**可以饿着，用 20% 血换省下全部口粮** —— 一个真实的赌注。
> **减员修正**：DD 是"每死 1 人，所需食物 −1/4" → 我们按**存活人数等比缩放**。

#### 🔴 口粮不足时的规则 ✅（**v0.86 补充 —— 原规格缺口**）

```
· 需要更多口粮的档位 → 🔴【不可选】（灰显 + tooltip「口粮不足」）
· 选【Starve】        → 🔴 照常受罚（全队 −20% HP、−15 士气）
                        —— 它是【主动选择】，不是"免费"
· 🔴 禁止"自动退化为 starve 且不扣" —— 那是【免费午餐】
```

> 🔴 **为什么必须补这条**：原规格只写了"四档的效果"，**没定义"口粮不足时怎么办"**
> → 实现自行补了一条"**退化为 starve 且不扣**"的路径
> → 造成 **E7 灵敏度非单调**（起手口粮 8 的那档**既没吃 Feast、又躲过 starve 惩罚** → 终局反而最好 67%/78%）
> ⇒ **这是"规格缺口"导致的实现偏差，不是实现的错。**
> ⚠️ **待核对**：我们的**口粮是否要"按存活人数缩放"**，还是固定 3/6/12（见 §6）。

### 3.2 阶段二 · 技能阶段 🔴（**角色专属扎营技能**，v0.84 改动）

> 🔴 **改动依据（用户）**："**我希望的是扎营有行动点，通过使用角色的扎营技能（学习 DD）来达到扎营的效果**"
>
> **DD 的原始结构**（`wiki.gg/wiki/Camping` 原文）：
> 「**Each class has their own skill sets.** There are also shared ones which can be used by all heroes…」
> ⇒ **12 点 Respite 是【共享池】，但花它的是"某个角色用他自己的扎营技能"** ——
> **真正的决策 = "哪个角色的哪个技能 × 点数怎么分"**，而不是"全队从 3 个里挑"。

**Respite 点数 = `6 + 存活人数`**（满编 6 人 = **12**，与 DD 默认值相同；**减员后变少** ✅ 天然惩罚减员）

#### 四个原型的扎营技能组（每原型 3 个，共 **12** 个）

| 原型 | 技能 | 点数 | 效果 |
|---|---|---|---|
| **战士** | **磨刀** | 2 | 单个友方：**下一场战斗伤害 +25%** |
| | **轮流守夜** | 3 | **免疫接下来的夜袭**（一次） |
| | **笑谈** | 1 | 单个友方 **+8 士气** |
| **坦克** | **加固甲胄** | 2 | 单个友方：**下一场战斗物防 +4** |
| | **站岗** | 3 | **免疫接下来的夜袭**（一次） |
| | **埋锅造饭** | 2 | **全队 +5 士气** |
| **军医** | **包扎** | 2 | 单个友方 **+15% HP**，**清除流血** |
| | **配药** | 3 | **清除【虚弱】与【死门后遗症】** |
| | **照料** | 1 | 单个友方 **+5% HP** |
| **政委** | **鼓舞** | 2 | 单个友方 **+15 士气** |
| | **训话** | 2 | 单个友方 **4 场战斗内 −15% 士气伤害**（= DD Pep Talk，即原方案的「打气」） |
| | **战前动员** | 3 | **全队 +10 士气** |

> 🔴 **关键设计：不是"全队回血"，是"谁用哪个技能、点给谁"** —— 12 点自由分配 ⇒ **决策密度**。
>
> 🔴 **一个很好的连带：编成影响扎营能力** ——
> 带 2 个军医 ⇒ 治疗/清减益类技能多；带 2 个战士 ⇒ 战斗准备类多。
> **编成决策从"单场层"延伸到了"远征层"** ✅ 与 #190 的可插拔契约一致。
>
> ✅ **不做 DD 的 3 个"共享技能"**（Encourage / Wound Care / Pep Talk）——🔴 **用户拍板："不做共享技能，就用角色的"**。
> 理由：①我们的编成是**固定的**（1 坦 + 2 战 + 1 政委 + 2 军医），共享会**冗余**；
> ②"共享"与"可插拔"（**#190**）的取舍精神不符 ⇒ **扎营能力完全由"带了谁"决定**。
> 📌 **将来若角色可自由替换，再议**（届时"最低保障"可能重新需要共享技能）。

#### 🔴 `DurationType` 的两条**不同类型**（必须分清，否则扎营会误清训话）

| 效果 | duration 类型 | 扎营时 | 回城时 |
|---|---|---|---|
| **`deaths_door_recovery`**（死门后遗症） | **到下次恢复**（`until_next_recovery`） | ✅ **清除** | ✅ 清除 |
| 🔴 **`训话`（Pep Talk）** | 🔴 **跨场战斗计数**（`remaining_battles: 4`，随场次递减） | ❌ **不清除** | ✅ 清除 |

> 🔴 **若把「训话」判成"到下次恢复"，一扎营它就没了** —— 而 DD 原意是"**持续 4 场战斗**"。
> **玩家花 2 点 Respite 买的效果当场失效，与"跨场投资"的设计意图相反。**
> **两者并列、语义不同，不得合并。**

#### 🔴 SP 的恢复：从「机制」改为「背包物品的 buff」✅（#248）

```
