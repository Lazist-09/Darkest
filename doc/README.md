## 3. 四条核心链路（最快理解这游戏的一页）

```
① 位置链   技能绑定「位置」→ 站位决定能用什么 → 位移改变站位 → 能用的技能就变了
           ⇒ 位置不是站位，是技能的资源与约束

② 位移链   推 N 格 = 逐级交换 N 次 → 永远不产生空位 → 撞障碍即交换 → 撞边界即失败
           ⇒ 位移改变的是「顺序」不是「间距」，阵型长度恒定

③ 士气链   只有【精神】伤害掉士气（物理不掉）→ 归 0 触发崩溃判定（折磨/美德）→ 士气留在 0
           → 进入崩溃余烬（不再判定）→ 拉回 50 才解脱
           ⇒ 唯一的士气威胁源是敌方后排施法者 ⇒「切后排」成为真战术

④ 生存链   受伤 → HP 归零【不死】→ 士气归 0 + 崩溃判定 → 虚弱（伤害-50%/速度-30%/HP 锁 1）
           → 虚弱期再受伤 → 死门判定（抗性 60~75%）→ 失败 = 真正死亡
           ⇒ HP 归零是「警告」，死门才是「处决」
```

## 6. 约定与纪律（改文档前必读）

1. **`#N` 指 `state.md` 决策表的第 N 条**。写代码注释 / 提 issue 时带上编号，方便回溯。
2. **冲突时以 `modules/` 为准**——模块是后写的、更细的一层；`GDD.md` 是骨架与意图。
3. **改一条决策要同步三处**：`state.md` 决策表 → 相关 `modules/*.md` → `CHANGELOG.md` 加版本。
4. **别同文件并行编辑**——本轮排雷踩过两次坑，同文件并行改会静默丢改动。
5. **数值不当即改**：起手值迭代走 `verification.md` 的 Monte Carlo，别手调。
6. **被推翻的决策不要删**，划线保留（如 `~~输出~~ ⚠️ 已被 #145 推翻`）——演进记录本身有价值。
7. **策划边界**：本文档只出设计规格。**不实现原型、不做模拟验证**；验证规格在 `verification.md`，交由实现方执行。
