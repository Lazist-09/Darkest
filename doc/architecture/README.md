## 4. 实施前必须知道的 9 件事（FAST START）

1. **先读** `_conventions.md`（写作规则）→ `blueprint.md`（架构全景）→ `data_schema.md`（数据字段）。
2. **目录铁律**：res:// 顶层只有 `scenes/ scripts/ data/ resources/ tests/`；`core / gameplay/sim / data` 零 `using Godot`（M0-04 静态检查）。
3. **数据唯一落点**：`res://data/` 七个 JSON（data_schema §1）；数值不当即改，走 `--override` 覆盖集，不改代码。
4. **确定性**：每场一个 seed；固件层 9 层随机在固定调用点（blueprint §8.2）；headless 与实机共用同一 BattleDirector（M6 前提）。
5. **位移预览 = 内核 dry-run**：预览与结算同源（blueprint §5d），禁止 UI 自己推演"只推 1 格"。
6. **UI 是机制的一部分**：9 条必显示信息（ui_spec §2）缺一不可，尤其行动序列 / 撤退成功率数字 / 灰显原因 / 位移预览。
7. **目标语义（#178/#179，v0.44）**：技能范围=**候选池**——单体/`any_ally` 在池内**选一**（玩家 ③b / AI / 策略），AOE 全中、`team` 全体、双段同目标两段；数据 JSON 零改动（data_schema §3.2 生效语义 + P11）。**v0.45/v0.48：池外「移动」（#180/#191，`pool_external` + `move_range`，**总量 44 = 36 池内 + 1 通用 `move` + 7 敌**）、增援单按钮两步（#181）、技能栏不内联要求文字但候选高亮必需（#182）**。
8. **开放题处置**：任务卡内遇到的歧义先查 open_issues.md（O-01~**O-61**）；未覆盖的 → 挂新 O-nn，**不得静默改设计/拍数值**；**多包同时提案时由架构师统一编号**（先到先得，重号者按"引用面最小"顺延 — 已发生 3 次，见 open_issues 表头 v0.50/v0.52/v0.55 说明；**新卡请写 `O-新（待编号）`**）。
9. **先读后写**：任何文件修改前先 read 全文；同文件禁止并行编辑（策划纪律第 4 条）。
10. **🔴 复测前置 + 判据纪律（O-42 / O-49~O-67）**：**前置链已全部落地**（`m6_fix_pack` P0~P3 · F0~F4 · D0~D7 · S0~S5 · G0a）；**切片唯一待办＝撤退口径**（撤退 = 该场失败 + 中止 run → ② 须 == ③ == 46%）。**切片判据**：**A1 单场（判定闸）＝ 胜率 ≥85% / 死门 ≤0.4 / 阵亡 ≤0.1 / 回合 4~6**；**A2 ＝ 3 场皆胜 [40,70]**（M7 起 → **6 场皆胜**）。**必报**：实测 `D`（= **21.04**）+ 实测 `E` + 口径健康度（**单一位次承伤 ≤40%**）+ `M_base`（= **7**，须与 `tuning.m_value` 一致，P16 fail-fast）+ 技能使用率（**按 `CasterSlot > 0` 过滤**）+ SP 分布 + 待命次数 + **增援事件数（预期 ≈0）**。**19% / 24% / 20% / 27% / 46% 等旧胜率一律不得作为验收或调参依据**。
11. **口径约定 A（v0.54；v0.87 更新滞后清单）**：**策划表记「最新决策值」；实现滞后由 `data_schema` 记两档（现生效 / 目标）**。**当前已知滞后项只剩两条**：**收割 0.4/0.5 → 0.6/0.7**、**劈砍 0.9 → 1.0**（敌 HP、敌攻、急救 CD、死门抗性、目标偏好**均已落地**）。
12. **🔴 可观测性优先序（O-55 / #199 / #217）**：**`feat_pack_02` 拆两批——`G0a`（`SkillUseEvent` + `TurnSkippedEvent` + 基类 `Round`）是 P3 v3 的前置；`G0b`（其余 12 类 + 补字段）与 G1/G2 后置**。理由：**复测是当前瓶颈，应尽量少拦它**；且 **P3 v3 报告字段「技能使用率 ← `SkillUseEvent`」「待命次数 ← `TurnSkippedEvent:passed`」直接依赖 G0a**，**不得用策略侧单独计数顶替**（实机没有策略层 → 与实机日志必然对不上）。纪律：**"UI 要显示的数字"必须先从事件流能算出来**，算不出就补事件字典，**不得为消费者单独造数据**；**"不显示" ≠ "不记录"**（级 4 `RngDraw` 必须记录）。

15. **🔴 术语固定纪律（v0.92 / #251，由三次同类事故立规）**：**凡是有歧义可能的词（数量 / 时间 / 轮次单位），第一次出现时就写死定义**。事故链：**#244「规格缺口」被当成「实现偏差」→ #247 `(b)/(c)` 定义前后漂移 → #251「一场」= 趟 还是 场**——**三次都是"术语没固定 → 下一轮一定读错"**。

    |---|---|

    | **场** | **单场战斗**（回合制的那个单位） |
    | **回合** | 一场战斗内的一轮行动序列 |
    | **HP** | 🔴 **一趟结束（回城）后完全恢复**；**场间不恢复** |
    | **士气** | 🔴 **一趟结束后完全不恢复**（#245） |
