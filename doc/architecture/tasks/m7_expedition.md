## E0 · 远征会话（`ExpeditionSession`）

### 规格（`expedition.md` §1）

```
远征 = 1 趟
· N = 6 场战斗
· 每场战斗后 → 可选【扎营】
· 6 场皆胜 → 完成
· 任一环节中止（撤退 / 全灭）→ 提前回城（未完成）
· 夜袭产生的战斗【计入】6 场皆胜（即实际战斗数 = 6 + 夜袭次数）
```

### 改动点

| 文件 | 改动 |
|---|---|
| `darkest/scripts/gameplay/sim/run/RunSession.cs` | 扩为 **`ExpeditionSession`**（或并列新增）：持有 **节点序列 / 当前节点索引 / 资源 / 已完成场数**；`BattleDirector` **仍保持"单场纯"**（每场工厂新建 → 同 seed 可复现单场） |

| `darkest/data/tuning.json` | 新增 `expedition: {n_battles: 6, ambush_chance: 0.33}` |

### 验收

| 用例 | 期望 |
|---|---|
| 6 场走完且全胜 | `CompletedStrict == true` |
| 第 3 场撤退 | run **立即结束**、该场判负、**不计完成** |
| 第 4 场全灭 | run 结束、**不计完成** |
| 夜袭场 | **计入** 6 场皆胜（夜袭也须赢） |
| 确定性 | 同 seed 同结果 |

## E3 · 扎营（**照抄 DD 两阶段**）（`expedition.md` §3）

### 规格

```
触发：每场战斗之后（= DD 的"已清空的房间"）
许可：消耗 1 份【柴火】

① 食物阶段（6 人）
     Starve  0 份 → 全队 −20% HP、−15 士气
     Half    3 份 → 无效果
     Full    6 份 → 全队 +10% HP
     Feast  12 份 → 全队 +25% HP、+10 士气
   （口粮需求按【存活人数】等比缩放，照抄 DD 的"每减员 −1/4"精神）
   🔴 v0.86 补【口粮不足时】：
        · 需要更多口粮的档位 → 【不可选】（灰显 + tooltip「口粮不足」）
        · 选 Starve → 照常受罚（−20% HP / −15 士气）—— 主动选择，不是"免费"
        · 🔴 禁止"自动退化为 starve 且不扣"（免费午餐 → 会造出非单调）

② 技能阶段
     Respite = 6 + 存活人数（满编 12）     ← 🔴 共享池
     🔴 花法 = 【某个角色用他自己的扎营技能】—— 每原型 3 个，共 12 个
        战士：磨刀(2,下一战伤害+25%) / 轮流守夜(3,免下次夜袭) / 笑谈(1,+8 士气)
        坦克：加固甲胄(2,下一战物防+4) / 站岗(3,免下次夜袭) / 埋锅造饭(2,全队+5 士气)
        军医：包扎(2,+15% HP 清流血) / 配药(3,清虚弱+死门后遗症) / 照料(1,+5% HP)
        政委：鼓舞(2,+15 士气) / 训话(2,4 场 −15% 士气伤害) / 战前动员(3,全队+10 士气)

③ 后置：33% 概率【夜袭】（见 §E5）
```

> 🔴 **v0.84 改动依据**（用户）："**我希望的是扎营有行动点，通过使用角色的扎营技能（学习 DD）来达到扎营的效果**" ——
> DD 原文：「**Each class has its own skill sets**」⇒ **12 点是共享池，但花它的是"某角色用他自己的技能"**。
> ✅ **连带好处**：**编成影响扎营能力**（带 2 军医 ⇒ 治疗/清减益多）→ **编成决策延伸到远征层**，与 #190 可插拔契约一致。
> ⚠️ **不做 DD 的 3 个"共享技能"** —— 🔴 **用户拍板："不做共享技能，就用角色的"**；
> ⇒ **扎营能力完全由"带了谁"决定**（固定编成下共享会冗余）。📌 将来可自由替换角色时再议。

### 改动点

| 文件 | 改动 |
|---|---|
| `darkest/data/camp_skills.json` 🆕 | 🔴 **12 个角色专属扎营技能**（**每原型 3 个**：战士 磨刀/轮流守夜/笑谈 · 坦克 加固甲胄/站岗/埋锅造饭 · 军医 包扎/配药/照料 · 政委 鼓舞/训话/战前动员）；字段：`owner_archetype` / `respite_cost` / `target` / `effects` |
| `tuning.json` | `camp: {food_tiers:{starve:0,half:3,full:6,feast:12}, respite_base:6, ambush_chance:0.33}` |
| `ExpeditionSession` | 扎营流程状态机（阶段一 → 阶段二 → 夜袭判定） |
| `BattleEventTypes.cs` | `CampStartedEvent` / `CampFoodChosenEvent(tier)` / `CampSkillUsedEvent(skillId, target, respiteLeft)` / `CampEndedEvent` |
| 🔴 `data_schema.md` — **两类型必须分清** | **①`DurationType` 新增「到下次恢复（扎营/回城）」** → **`deaths_door_recovery`** 用它（原 `until_run_end` 改义）；**扎营会清它** ✅<br>**②`DurationType` 新增「跨场战斗计数 `battles:N`」** → **`打气`（Pep Talk，4 场）** 用它；🔴 **扎营【不清】它**、回城才清 |
| UI 🆕 | **扎营界面**：食物档位选择 + Respite 点数分配 |

> 🔴 **两类型不得合并**：若把「打气」判成"到下次恢复"，**一扎营它就没了** —— 而 DD 原意是"持续 4 场战斗"。
> 🔴 **「扎营耗时」不做**（DD 有"扎营花时间"）——**靠资源稀缺自然约束**：柴火 2 份 ⇒ 结构上就不可能每次都扎，**不加隐藏规则**。

### 验收

| 用例 | 期望 |
|---|---|
| 无柴火 | **不可扎营**（灰显 + tooltip） |
| Starve | 全队 **−20% HP、−15 士气** |
| Feast | 全队 **+25% HP、+10 士气**（且消耗 12 份口粮） |
| Respite 上限 | 满编 **12**；死 2 人 → **10** |
| 包扎 | 治 **15% HP** 且**清除流血** |
| **打气/训话** | **跨场**生效（持续 **4 场战斗**，不是 4 回合）；🔴 **扎营【不清】它**（与 `deaths_door_recovery` 的"到下次恢复"**是两类**）；🔴 用 **`remaining_battles: 4`**（随场次递减），**不复用恢复语义** |
| 🔴 **角色专属** | 扎营技能**按 `owner_archetype` 区分**：**只有该原型的角色能用**（战士的技能不能由军医放）。**可测判据（架构侧补）**：① **数据**：`camp_skills.json` **恰 12 条、每原型恰 3 条、每条必填 `owner_archetype`**（P20 ④）；② **正向**：`medic_bandage` 交给军医 → 可选；**反向**：交给战士/坦克/政委 → **不可选（灰显）且命令被拒、不消耗 Respite**；③ **逐条覆盖 12 个技能**；④ **UI**：跨原型技能**不出现/灰显**（不得"显示了但点了没反应"）；⑤ **禁止** `owner_archetype == null` 的"共享技能"（#243）。见 `m7_verification` **V8** |
| 🔴 **编成影响能力** | 带 2 军医 ⇒ 治疗/清减益类更多；带 2 战士 ⇒ 战斗准备类更多（**验：换编成后可用扎营技能集合确实变化**） |
| 口粮缩放 | 减员后所需口粮按比例降 |
| 点数不足 | 该技能**不可选**（灰显） |

## E6 · 回城与士气惩罚（`expedition.md` §1.2 / §1.2.1）

### 规格

```
【回城效果】
   HP        → 完全恢复
   士气      → 🔴【完全不恢复】（v0.87 拍板；**完成档也不恢复**）
               撤退档：撤退时已结算惩罚，回城同样不恢复
               全灭档：无惩罚，但同样不恢复
   状态      → 清除【虚弱】与【死门后遗症】
   阵容      → 恢复满编（不做招募）

   🔴 连带义务：士气完全不恢复 ⇒ 跨趟单调下降 ⇒ 最终必崩
      · DD 的出口是 Tavern / Abbey（**花钱减压**）——【我们 M7 没有】
      · ✅ M7 处置：**规则先落；跨趟平衡【不验】**（留 M8）；M7 验收不变（单趟完成率）
      · 🆕 **诊断读数：连续 3 趟的士气曲线**（同 #225 把"单场"改"3 连战"的做法）
      · ℹ️ **这不只是"更狠"，是"更对"**：现状"拉回 50"把单趟损耗一笔勾销 ⇒ 士气只是**单趟资源**（⑯ 无信息量）；
        改后士气成为**跨趟资源** ⇒ **#210「压力长线化」才真正落实**，并与"HP 会治、士气不会"完全对齐

【撤退的士气惩罚】
   只对【存活者】施加（阵亡者不罚）
   固定两档：本趟【无死亡】→ −12 ／ 本趟【有死亡】→ −15
   🔴 在【撤退发生的那一刻立即结算】（沿用 #43 的 `morale_events.retreat_success`）
   回城只是"不恢复到 50"，不二次扣

【全灭】
   🔴 无士气惩罚（无人可罚）

【基准】士气区间 0~100、基准 50
```

### 改动点

| 文件 | 改动 |
|---|---|
| `tuning.json` | `expedition.retreat_penalty: {no_death: 12, with_death: 15}` |
| `morale_events` | **改写 `retreat_success`**：从"全队 −10（固定、含阵亡者）"→ **"只对存活者、两档 −12/−15"**（**推翻 #43 字面值**） |
| `ExpeditionSession` | 回城结算（HP/士气/状态/阵容） |
| `BattleEventTypes.cs` | `TownReturnEvent(outcome, moraleBefore, moraleAfter, penaltyApplied)` |

### 验收

| 用例 | 期望 |
|---|---|
| 撤退（无死亡） | 存活者 **−12**；阵亡者不扣（无人）；**回城士气不回到 50** |
| 撤退（有死亡） | 存活者 **−15** |
| 全灭 | **无士气惩罚**；回城士气回 50 |
| 完成 | 回城士气回 50 |
| 状态清除 | 虚弱与死门后遗症**被清** |
| 不重复扣 | 撤退结算一次；回城**不再扣** |

## E7 · 验收（M7 层）见 `expedition.md` §7

| 项 | 判据 |
|---|---|
| **完成率** | **6 场皆胜 → 落 [40,70]**（区间 `N=6` 实测后校准） |
| **单场层不退化** | A1 四项仍达标（胜率 ≥85% / 死门 ≤0.4 / 阵亡 ≤0.1 / 回合 4~6） |
| **损耗累积真实发生** | HP 曲线**后段斜率不为零**；`N=6` 总损耗 **显著 > 28%** |
| **扎营次数分布**（🆕） | 是否用满 **2** 次 · **用在哪几场**（是否留到最后）—— 这才能说明玩家在**决策**<br>⚠️ 原写"**不是每次都扎**"**已废**：柴火 2 份 ⇒ **结构保证**（6 场最多扎 2 次），**验不出任何东西** |
| **`Starve` 有意义** | 出现"饿着过"的选择 |
| **士气长线化生效** | 士气**跨场累积下降** + 回城惩罚可观测 |
| **决定性** | 同 seed 同结果 |

### 复测必报字段（在 M6 的 9 项之上追加）

```
⑩ 完成率（6 场皆胜）＋ 逐场胜负序列
⑪ 每场结束的 HP% / 士气%（曲线，判"损耗累积"）
⑫ 扎营次数 / 食物档位分布（Starve 占比）／ Respite 花费分布
⑬ 资源收支（柴火/口粮 得与失）
⑭ 夜袭触发次数
⑮ 撤退次数＋当时死亡人数（验证两档惩罚）
⑯ 🔴 撤退档的回城士气分布（**v0.86 修正**：完成档必然 = 50 ⇒ **只报撤退档**，否则无信息量）
```
