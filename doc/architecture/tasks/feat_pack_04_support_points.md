## S0 · 规格

```
【支援点 SP】

· 起手 3；每回合开始 +1；上限 4
· 消耗：
    支援位（5/6）单位使用技能        →  −1
    我方增援（Reinforce，把支援位角色调动上场） →  −2
· 不消耗：
    战斗位（1~4）单位使用技能
    被动效果（支援位每回合回士气 +3）
    撤退
· 点数不足 → 该行动【灰显不可用】+ tooltip：支援点不足（当前 N / 需要 M）
· UI：常驻显示剩余 SP（含本回合恢复预览）
```

| 参数 | 起手值 | 说明 |
|---|---|---|
| `start` | **3** | 前 2 回合可爆发（各 2 次支援行动） |
| `regen_per_round` | **+1** | 与"支援位 2 个单位"形成稳态 **1 次/回合**（现为 2） |
| `cap` | **4** | 防长攒爆发；允许 ≈2 回合的小额蓄力 |
| `cost_skill` | **1** | 支援位技能 |
| `cost_reinforce` | **2** | 增援——**调动一个人比放一个技能重** |

> 🔴 **为什么是「随回合恢复」而不是「每场固定次数」**：固定次数是**配额**（用完就废）；
> 恢复制是**节奏约束**（现在用还是攒着）→ **每回合都产生一个小决策**。
> **旋钮 = `regen_per_round` 与 `cost_skill`**（都只改一个数）。

## S5.1 策略规格（规则化、可解释）

> 🔴 **v0.57 修订（O-61 裁定 #215）**：本节的阈值原先按 **`cost_skill = 1`** 写；
> #213 把 `cost_skill` 改成 **2** 后产生两处矛盾（① 保命分支缺 SP 前置；③ 续航分支"SP ≥ 2 且治完保留 ≥1"自相矛盾）。
> **已按"分级消费"重写如下**——架构侧两个候选**均未采纳**（见 §S5.1b）。

**阈值（起手值）**：

| 项 | 值 | 说明 |
|---|---|---|
| 保命线 | 目标 HP% **< 30%** | **需 `SP ≥ 2`**（一次技能 −2） |
| 续航线 | 目标 HP% **< 60%** | **需 `SP ≥ 4`** |
| 留余量 | 治完**保留 ≥ 2 点** | **= 留够"一次保命"的量**（不是"留 1 点"） |
| 增援门槛 | **SP ≥ 2** 且存在战斗位【虚弱】者 | 增援同为 −2 |
| 攒点 | **无危机时一分不花** | 只做不消耗 SP 的事 |

**判定顺序（每回合，按序取第一个成立的）**：

```
① 保命   有单位 HP% < 30% 且支援位军医【急救】可用 且 SP ≥ 2   → 花 2 点（可花到 0）
② 救崩溃 有战斗位单位【虚弱】且支援位有健康者 且 SP ≥ 2         → 花 2 点增援换下（#176 意图保留，加 SP 门槛）
③ 续航   有单位 HP% < 60% 且 SP ≥ 4                          → 花 2 点（保留 ≥2）
④ 士气   有单位士气 < 20 且政委【战场鼓舞】可用                 → 直接做（士气类不消耗 SP）
⑤ 攒点   以上都不成立                                        → 支援位只做不消耗 SP 的事；
                                                              若此时没有任何可用行动 → 【待命】
```

🔴 **分级消费原则（本节的核心）**：

> **紧急用途（保命 / 救崩溃）可花到 0；非紧急用途（续航）必须留够一次应急储备。**

**设计意图**：
- **平时攒、危急花** —— 这正是"恢复制 vs 配额制"想要的那个决策
- ② 保留了 #176「把虚弱者换下来」的战术意图，但**加了 SP 门槛** → 变成"值不值得花 2 点"

### S5.1a 🔴 一个必须写清的分析：`regen(1) < cost(2)` 的含义

```
长期平均支援技能频率【恒为 0.5 次/回合】—— 与"保留"政策无关。
```

→ **"留余量"不改变总量，只改变【时机分布】**。它的价值是**保住应急能力**，**不是"省着用"**。
不写清这点，日后会有人误读成"留余量是为了省 SP"。

### S5.1b 为什么未采纳架构侧的两个候选（O-61 裁定记录）

| 候选 | 问题 |
|---|---|
| ① 续航门改 **`SP ≥ 3`**（花 2 留 1） | 🔴 **"留 1 点"在 `cost=2` 下毫无意义**——1 点买不了任何东西，是**空头储备** |
| ② 允许降到 0、删掉"保留 ≥1" | ⚠️ 规则自洽，但**放弃"给保命留储备"的设计意图**——保命是**时间敏感**的（等 2 回合可能人就死了） |

✅ **采纳第三方案（`SP ≥ 4` / 保留 ≥2）**，而且它**同时更削**（已算）：

| 续航门 | 8 回合内能做几次 | 储备 |
|---|---|---|
| `SP ≥ 3` | **5 次** | 留 1 点（空头） |
| **`SP ≥ 4`** | **4 次** | 留 2 点（真储备）→ **既保住应急、又多削 20%** |

## S5.2 ⚠️ 连带：需要「待命（Pass）」这个流程动作

**SP 耗尽 + 支援位技能全在 CD 中 → 支援位单位无事可做。** 现在流程里没有"什么都不做"的出口 → 会卡住。

| 项 | 规格 |
|---|---|
| 动作 | **「待命」**——显式结束该单位本次行动（不消耗 SP、不算技能） |
| 入口 | 支援位单位行动时，技能栏旁一个「待命」按钮 |
| 与 #189 的关系 | **不冲突**：#189 管"技能必须点选目标"；待命**不是技能**，是"放弃本次行动" |
| 归属 | 建议**全体单位都可用**（战斗位也常在"打不动/不值得打"时想跳过）——但**这条要策划另判**（见 §S5.5） |
| 日志 | 记为 `TurnSkippedEvent(Reason: passed)`（`logging.md` §3.1 已有该事件） |

## S5.3 复测必出的行为统计（用来区分"变难"与"变笨"）

| 统计 | 期望 | 用途 |
|---|---|---|
| **SP 存量分布** | 应在 0~4 间波动，不应长期贴 0 或贴 4 | 判断"平时攒、危急花"是否生效 |
| **SP 花费分布**（治疗 / 增援） | 两者都非零 | 判断用途是否合理 |
| **支援位技能次数** | ~15.8 → **~7.9（−50%）** | 验证 SP 真的在限流 |
| **增援次数** | **应下降**（变贵了） | 🔴 若骤降到 0 → 说明策略"变笨"（不敢换人），而非游戏变难 |
| **待命（Pass）次数** | 新增统计 | 若过高频 → **支援位"没事做"是一个设计信号**（不是策略问题） |

> 🔴 **关键区分**：增援次数下降有两种解释——① **SP 性价比**（合理：2 点换一次换人，不值）② **策略退化**（不合理：门槛设太死）。
> **必须用"SP 花费分布"来判定**：若 SP 大量花在治疗而增援为 0，且治疗也没解决问题 → 是 ②。

## S5.4 验收

| 用例 | 期望 |
|---|---|
| 保命优先 | 构造 HP% 25% 的单位且 **SP = 2** → **花 2 点**治疗它 |
| 🔴 保命买不起 | 构造 HP% 25% 的单位且 **SP = 1**（< 2）→ **不治疗**，走 ⑤ 攒点（**不得**试图花 2 点） |
| 增援门槛 | SP = 1 时构造战斗位虚弱者 → **不增援**；SP ≥ 2 → 增援（−2） |
| 🔴 留余量（**已按 #215 改**） | 续航分支**仅当 `SP ≥ 4`** 触发；治疗后 `SP = SP − 2 ≥ 2`（**留够一次保命**） |

| 攒点 | 无危机时 → SP **不下降**（只做士气类） |

# S7 · 参数压一档（#213）：`cost_skill 1 → 2`

> 判据 A 落地后仍 **100%** → 按 §S3 顺序取**第 ① 步**。**只改一个数**：

| 参数 | 现值 | 改为 |
|---|---|---|
| **`cost_skill`** | 1 | **2** |
| `regen_per_round` | 1 | **不动** |
| `cap` | 4 | **不动** |
| `cost_reinforce` | 2 | **不动** |

**稳态（起手 3 / 每回合 +1 / 钳 4 / 技能 −2）**：

| 回合 | R1 | R2 | R3 | R4 | R5 | R6 | R7 | R8 |
|---|---|---|---|---|---|---|---|---|
| SP（回合开始） | 4 | 3 | 2 | 1 | 2 | 1 | 2 | 1 |
| 可做技能 | ✅ | ✅ | ✅ | ❌ | ✅ | ❌ | ✅ | ❌ |

→ **8 回合 5 次**（0.63 次/回合）；现状 8 次（1 次/回合）→ **−37%**（一档，非过冲）。

## S7.1 🔴 明确否决的替代项：`regen_per_round 1 → 0`

**否决**：它把**恢复制退化成配额制**——抽掉 #211 的设计精髓。
`regen=0` 后玩家开局 3 发打完，**支援位永久瘫痪**；决策从"每回合用不用"退化成"什么时候用光"。
（#211 原文：「固定次数是**配额**，用完就废；恢复制是**节奏约束**，现在用还是攒着」。）

## S7.2 ⚠️ 设定修正：`增援` 不再"比技能重"

#211 原写「增援 −2 ＝ 调动一个人比放一个技能重」。
`cost_skill = 2` 后**两者同价** → 该表述作废。**新表述（更好）**：

> **技能与增援同价（都 2 点）→ "治疗"与"换人"是【同价竞争】**，
> 玩家必须在"救一个伤员"和"换一个虚弱者下场"之间做**等价取舍**——比"增援更贵"时更清晰。

## S7.3 🔴 复测必须新增统计 `E`（敌方每回合对我方总伤害）

| 统计 | 用途 |
|---|---|
| `D`（已有） | 我方每回合对敌总伤害 ＝ **20.81** |
| **`E`（新增，本次强制）** | 敌方每回合对我方总伤害 → **难度的另一半** |

**为什么强制**：难度的本质是**双方输出的比值**；我们**只有 D 没有 E** → 判断"够不够难"只能靠估算，
而策划**已两次估错 D**（先 24、后 35，实际 20.81），并因此让 **#195 的降 HP 决策建立在错数上**。**不能再犯第三次。**
**有了 E 就能直接算**：

```
玩家会不会死  ⟺  E × 回合数  ≥  我方裸HP(232) + 自愈量
```

## S7.4 后续顺序（登记，见 `state.md` #214）

```
① cost_skill 1→2 + 复测（必须输出 E 与 SP 花费分布）
   → 胜率落 [40,70] → 收口

   → 仍 >70% → ③ 数值（预置：急救 12→8、群体绷带 5→3；剂量待 E 与 KPI 定）
```

> 🔴 **③ 大概率必须做**：**结构上 SP 对总治疗的削减封顶 −50%**（另一半来自战斗位军医 slot 4，按 #211 要求不受 SP 约束）。
