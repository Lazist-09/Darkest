## S0 · 规格

```
【支援点 SP】

· 起手 3；每回合开始 +1；上限 4
· 消耗：
    支援位（5/6）单位使用技能        →  −1
    我方增援（Reinforce，把支援位角色调动上场） →  −2
· 不消耗：
    战斗位（1~4）单位使用技能
    被动效果（支援位每回合回士气 +3）
    撤退
· 点数不足 → 该行动【灰显不可用】+ tooltip：支援点不足（当前 N / 需要 M）
· UI：常驻显示剩余 SP（含本回合恢复预览）
```

| 参数 | 起手值 | 说明 |
|---|---|---|
| `start` | **3** | 前 2 回合可爆发（各 2 次支援行动） |
| `regen_per_round` | **+1** | 与"支援位 2 个单位"形成稳态 **1 次/回合**（现为 2） |
| `cap` | **4** | 防长攒爆发；允许 ≈2 回合的小额蓄力 |
| `cost_skill` | **1** | 支援位技能 |
| `cost_reinforce` | **2** | 增援——**调动一个人比放一个技能重** |

> 🔴 **为什么是「随回合恢复」而不是「每场固定次数」**：固定次数是**配额**（用完就废）；
> 恢复制是**节奏约束**（现在用还是攒着）→ **每回合都产生一个小决策**。
> **旋钮 = `regen_per_round` 与 `cost_skill`**（都只改一个数）。

| 项 | 估算 |
|---|---|
| 支援位行动 | 2 次/回合 → **稳态 1 次/回合** |
| 支援位技能总次数 | ~15.8/场 → **~7.9（−50%）** |

# S5 · 🔴 策略侧必改：SemiRandom 必须学会分配支援点（#212）

> **为什么必须一起做**：SP 引入后，**唯一会立即失灵的既有策略就是 SemiRandom**——
> 它现在会**无条件地**花 SP（支援位技能照放、虚弱者照换）。
> 若不同步改策略，复测出来的胜率会**混入"策略变笨"的成分**，而不是"数值变难"——
> **这正是我们已经踩过 3 次的坑**（#177 换位增援口径 / O-38 目标语义 / O-42 策略质量）。
>
> 🔴 **契约（承接 #183）**：**SP 花费必须有目的，禁止无条件随机花**；未改完前的胜率不作验收依据。

## S5.1 策略规格（规则化、可解释）

**阈值（起手值）**：

| 项 | 值 | 说明 |
|---|---|---|
| 保命线 | 目标 HP% **< 30%** | 触发治疗 |
| 续航线 | 目标 HP% **< 60%** | 触发治疗（需 SP ≥ 2） |
| 留余量 | 治完保留 **≥ 1 点** | 除非走"保命"分支 |
| 增援门槛 | **SP ≥ 2** 且存在战斗位【虚弱】者 | 增援是 −2 |
| 攒点 | **无危机时一分不花** | 只做不消耗 SP 的事 |

**判定顺序（每回合，按序取第一个成立的）**：

```
① 保命   有单位 HP% < 30% 且支援位军医【急救】可用           → 花 1 点治它
② 救崩溃 有战斗位单位【虚弱】且支援位有健康者 且 SP ≥ 2        → 花 2 点增援换下（#176 的意图保留，但加 SP 门槛）
③ 续航   有单位 HP% < 60% 且 SP ≥ 2                          → 花 1 点治它（保留 ≥1）
④ 士气   有单位士气 < 20 且政委【战场鼓舞】可用                → 直接做（士气类不消耗 SP）
⑤ 攒点   以上都不成立                                        → 支援位只做不消耗 SP 的事；
                                                              若此时没有任何可用行动 → 【待命】
```

**设计意图**：
- **平时攒、危急花** —— 这正是"恢复制 vs 配额制"想要的那个决策
- ② 保留了 #176「把虚弱者换下来」的战术意图，但**加了 SP 门槛** → 变成"值不值得花 2 点"

## S5.2 ⚠️ 连带：需要「待命（Pass）」这个流程动作

**SP 耗尽 + 支援位技能全在 CD 中 → 支援位单位无事可做。** 现在流程里没有"什么都不做"的出口 → 会卡住。

| 项 | 规格 |
|---|---|
| 动作 | **「待命」**——显式结束该单位本次行动（不消耗 SP、不算技能） |
| 入口 | 支援位单位行动时，技能栏旁一个「待命」按钮 |
| 与 #189 的关系 | **不冲突**：#189 管"技能必须点选目标"；待命**不是技能**，是"放弃本次行动" |
| 归属 | 建议**全体单位都可用**（战斗位也常在"打不动/不值得打"时想跳过）——但**这条要策划另判**（见 §S5.5） |
| 日志 | 记为 `TurnSkippedEvent(Reason: passed)`（`logging.md` §3.1 已有该事件） |

## S5.3 复测必出的行为统计（用来区分"变难"与"变笨"）

| 统计 | 期望 | 用途 |
|---|---|---|
| **SP 存量分布** | 应在 0~4 间波动，不应长期贴 0 或贴 4 | 判断"平时攒、危急花"是否生效 |
| **SP 花费分布**（治疗 / 增援） | 两者都非零 | 判断用途是否合理 |
| **支援位技能次数** | ~15.8 → **~7.9（−50%）** | 验证 SP 真的在限流 |
| **增援次数** | **应下降**（变贵了） | 🔴 若骤降到 0 → 说明策略"变笨"（不敢换人），而非游戏变难 |
| **待命（Pass）次数** | 新增统计 | 若过高频 → **支援位"没事做"是一个设计信号**（不是策略问题） |

> 🔴 **关键区分**：增援次数下降有两种解释——① **SP 性价比**（合理：2 点换一次换人，不值）② **策略退化**（不合理：门槛设太死）。
> **必须用"SP 花费分布"来判定**：若 SP 大量花在治疗而增援为 0，且治疗也没解决问题 → 是 ②。

## S5.4 验收

| 用例 | 期望 |
|---|---|
| 保命优先 | 构造 HP% 25% 的单位 → **必花 1 点**治疗它 |
| 增援门槛 | SP = 1 时构造战斗位虚弱者 → **不增援**（SP 不足）；SP = 2 → 增援 |
| 留余量 | 续航分支治疗后 SP ≥ 1 |
| 攒点 | 无危机时 → SP **不下降**（只做士气类） |
| 待命 | SP = 0 且技能全 CD → **待命**，流程不卡死 |
| 确定性 | 同 seed 同结果（策略不得引入新随机） |
| 无随机花 SP | 构造 SP = 4 → **不会**为了花而花 |

## S5.5 待策划另判（登记，不在本包实现）

| 议题 | 说明 |
|---|---|
| **「待命」是否给全体单位** | 现在只有支援位会"无事可做"；但战斗位在"打不动"时也可能想跳过。**给全体 = 增加一个"放弃行动"的战术选项**（可能被滥用为"故意拖延"——需与 #198 的弹性增援判定对齐）；**只给支援位 = 更保守**。**建议先只给支援位**，复测后再评估 |
