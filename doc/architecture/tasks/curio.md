## §1 片① 内核：`ResolveCurio`（**零 Godot**）

### 1.1 接口

```
ExpeditionSession.ResolveCurio(
    string roomId,        // 房间（拓扑模式）或步骤（线性模式）
    string heroId,        // 【哪个英雄去碰】—— DD 原文⑤：只影响【当前选中的那个】 ✅
    string? itemUsed)     // null = 空手；否则 = 道具 id（firewood / food / support_pack）
  → CurioOutcome
```

### 1.2 三条路径（**缺一不可**）

| 路径 | 行为 | 随机 |
|---|---|---|
| 🔴 **空手** | 走 `bare_hands` 结果表 | 🔴 **必写 `RngDraw`** |
| 🔴 **用道具** | 走 `item_results[itemUsed]` | 🔴 **不掷骰 ⇒ 不写**（**确定结果**） |
| **走开** | **什么都不发生**（`CurioOutcome.Skipped`） | 不写 |

### 1.3 硬要求

| # | 要求 |
|---|---|
| **①** | **道具路径必须【确定】**（**不得有概率**）—— 那是 Curio 的灵魂（DD 原文） |
| **②** | **"用错道具"也要有确定结果**（可能坏）—— 至少一个 Curio 如此（**骸骨堆 + 口粮 ⇒ 100% −10 士气**） |
| **③** | 🔴 **结果必须带【描述文本】**（不是"获得 2 个口粮"，而是"箱子里有腌肉…"） |
| **④** | 🔴 **不消耗未列出的道具**；**道具不在 `item_results` 里 ⇒ 拒绝 + 不扣**（照 `StressRelief` 的"不足即拒绝且不扣"同一纪律） |
| **⑤** | **结果写事件**（`CurioResolvedEvent`：roomId / heroId / itemUsed / result / 描述） |

## §2 片② 数据：`curios.json`（6 个，占位数值）

### 2.1 结构（照 `curio.md` §3 的 6 个）

```jsonc
{
  "curios": [
    {
      "id": "cur_supply_crate",
      "name": "补给箱",
      "curio_type": "treasure",              // 类型标签（DD 用于「强制交互」匹配）
      "bare_hands": [
        { "weight": 60, "result": { "food": 2 }, "text": "箱子里有腌肉，够吃一阵。" },
        { "weight": 40, "result": {},           "text": "箱子只剩碎木屑。" }
      ],
      "item_results": {
        "firewood": { "result": { "firewood": 2, "food": 1 },
                      "text": "点燃火把，看清了箱底——还有柴火！", "placeholder": true }
      }
    }
    /* … 其余 5 个 … */
  ]
}
```

### 2.2 校验（**新 P 号，建议 P26**）

| # | 校验 |
|---|---|
| **①** | `bare_hands` **权重和 = 100**（或至少 > 0） |
| **②** | 🔴 **`item_results` 的每个条目【不得含概率字段】**（否则破坏"确定"语义） |
| **③** | 🔴 **至少一个 Curio 存在"确定坏结果"的道具条目**（`curio.md` §3 检查②） |
| **④** | **道具 id 必须在【已知补给品】白名单里**（`firewood` / `food` / `support_pack`） |
| **⑤** | **`placeholder` 字段存在性可查**（**冻结期要求：至少一个数值标占位**） |
| **⑥** | **每个 result 必须有 `text`**（非空） |

## §3 片③ UI：进房间 ⇒ 物件 + 三按钮

### 3.1 排布

```
【房间：书堆】
  一堆发霉的旧书靠在墙边，纸页被风翻动。

  [ 空手翻看 ]      [ 用道具 ▾ ]      [ 走开 ]
      ↑ 有概率            ↑ 确定结果        ↑ 什么都不发生
```

| 件 | 要求 |
|---|---|
| **名称 + 描述** | **先给"物件的样子"**（DD 式叙事），再给按钮 |
| 🔴 **三个按钮** | **空手** / **用道具 ▾**（下拉：**只列该 Curio 有 `item_results` 的道具**）/ **走开** |
| 🔴 **道具下拉只列【已实现且有效】的** | **红线 21**：不得列出"点了没反应"的项 |
| 🔴 **玩家不知道"哪个道具对"** | ⚠️ **这是设计要点**：**不提示正确答案**（DD 也是这样）⇒ 玩家靠**试/记** |
| **结果展示** | **显示 `text` + 实际变化**（金钱/士气/光照/疾病…） |
| **走开** | **无任何变化**（且**不阻塞通行**，DD 原文①） |
| 🔴 **真实 `Pressed`** | 三个按钮 + 下拉项 **全部走真实信号**（红线 18/26） |

## §4 片④ 验收 V1~V7（**功能级 —— 红线 26**）

| # | 断言 | 方式 |

| **V1** | **Curio 在房间里可见、可交互** | **走玩家路径**：选路 ⇒ 进房间 ⇒ 出现物件 ✅ |
