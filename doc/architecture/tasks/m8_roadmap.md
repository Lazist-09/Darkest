## §0 两步收尾（🔴 **可立即开工**）

### 0.1 `ProbMod` 的显式标注（**按 `#290` 更正后的规则**）

```
🔴 "死声明"的判据不是"有没有集中消费点"，
   而是【有没有人真的会读它】
```

| 项 | 内容 |
|---|---|
| **事实（已核实）** | `prob_mod` **数据里确实在用**（恐惧/自私/失控/两种美德/死门后遗症）；消费**按 `effect` 名走专用通道**（`refuse_*`/`randomize_attack_target` 在 `AfflictionProcs`；`crit_bonus`/`hit_mod`/`deaths_door_resist_bonus` 在各自结算处） |
| **要做的** | 在 `BuffDefsConfig` 写**显式标注 + `effect` 名对照表**（注释已拟好，需用**文件工具**先读再改） |
| 🔴 **要防的真问题** | **新增 `effect` 名但没人实现** ⇒ **对照表就是防线**（新增名时必须在表里登记消费点） |
| **验收** | 表里每个 `effect` 名都能指出**消费点文件**；无"表里没有的名字" |

### 0.2 特质幅度的**读数口径**（**不是判红**）

```
现状读数：特质 +10% ⇒ 全队伤害合计 130；0% ⇒ 126；−10% ⇒ 125
🔴 相邻差只有 ~3% 与 ~0.8% —— 而那是【全队合计】，只有一人带特质 ⇒ 【被 6 人摊薄】
⇒ 它证明"接上了"，但【不反映玩家感知】
```

| 项 | 内容 |
|---|---|
| **要做的** | 补报 **【带特质者自己的伤害差】**（单人对单人的读数） |
| **为什么要** | 🔴 若他一人只差 3% ⇒ **玩家感受不到** ⇒ 那是 **`#283` 7.7「小幅特质」的数值问题** |
| **判据** | `#283` 7.7 的幅度定义是 **`伤害 ≤15%`** —— **上限定得不小，但【实际生效值】请一并报** |
| **验收** | 报告里能回答"**一个 +10% 特质的英雄，他自己的伤害比无特质高多少 %**" |

## §1 M8.1：传家宝 + 建筑升级（**下一个大块**）

### 1.1 规格（照抄 DD 两条轴）

```
🔴 DD 的升级有两轴（`hamlet.md` §1 五条关键设计 ⑤）：
   ① 降低费用（服务更便宜）
   ② 解锁更高阶（能买到更强的）
⇒ 🔴 不只是"变强"，还有"变便宜" ⇒ 让"升级"这件事本身有梯度
```

### 1.2 传家宝（DD 四种）

| 传家宝 | DD 用途 |
|---|---|
| **Busts** | Abbey · Sanitarium · Stage Coach（等级上限） |
| **Crests** | **几乎所有建筑**（最通用） |
| **Deeds** | Blacksmith · Stage Coach（名额） |
| **Portraits** | Guild · Tavern · Sanitarium |

🔴 **DD 的规律**：**每个建筑固定需要同样几种传家宝，但数量递增** ⇒
**那是"长期投入曲线"的载体**（玩家知道该攒什么，但永远不够）✅

### 1.3 我们要做什么（**M8.1 的最小版**）

| # | 内容 |
|---|---|
| **① 传家宝作为第三种资源** | 从**光照档掉落**（与金钱同源）；**四种**（照抄 DD 的名字或自己命名） |
| **② 建筑升级** | **两轴**：降费 / 解锁更高阶；**每级消耗固定几种传家宝、数量递增** |
| **③ 首批可升级的建筑** | 🔴 **只做已在 M8.0 存在的**：**Tavern / Abbey（降费 + 提高恢复量）** · **Stage Coach（提高名册上限 / 新兵起始等级）** |
| 🔴 **④ 暂不做** | Blacksmith（装备）· Guild（技能升级）· Sanitarium（怪癖/疾病）—— **它们各自依赖 M8.2/M8.3 的子系统** |

### 1.4 验收（M8.1）

| 项 | 判据 |
|---|---|
| **传家宝可获取** | 与**光照档**挂钩（越暗越多，与金钱同源）|
| **升级真的改变数字** | 升级前后：**费用下降 / 恢复量上升**（可观测）|
| **两轴都在** | 至少**一个建筑**能验证"降费"，**一个**能验证"解锁更高阶" |
| 🔴 **升级有代价** | 传家宝**稀缺**（不能一次全升满）⇒ 存在"**先升哪个**"的决策 |
| **红线 18/21** | 升级入口**从启动场景可达** · 按钮**初始状态确实可用** |

## §4 M7.6：地牢「房间 + 走廊」地图（**与 M8 并列的独立里程碑**）

### 4.1 为什么它独立

```
M8 = 【局外】（回城、养成、经济）
M7.6 = 【局内】（地牢的拓扑结构）
⇒ 两者互不依赖，可并行或任选先后 ✅
```

### 4.2 与现状的差距（`#281` 已定）

| | DD | 我们（M7.5 现状） |
|---|---|---|
| **结构** | 🔴 **房间 + 走廊的地图**（可绕行 / 回头 / 死路） | **线性 6 节点** |
| **侦察** | 侦察**揭示地图**（看到前方拓扑与危险） | 只揭示"下一节点类型" |
| **移动** | 按段计，**重走已探索区更便宜**（−1 vs 新区域 −6） | 每节点固定 −30 |
| **奇物 Curio** | 有（可交互对象） | 无 |

### 4.3 M7.6 要做的（草案）

| # | 内容 | 说明 |
|---|---|---|
| **① 地图生成** | **房间 + 走廊**的图（**写 `RngDraw`**）；节点数 = 6~8 房间 | 保留现有"6 步"的节奏感 |

