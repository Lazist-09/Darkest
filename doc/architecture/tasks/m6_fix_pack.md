## P0.2 规格

**① 胜负分别判定**——导演侧新增结果投影：

```
BattleOutcome { Ongoing, Victory, Defeat }
  if (Player.OccupiedPositions(false).Count == 0) → Defeat     // ★ 我方优先判负
  else if (Enemy.OccupiedPositions(false).Count == 0) → Victory
  else → Ongoing
```

- 🔴 **我方优先判负**（同瞬间双方归零 → 判负）：本作是**硬核受苦**定位，"活下来才算赢"。
  ⚠️ 此优先级是**策划可调项**——若实机觉得"同归于尽算赢"更爽，改判序即可（登记后调）。
- `IsBattleOver` 保留为 `Outcome != Ongoing` 的别名，**不破坏既有测试语义**。

**② 即时收束**——任一方归零后**立即终止**本回合剩余行动：

- 实机（`BattleRoot._Process`）：每轮推进**先查 Outcome**，非 Ongoing → 立即 `EndGame`（对应胜/负文案）。
- headless（`RunFullRound`）：`while (!IsBattleOver)` 已满足，**但需补一条测试**锁住"胜负后不再有行动"。

**③ 结果文案**：`胜利：敌方全灭` / **`失败：我方全灭`** / `撤退成功` / `撤退失败`。

**④ 结算面板（最小版，建议进切片）**：

- 复用状态栏区域，做一个**文本面板**即可（**不做美术级界面**）。
- 必显示：**结果** + **回合数** + **7 项系统触发计数**（士气触底 / 虚弱 / 死门 / 撤退 / 美德 / 折磨 / 位移）+ `按 R 重开`。
- 理由：这些数字**现在已算好**（`EndGame` 内已统计，只 print 了），而 M6-07 手感评测的试玩报告**正需要它们**——不显示就得让试玩者去翻控制台。

# P1 · 敌人目标选择（O-46 ← #185/#186/#187）

## P1.1 现状缺陷

`EnemyAi.ResolveTargets`（`EnemyAi.cs:160-182`）返回**槽升序候选全池** → `BattleDirector.EnemyAct`（`:192`）只取 `TargetSlots[0]` → `SkillExecutor:71-93` 取"chosenTargets 中第一个仍在候选内的" = **槽号最小** = **我 1 位 = 坦克**。

实测每回合：近战A→我1、近战B→我1、射手→我1、施法者→我1(+我2)。**军医/政委几乎从不被打。**

## P1.2 规格（三层，按序判定）

```
池内选一：
① 若 taunt 生效且嘲讽者在候选池内 → 【概率优先】加权抽取
     嘲讽者权重 = taunt_weight（起手 3），其余每个候选权重 = 1
     → 池内 2 人 P=75% / 3 人 60% / 4 人 50%
② 否则按【原型固定偏好】target_preference：
     lowest_hp      近战小兵 → 池内【当前 HP 最低】（平局取槽号小）
     backmost       远程射手 → 池内【槽号最大】（点后排）
     lowest_morale  施法者　 → 池内【士气最低】（平局取槽号小）
③ 兜底 → 槽号最小
```

**边界（必须逐条实现）**：

| 情形 | 行为 |
|---|---|
| 候选池只有 1 个 | 直接选它，**不掷骰、不写 RngDraw**（避免无意义抽取破坏确定性基线） |
| 候选池为空 | 技能不可用（既有逻辑，不新增抽取） |
| **AOE 技能**（精神震荡） | **不受本节影响**，命中池内**全部**（沿用 `IsAoe` 判定） |
| taunt 是池内唯一候选 | 100% 打它（走"唯一候选"分支） |
| taunt 生效但嘲讽者**不在**池内 | 忽略 taunt，走偏好② |
| 多次 taunt / 多个嘲讽者 | 按"嘲讽者在池内"逐个给 ×3 权重（切片只有坦克会嘲讽，不额外复杂化） |

**确定性要求（红线）**：

- taunt 加权抽取**必须写 `RngDraw` 日志**（`_log.Append(new RngDraw(...))`），与 `SkillExecutor:89` / `PlayerRetreat:273` 同规格，保证**同 seed 可复现**与回放一致。
- 抽取走既有 `IRngProvider`，**不得**引入 `System.Random` 或时间源。

## P2.2 规格（四条启发式）

**① 选目标（输出技能）**：候选池内取**当前 HP 最低**的敌人（收残）；平局取槽号小。

**② 移动条件化**（不满足任一 → **从策略池中剔除「移动」**）：

```
仅当下面任一条成立才允许把「移动」纳入选择：
  a. 当前位置下【可用输出技能数 == 0】（被推到坏位）
  b. 自身虚弱 且 处在战斗位（考虑换下——但优先走增援，见④）
  c. 存在一次移动能【增加可用技能数】（移动后可用技能数 > 当前）
否则：移动不进池（权重视为 0）
```

> 起手实现可先做最保守版：**默认不移动**，仅在 (a) 成立时使用。先让"移动使用率"降下来，再看复测。

**③ 治疗 / 增益目标**：选**最低 HP%** 的友方；**若全体满血 → 不使用治疗**（不浪费行动）。

**④ 增援战术意图**（保留并明确既有 `SwapSupportNeeded`，`Policies.cs:141-172`）：

```
优先级：战斗位有虚弱者 → 用健康支援位换下（优先军医 / 政委）
追加：战斗位有 HP% < 30% 者 且 支援位有军医 → 拉起
护栏：同回合至多 1 次（既有）
```

**⑤ 控制 / 位移技能目标**：池内取"对己方威胁最高者"——**切片简化版 = 攻击力最高的敌人**；平局取槽号小。
