## 0. 里程碑目标（一句话）

**走通「受伤 → 虚弱 → 死门 → 死亡 / 靠齐」全链，且只被精神伤害掉士气（#157）。**

- 对应蓝图 M4 验收判据（blueprint §11）：走通上述全链 + 物理不掉士气。
- 对应 GDD §3 与 modules 士气 / buff / 生存三块，唯一交付物为本里程碑任务卡集。
- 敌方单位无士气 / 虚弱 / 死门，不套本状态机（enemy §1 / blueprint §5c）。

### T-M4-01 MoraleLedger（士气台账）
- **上游**：[设计] morale.md §1/§2；combat_math.md §5.1/§5.2 · 决策：#157, #104, #151, #155
- **依赖**：T-M2（DamagePipeline）、T-M3（导入 morale_events.json / tuning.json）
- **产出**：`res://scripts/gameplay/sim/morale/MoraleLedger.cs`（blueprint §9.4 `IMoraleLedger`）；`res://data/morale_events.json`（14 行全量）；`res://data/tuning.json`（`morale` / `weak` 段）；`res://tests/MoraleTests.cs`
- **要点**：
  1. 士气范围 **[0,100]**、起手 **50**、钳制（tuning `morale`），任何加减不越界；派生「士气事件」不入 units.json（data_schema §2.2）。
  2. **唯一写入口** = `MoraleLedger.Apply(unit, delta, source)`（事件驱动）：UI / 飘字 / 日志只**订阅 MoraleChanged 事件**，禁止旁路直改士气（blueprint §6.2）。
  3. 增减表 **14 行全量**逐字落 morale_events.json（data_schema §3.3，P9 校验缺失即阻断）：物理 **0**（#157）/ 精神 **-8** / 精神暴击 **-12** / AOE 精神 **-5/目标** / 暴击 **+5** 全队 / 击杀 **+10** 全队 / 队友虚弱 **-8** 全队 / 队友死亡 **-15** 全队 / 支援位 **+3** / 战场鼓舞 **+15** 单目标 / 士气满 **+10** 全队（一次性）/ 撤退成功 **-10** / 撤退失败 **-5** / 虚弱受伤 **-5**（每回合≤1）。
  4. **物理不掉士气**（#157）；**唯一例外** = 虚弱状态下受任意伤害仍 -5，每回合最多 1 次（morale_events `weak_hit_any_damage` occurrence `once_per_turn_max1`）。
  5. 精神暴击 **-12** 覆盖同一次伤害的 **-8**（`mental_crit_hit` 覆盖 `mental_hit`）。
  6. 事件顺序：**先伤害 → 再士气 → 再虚弱/死门**（combat_math §5.2）。
- **完成判据（可测）**：
  - 钳制用例：`Add(-1000)→0`、`Add(+1000)→100`、起手 `=50`。
  - 物理攻击命中 → 士气**不变**；精神命中 `-8`、精神暴击 `-12`、AOE 精神每目标 `-5`。
  - 全队性事件（暴击/击杀/队友虚弱/死亡/撤退）按 O-14 聚合口径实现，可用事件日志断言。
  - `Apply` 为唯一写入口：单测 / 静态检查断言「UI 直改士气」被禁（blueprint §6.3）。
- **风险/开放**：O-14（全队性事件聚合口径）、O-03（虚弱受伤 -5 保留任意类型，可推翻）。

### T-M4-02 崩溃判定（事件触发）
- **上游**：[设计] morale.md §4/§4.0/§8.1；GDD §3.2；combat_math.md §6 · 决策：#67
- **依赖**：T-M4-01、T-M4-03/04（判定产物）、T-M2（HP 归零管线）
- **产出**：`MoraleLedger.RollCollapse` 触发点、`IsCollapseEmber`、unit_state `CollapseEmber`（tuning `collapse.proc`）；`res://tests/MoraleTests.cs`
- **要点**：
  1. 判定由**【事件】触发非【状态】触发**：仅「士气从 **>0 降到 0**」这一下降事件触发判定（#67，GDD §3.2「已停在 0 时挨打不重复判定」）。
  2. 停在 0 = **崩溃余烬（CollapseEmber）**：余烬期间无论挨多少打都不再触发判定（morale §4.0）。
  3. **HP 归零也立即触发一次判定**（combat_math §6），随后同样留在 0；若士气已在 0（余烬）→ 仍走 HP 归零判定**一次**，须去重不重复判定（正交组合见 T-M4-09，O-18）。
  4. 判定产物：**大概率折磨 / 小概率美德**（RollCollapse，见 T-M4-03）；判定后**士气留在 0**（#67，§8.1 已裁决）。
  5. 折磨结束点 **==** 恢复判定资格点（士气回 50），无需额外计时器/标记位（morale §4.0）。
- **完成判据（可测）**：
  - 用例：士气 10 → 精神伤害 -8 → 降到 0 → **恰好触发 1 次**判定；判定后士气 `=0`。
  - 用例：已在 0（余烬）→ 再受物理/精神伤害 → **不再**触发判定（除 HP 归零分支）。
  - HP 归零同时刻士气跨 0：**只判定一次**（去重）。
- **风险/开放**：O-18（崩溃判定 × 虚弱正交闭环组合场景 → T-M4-09 用例表）。

### T-M4-03 崩溃掷骰：折磨 / 美德
- **上游**：[设计] morale.md §4/§4.1/§5/§5.1/§6/§10 · 决策：#56, #68（美德率）、#57（33%）、#61（恐惧不耗行动）、#54（失控战斗位随机攻击）、#48（支援位失控→捆缚）、#28（不设保底）
- **依赖**：T-M4-02、T-M3（韧性属性 / buff 定义）
- **产出**：`MoraleLedger.RollCollapse` 实现；`res://data/buff_defs.json`（`affliction_*` / `virtue_*`）；`res://data/tuning.json`（`virtue_rate` / `affliction_proc_percent` / `collapse`）
- **要点**：
  1. 美德率 = **10% + 韧性 ÷ 2**（派生量不入库，data_schema §2.2）：掷骰 `rand(0,100) < 美德率` → 美德，否则折磨（blueprint §8.2 崩溃判定调用点）。
  2. **不设保底**：连续折磨完全可能（#28）。
  3. 折磨池 **3**：**恐惧**（用技能前 33% 拒放、**不消耗行动**、技能灰掉必须重选 #61）/ **自私**（被治疗/鼓舞前 33% 拒绝这一次）/ **失控**（攻击时 33% 换目标）。
  4. **失控**：战斗位**保留随机攻击**（#54，可能打到战斗位队友）；**支援位**触发改为「**捆缚**」无法行动（#48）。
  5. 统一概率 **33%**（tuning `affliction_proc_percent`，#57）。
  6. 折磨降死门抗性 **-10%**（#123，由 `IDeathsDoor` 读取，见 T-M4-06）。
- **完成判据（可测）**：
  - 美德率复算（morale §4 样例）：韧性 30 → **25%**、60 → **40%**、100 → **60%**；掷骰对照 `rand` 值可复现。
  - 33% 触发复算：恐惧/自私/失控在对应动作按 `rand<33` 触发；恐惧拒放**不消耗行动**。
  - 支援位失控 → 产生「捆缚」而非随机攻击。
  - 无保底：连续 N 次折磨不强制插入美德。
- **风险/开放**：O-27（美德池范围，见 T-M4-04）；失控换目标可能打队友为设计风险（morale §5.1 风险记录）。

### T-M4-04 折磨 / 美德状态生命周期
- **上游**：[设计] morale.md §4.0/§6/§8；buff.md §5/§6 · 决策：#94（美德不叠层上限 1）、#123（折磨 -10%）
- **依赖**：T-M4-03、T-M3（IBuffLedger）
- **产出**：`res://data/buff_defs.json` 生命周期字段（`until_morale_50` / `until_battle_end_or_morale_zero`）；`IBuffLedger` 挂 / 摘；`res://data/tuning.json`（`collapse.virtue_pool`）
- **要点**：
  1. **折磨**持续到该角色士气回到初始值 **50**；结束点 == 恢复可判定资格点（morale §4.0）。
  2. **美德**持续到**战斗结束** 或 **士气再次归 0**（先到为准，morale §8）。
  3. 美德**上限 1、不叠层**（#94）：已有美德再得 → **保留旧美德**，只结算全队 +10（#100，见 T-M4-05）。
  4. 美德中士气再归 0 → **消除美德 buff** → 士气回 50 → **重新走崩溃判定**（morale §8）。
  5. **切片美德池 = 勇猛 + 振奋**（morale §6.1 / blueprint §5c 建议）；因「振奋每回合回士气」数值缺失（O-27），当前 tuning `collapse.virtue_pool` 实际仅 `["virtue_brave"]`，数值补齐后加数据扩展即可（buff.md §1「加 buff 只加数据」）。
  6. buff = 修改器 + 钩子 + 生命周期（buff.md §1）；属性修正**加法先于乘法**（buff.md §3）。
- **完成判据（可测）**：
  - 折磨：士气回 50 → 折磨移除，**同一时刻**恢复判定资格。
  - 美德：士气再归 0 → 美德消除 → 士气回 50 → 重新判定（=折磨或美德）。
  - 美德不叠层：已有美德时再判定得美德 → 不替换、不叠加，仍 1 个。
  - 勇猛效果断言：造成伤害 **+25%**、免疫恐惧（buff 修改器 / 状态标记可断言）。
- **风险/开放**：O-27（振奋数值缺失，美德池仅勇猛）。

### T-M4-06 虚弱 & 死门
- **上游**：[设计] GDD §3.3/§3.4；combat_math.md §6；morale.md §4 · 决策：#123, #164, #117, #114, #115, #24
- **依赖**：T-M4-02（崩溃判定）、T-M2（DamagePipeline）、T-M3（死门抗性属性 / IBuffLedger）
- **产出**：`res://scripts/gameplay/sim/survival/DeathsDoor.cs`（blueprint §9.5 `IDeathsDoor`）+ Weak 状态机；`res://data/tuning.json`（`weak` / `weak_exit_hp_ratio` / `deaths_door`）
- **要点**：
  1. HP 归零 → **不死亡** → 士气置 0 + **立即崩溃判定**（T-M4-02）→ 进入**虚弱**：伤害 **-50%** / 速度 **-30%** / **HP 锁 1**（tuning `weak`）。
  2. 虚弱中**再受任意伤害** → 死门判定：存活概率 = **死门抗性 − (折磨中 ? 10% : 0)**（#123）；`rand(0,100) < 存活概率` 存活。
  3. **死门抗性表**（units.json `deaths_door_resist`，仅我方）：战士 **70** / 坦克 **75** / 军医 **60** / 政委 **60**。
  4. 伤害来源含：直接攻击、流血等持续伤害、护卫替挡（buff.md §7.1）；**位移不产生伤害 → 不触发死门**（#117）。
  5. 虚弱中伤害**不改 HP（恒 1）**，直接判死门；存活留 1、失败归 0 死亡（**O-15 已架构裁定**）。
  6. 死亡 → 全队士气 **-15**（morale_events `ally_death`）+ **向中靠齐**（虚弱者不参与前移、全虚弱留空不补 #114/#115/#24）。
  7. 归队：虚弱者士气回升 ≥ 50 → 脱离虚弱 → **HP = 最大血量 10%**（#164）。
- **完成判据（可测）**：
  - 死门抗性复算：战士（折磨 -10%）= **60**、坦克 = **65**、军医 = **50**、政委 = **50**；`rand<存活概率` 存活。
  - 虚弱中任意伤害**只走死门、HP 不变**（O-15：不改 HP 恒 1）。
  - 死亡 → 全队 -15 + CloseUp（虚弱者不前移）。
  - 归队：士气 ≥ 50 → HP = 最大血量的 **10%**（#164）。
- **风险/开放**：O-15（HP 算术已裁定）、O-17（状态标记互斥见 T-M4-09）。

### T-M4-07 虚弱士气回升
- **上游**：[设计] morale.md §9；GDD §3.3；combat_math.md §5.2 · 决策：#59, #157
- **依赖**：T-M4-06、T-M4-01（士气台）、T-M2（FormationBoard 支援位查询）
- **产出**：`MoraleLedger.SupportSlotRegen`（blueprint §9.4）；`res://data/tuning.json`（`weak_recovery`）
- **要点**：
  1. 每回合回升 = **10 + (健康支援位队友数 × 5) + (韧性 ÷ 20)**，**上限 25**（tuning `weak_recovery`）。
  2. 支援位加成只来自**【健康】（非虚弱）**队友；**虚弱者之间互不提供**加成（避免「全员虚弱互相奶」）。
  3. 回升在回合开始结算（与「振奋」钩子同点，buff.md §4）。
  4. 与「虚弱受伤 -5」（T-M4-01）同一回合可同时发生：净变动 = 回升 − 受击惩罚（每回合≤1 次）。
- **完成判据（复算样例）**：
  - 韧性 100、0 健康支援位 → `10 + 0 + 5 = 15`（≤25）。
  - 韧性 60、2 健康支援位 → `10 + 10 + 3 = 23`（≤25）。
  - 韧性 100、3 健康支援位 → `10 + 15 + 5 = 30` → 钳制 **25**。
  - 虚弱者互不提供：2 虚弱者 + 0 健康 → 仅 `10 + 韧性÷20`，不含 `+5×2`。
- **风险/开放**：无（数值已定）。

### T-M4-08 护盾 / 护卫
- **上游**：[设计] buff.md §7.1；combat_math.md §8.1 · 决策：#156（护盾按次数/只挡物理）、#159（护卫边界/驱散）、#136（守护重定义）、#123（折磨 -10%）
- **依赖**：T-M4-06（死门）、T-M2（DamagePipeline 受伤害前钩子）、T-M3（IBuffLedger）
- **产出**：`res://scripts/gameplay/sim/buffs/ShieldGuard.cs`（blueprint §9.9 `IShieldGuard`）；`res://data/buff_defs.json`（`shield` / `guard_attach`）
- **要点**：
  1. **护盾** = 按次数抵挡 N 次物理攻击（铁壁 = **2 次 / CD 4**，`tank_iron_wall`）；**被挡这次完全无效**（不扣 HP、不触发死门、不触发虚弱、不进入后续结算）。
  2. **精神类攻击穿透护盾**（伤害照常、士气照扣 #157）；**流血 / 位移 / 自我伤害不消耗**次数；**AOE 算 1 次**攻击（#156）。
  3. **护卫** = 伤害重定向：**实时判守护范围**（结算时）、**每回合最多重定向 1 次**、重定向后**再算保护者防御**、**虚弱保护者替挨触发死门**、**只挡物理**（O-22 可推翻）。
  4. 被守护者 **+3 士气**（#136）。
  5. **驱散**（#159）：负面可驱散（折磨/眩晕/捆缚/流血/属性减益），正面与**虚弱不可驱散**；**1 次 1 个 / 消耗行动 / 100%**。
- **完成判据（链式用例）**：
  - 护盾「被挡完全无效」：带 1 次物理攻击打护盾 → 不扣 HP、不触发死门、不触发虚弱、士气不变。
  - 精神攻击穿透护盾：扣 HP、扣士气 **-8**。
  - 流血 / 位移 / 自我伤害**不消耗**护盾次数；AOE **消耗 1 次**。
  - 护卫每回合重定向 ≤1；重定向后再算保护者防御；虚弱保护者替挨 → 触发死门（O-15 口径）。
  - 护卫只挡物理（精神不替挡，O-22 标注可推翻）。
- **风险/开放**：O-22（护卫只挡物理，未独立立策可推翻）、O-25（护盾重复施加叠层）、O-26（护卫持续时长未标）。

### T-M4-09 状态机组合用例
- **上游**：[设计] blueprint §5c（状态图）；morale.md §8；buff.md §5.1/§8.1 · 决策：#94, #67, #123
- **依赖**：T-M4-01 ~ T-M4-08 全部
- **产出**：`res://tests/*StateMachineTests.cs`；组合用例表（本文档）
- **要点**：
  1. 由 blueprint §5c 状态图导出用例表：`Normal→Weak→Dead`、`Afflicted→Normal`、`Virtuous→Afflicted→…`、`Virtuous→Virtuous`（重判=美德，上限 1 不叠层 #94）。
  2. 折磨 / 美德 / 护盾等 buff 与虚弱**正交存在**，由 `IBuffLedger` / 状态标记承载，**不并入状态机**（blueprint §5c）。
  3. **O-17 互斥**：眩晕 + 捆缚并存 → **后者覆盖（取较长者）**（buff.md §8.1）。
  4. **O-18 正交场景**：崩溃判定 × 虚弱交叠——如「余烬 / 折磨中 HP 归零 → Weak + 立即判定去重」；`Afflicted × Weak` 可并存且状态独立推进。
  5. **buff 驱散**：#159 负面可驱散、正面与虚弱不可驱散（见 T-M4-08）。
  6. 敌方无士气 / 虚弱 / 死门，不套本状态机（enemy §1 / blueprint §5c）。
- **完成判据（可测）**：
  - `Normal→Weak→Dead`：HP 归零 → 虚弱 → 死门失败 → 死亡 + CloseUp 全链事件序列断言。
  - `Afflicted→Normal`：士气回 50 → 折磨结束。
  - `Virtuous→Afflicted`：美德中士气再归 0 → 消除 → 回 50 → 重判 = 折磨。
  - 互斥：眩晕 + 捆缚并存 → 按后者覆盖（取较长者）。
  - 正交：`Weak + Afflicted` 可同时存在，各状态独立推进。
- **风险/开放**：O-17（互斥占位）、O-18（正交闭环）、O-16（数据口径冲突源，见 T-M3）。
