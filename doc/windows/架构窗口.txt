#### ② 两条**假通过**（我判据口径的缺陷，不是主程序的错）
```
现象：审计把【纯布局容器 `MarginContainer`】当成"满屏不透明模态覆盖层"（它竟能解析出 `panel` 样式 a=1）
⇒ 审计范围被缩进那个子树 ⇒ 地图屏曾报"2 Label / 重叠 9→0 / ✅"、战斗屏曾报"10 Label / 0 / ✅"
⇒ 🔴 真相：地图屏全场景 **2 对重叠（未通过）**；战斗屏全场景 **59 Label / 391 重叠 / 22 透明（远未通过）**
修法（`7067c77`）：① 覆盖层判定只认【能画底的 `Panel`/`PanelContainer` 类】（纯容器遮不住任何东西）
                  ② 报告**强制**追加【口径自证行】：覆盖层是谁/什么类/样式来源 + **全场景计数** + **范围外控件数**
📌 建议登记为"判据缺一致性"的**第 4 例**（与前三条并列进 `ui_spec §14.5`）：
   **"① 审计范围是否被悄悄缩小 ② 范围外是否还有控件" 必须一起打出来**
```

#### ③ `--ui-audit` 失声的真因（取证，不是推测；主程序交接的卡点，已解决）
```
`_Ready` 内直接 `GetTree().Root.AddChild(timer)` ⇒ `Root` 正在 add_child 本场景（busy）⇒
  ERROR: Parent node is busy setting up children, `add_child()` failed
  [2] MainMenuRoot.PrintUiAudit() (MainMenuRoot.cs:63)　[3] _Ready() (:75 / :157)
⇒ 定时器**根本没进场景树** ⇒ 一行都不输出（退出另报 `ObjectDB instances leaked` = 泄漏的就是它们）
修法：新增 `scripts/ui/UiAuditHook.cs`（挂 `SceneTree.Root` + `CallDeferred` 入树 + 每屏跑满 5 次以最后一次为准）
```
