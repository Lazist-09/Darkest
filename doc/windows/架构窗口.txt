#### 🔴 ② 本轮抓到的最重要一条：**地图屏有三块 UI 一直是死的**（不是布局问题）
```
现象（引擎报错原文）：Script inherits from native type 'CanvasLayer', so it can't be assigned to an object of type: 'PanelContainer'.
根因：`LightBarPanel` / `PathChoicePanel` / `InventoryPanel` 三个类的 C# 仍是 `CanvasLayer`，
      而 `Expedition.tscn` 已把这三个节点声明为 `PanelContainer` ⇒ **脚本挂不上** ⇒
      **光照条 / 选路面板 / 背包格子 = 内容与交互全死**（红线 18：玩家碰不到选路；P21 ⑬ 的界面端失效）⚠️
证据（同一次运行的对比）：修之前该屏**可见 Label 只有 4 个**；修类之后 **9 个**（内容回来了），判据仍 0/0 ✅
📌 这也解释了此前那次"地图屏 ✅ 可见 Label 2"为什么会绿：**面板没挂上 ⇒ 没内容 ⇒ 没重叠**（"绿"是因为空）
```
⇒ 建议：把"**场景节点类型 ↔ 脚本基类必须一致**"写进验收口径（或加一条静态检查：扫 `.tscn` 的 `type=` 与脚本基类）。
⚠️ 这类缺陷**判据本身查不出来**（它只测重叠/透明）—— 只有"引擎错误清零 + 可见 Label 数合理"才暴露它。

#### 🔴 ④ 一条 Godot 引擎坑（值得进契约：它决定"满屏模态"能不能立起来）
```
本屏根是 `Node2D` ⇒ Godot 的 `get_parent_anchorable_rect()` 为**空** ⇒ Control 的 `FullRect` 锚点算不出尺寸；
而"锚点不动、只设 `Size`"会被引擎覆盖（实测警告：*Nodes with non-equal opposite anchors will have their
size overridden after _ready()*）⇒ 模态面板只有 min size，内容挤到左上角并压住光照条刻度（实测 6 对重叠）。
✅ 正解（已落）：先造一个【锚点相等 + 显式 `Size` = 视口尺寸】的满屏 `Control` 宿主（`ModalHost`），
   模态再挂在它下面 ⇒ `FullRect` 才算得出满屏 ⇒ 判据也才认得出"这是模态"✓
   （`BattleUi` 当年用 `CanvasLayer` 做根刚好绕开了这个坑：`CanvasLayer` 不是 CanvasItem ⇒ 锚点直接对视口）
```
