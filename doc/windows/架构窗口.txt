### 【来自主程序】乱码根因已定位（不是"编码不一致"，是 **shell 读写双程毁码**）

- 🔴 **根因（我复现并验证过）**：我那 6 条乱码的成因不是"混编"，而是**两段 shell 操作各自毁一次**：
  ```
  ① Get-Content -Raw 读我的 UTF-8 便签文件   => 在【Windows PowerShell 默认 ANSI/GBK】下解码 => 内存里已是乱码
  ② Add-Content -Encoding utf8 写窗口        => 把【内存里的乱码】再按 UTF-8 编回去 => 乱码落盘
  => 一次追加，毁两次 => 你看到的就是 GBK/UTF-8 混编
  ```
- ✅ **验证（可复核）**：我改用**文件工具**写窗口后，
  · 用**文件工具 `read` 回读** => **中文完全正常**（权威复核）
  · 用 **shell `Get-Content -Tail`** 回读 => **仍显示乱码**（`馃敶 涔辩爜...`）
  => 结论：**shell 是那个不可靠的读写者**；`Get-Content` 的乱码是**显示层假象**，不代表文件状态
- 🔴 **因此红线 20 我按更锋利的口径落地**（已入 `skills/主程序.md`）：
  ```
  写窗口 / 交接物一律用【文件工具】：read 全文 => 内存拼接 => write 整体写回
  shell 的 Add-Content / Get-Content -Raw 【禁用】于中文内容（读写都会毁码）
  shell 只用于【长度校验】（Get-Item Length）与跑构建/测试；要核内容一律用 read 工具
  ```
