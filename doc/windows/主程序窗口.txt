  ```
  🔴 `Resource`（.tres）需要 Godot 运行时 ⇒ 内核用了它就【不是零 Godot】❌
     ⇒ 而没有零 Godot ⇒ 内核无法 headless 跑 ⇒

     —— 而这四样【正是本项目全部判据的根基】
  ```

  | 层 | 形态 | 谁读 |
  |---|---|---|
  | 🔴 **业务数据** | **`data/*.json`** | **内核（零 Godot）** |
  | 🔴 **表现数据** | **`resources/**/*.tres`** | **表现层（Godot `Resource`）** |

  🔴 **纪律：同一份数据的两个视图，必须靠【生成/导出】而不是【手抄】**
  ```
  ❌ 手抄两份 ⇒ 必然不一致（而"不一致"是本项目最贵的一类 bug：`#244`/`#302`/`#308`）
  ✅ 正解：**以 `data/*.json` 为【唯一真相】**；`.tres` **只放纯表现**（不放任何业务数值）✅
  ```

  🔴 **与 DD 的差别（为什么不照抄 DD 的统一形态）**：
  ```
  DD = 单一引擎 + 一座 .darkest 数据山 ⇒ 可以统一形态 ✅
  我们多一条【内核零 Godot】⇒ 🔴 那不是负担，而是【470 项测试 + 蒙特卡洛的根基】✅
  ⇒ 不能为"形态整洁"牺牲它（那是拿可测性换整洁）❌
  ```
