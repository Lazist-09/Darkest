## 2. Godot 节点生命周期（易爆点）

- `_Ready()` 内**不得直接切场景**：父节点正增删子节点 ⇒ `Parent node is busy adding/removing children` 并 exit 1 ⇒ 必须 `GetTree().CallDeferred("change_scene_to_file", path)`。
- 同类：`_Ready` 内增删子节点、`QueueFree` 后立即访问。出处 O-74 地牢层入口（架构收进 blueprint §9.14）。
- 🔴 **它的连锁后果（`#319` 实测）**：引擎错误之后**场景树状态不一致** ⇒ UI 判据会**乱认浮层**（把 `VBox` 当"满屏不透明面板"）⇒ **读数与结论全部不可信** ⇒ **先修引擎错误再谈验证**（别拿污染后的读数下结论）。
- 🔴 **`CallDeferred` 到"即将被释放的节点"= 永不执行**：切场景改 deferred 后，主菜单节点先被释放 ⇒ 挂在它上面的延后调用（含建审计定时器）**一行都不输出** ⇒ 审计定时器要挂**场景树根**、并在 `_Ready` **第一句**建立。
- 🔴 **`CanvasLayer` 不是 `Control`**：子控件不在 Control 链上（不受 Theme 管、没有"框"）；且 **`Container` 不会排它**（只管理 Control 子节点）⇒ 纳入容器树前先把类改成 `Control` 系（如 `PanelContainer`）并同步改 `.tscn` 的 `type=`。
- 🔴 **`AddChild` 不自动换父**（`Can't add child … already has a parent`）；`Reparent()` 在"边遍历边搬"时触发内部断言（`p_child->data.parent != this`）⇒ **控件在创建时就加进目标容器**，不要事后搬运。
- 🔴 **容器子项必须给 `CustomMinimumSize`**（或 `size_flags`），否则分配 0 尺寸 ⇒ 重叠。
- `GetViewport().GetVisibleRect()` 在 headless 下**尺寸会波动**（见过 1280×1280 与 2560×2000）⇒ 不要拿具体尺寸当判据；判"锚点 1/1 / 是否跟随视口"。

## 2.1 布局基建与 UI 判据（`ui_spec §14` / `#319`）

- 目标（用户原话）：**文字不重叠、每个东西在自己框里、框不透明** —— 治它的是**布局基建**，不是美术素材。
- 四条硬规则：① 删掉手写 `Position/Size` ② 每块 = `PanelContainer` + `StyleBoxFlat`（`BgColor.a=1.0` + 1px 边框 + 圆角 0）③ 内部 `VBox/HBox` 自动堆叠 ④ 给最小尺寸。
- 顶层：`Root → MarginContainer → VBox（顶栏/主体/底栏）`，每分区一个 `PanelContainer`；**中央 Theme 挂【容器树的根】**（挂错层 ⇒ 引擎默认样式，实测 `a=0.6`）。
- 🔴 **两条自动判据（`--ui-audit`，每屏必跑）**：① 可见 `Label` 两两不相交 ② **`Panel` 与 `PanelContainer`** 的 `BgColor.a == 1.0`。
- 🔴 **判据口径纪律**（连续 3 次踩到）：只收 `Panel` 漏 `PanelContainer` ⇒ 假通过；模态浮层之下被遮 Label ⇒ 假重叠（应只审最上层浮层）；空文本/过早判定 ⇒ "Label 0 / 通过"假通过（跑满 N 次以最后一次为准）。
- 参考读数（本轮）：城池 重叠 2→**0**、Panel 0→5 ✅；角色详情 0/0 ✅；地图 重叠 9→**0**、透明 3→**0** ✅；战斗 **未通过**（判据曾受引擎错误污染）。

## 4. 提交纪律（附 C.1，实证事故）

- 提交前 `git status --porcelain` 看清单；大文件(>1MB)/外来目录（参考副本、缓存、导出物）先看再决定。
- `git add -A` 非默认安全；参考目录写进 `.gitignore`（`Example/`、`**/Darkest Dungeon/`、`*.csd`、`*.csm`、`*.depotcache_*`）。
- 误提交：`git reset --soft HEAD~1` → `git restore --staged <外来>` → 重提交 → `git reflog expire --expire=now --all` + `git gc --prune=now` 回收；校验 `git show --stat HEAD | Select-String <外来>` 须 0 命中。
- 提交信息不用 ASCII 双引号（用「」或不用）——PowerShell 截断致静默失败；根治：写文件再 `git commit -F <文件>`（无 BOM UTF-8）。

## 5. 三角窗口投递模板（主程序收件箱 = 主程序窗口.txt）

```markdown
### 轮次：<日期> · <一句话主题>
- **我做了什么**：<≤3 行>
- 🔴 **需要你做什么**：<逐条、可执行>
- **阻塞 / 待裁定**：<有就写；无写「无」>
- **权威在哪**：<doc/ 具体文件 + 章节>
```

- 写对方窗口 = **先读全文 → 拼接 → 用 write 整体写回**（幂等、不夹带命令、不重复）。
- 清空自己窗口前确认每条已处理/已转写 doc；没确认就清 = 丢交接项。
- 写入失败立即重读补写，当轮不滞留；只有 read 回读能证明信在窗口里。

## 6. 复测报告 9 字段（reports/*.json，缺 D/E 基线不成立）

1. 判据 A1 单场：胜率≥85% / 死门≤0.4 / 阵亡≤0.1 / 回合4~6
2. 判据 A2 run：完成率[40,70]（含撤退口径，撤退即放弃作诊断）
3. 实测 D（我方每回合对敌总伤害）
4. 实测 E（敌方每回合对我方总伤害）
5. 我方自愈总量/场（HealEvent 求和÷场数）
6. SP 存量/花费(治疗·增援)/待命次数/成功增援次数
7. 口径健康度：敌方命中各槽分布(1号位占比<50%)+池外移动占比
8. KPI 七项：士气触底/虚弱/死门/撤退/美德/折磨/位移
9. 多场曲线：每场结束存活人数/HP%/士气%
