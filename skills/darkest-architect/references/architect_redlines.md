## 3. 可观测性与门禁清单

- 报告/UI 数字必须先从事件流能算出；算不出＝事件字典缺项，不得为某消费者单造数据。
- "不显示" ≠ "不记录"：`RngDraw`/`DrawCount` 必须记录（回放/确定性审计），仅默认不显示。
- 新增字段尾部追加+默认值（不破既有测试）；新增随机必写 `RngDraw`；预览路径必须不掷骰。
- 同类偏差重复出现即升格为数据门禁（**P1~P27** 的做法：一句话规则 → 一条 fail-fast 校验）。
- 🔴 **未接线的枚举/字段：不入白名单、UI 不显示**（`BuffDefsConfig.ConsumedEffectNames` / `CampSkillsConfig` / `RoomContentsConfig` 同一道防线）。
- 🔴 **运行期遇到不认识的引用 ⇒ 显式留痕跳过**（如 `curio_pool_unresolved:$pool:xxx`），**绝不静默当成能用的东西**。

## 4. 三向差异对账（自动化）

```
每批改动逐字段比对：
  策划表（doc/modules/*.md 数值表）
      ↕
  data_schema 两档（现生效 / 目标）
      ↕
  实现 JSON（darkest/data/*.json）
→ 输出【差异表】；凡差异必须显式标注「待落地」，否则【报错】
```
- 为什么必须机器做：一次人工走查查出 **7 处漂移**（5 处同类：改了决策没回头改引用处）。
- 典型：`skill_data.md` 仍写 4 条 `*_move`/总 47（`#191` 已改）⇒ 实现方照抄会造出已删除技能。

## 6. 判据可同时成立性预检（纪律16）

| 步骤 | 动作 |
|---|---|
| 1 | 每条判据同时写出它要求的"方向"（↑/↓） |
| 2 | 方向相反 → 任务卡显式标注「判据冲突」，不得直接开给主程序调 |
| 3 | 同向但余量 → 把两条写成共同约束的同一个量，算清余量 |

样板（`#256`）：`完成率 = p^6` 落 [40,70] 需 `p≈0.90` ⇒ 需 10% 场次"输" ⇒ 代价死人/濒死 ⇒ 正撞 A1「阵亡 ≤0.1」⇒ 不可兼得。正确处置：标注"当前机制下不可达"+ 待引入"让玩家自选风险"机制后复评，**不调参硬压**。

## 7. Godot 内置判定五问

1. 引擎是否已有该能力？
2. 有没有内置类型/节点/资源可直接用？
3. 有没有内置编辑器工具链（`[Tool]`/`[Export]`/`Theme`/`TileSet`/`EditorPlugin`）能让非程序员改？
4. 我自研的版本能否被内置替代，且不破坏分层？
5. 若必须自研（内核为可测性/确定性）——理由是否写在注释里？

**分层边界**：内核（`core`/`sim`/`data`/`tests`）刻意零 Godot；表现层（`ui`/`gameplay/scene`/`scenes`）必须优先用内置。

**顺序（`#319` 调整后）**：**② Theme+容器+锚点（布局基建）优先** → ③ 焦点+手柄 → ④ 动效 → ⑤ 音效 → ⑦ 材质/字体/图标。
**UI 验收可自动化判据（`#319` ⑤）**：所有可见 `Label` 两两不相交 · 每个 `Panel` 的 `BgColor.a == 1.0`（遍历四个界面）。
**落点**：Theme→`resources/theme/` · 材质→`resources/shaders/` · 音频→`resources/audio/` · i18n→`resources/i18n/` · 预制件→`scenes/**/prefabs/`。

## 8. 跨层风险 O-84（实测）

- 表现层 **20 处**用 `FileAccess`（导出安全），而 `BattleUi.cs` 用 `System.IO` 磁盘路径 ⇒ 发行版 `data/*.json` 在 PCK 内 ⇒ `File.Exists` 失败 ⇒ 抛异常。
- 规定：**表现层读数据一律 `FileAccess`/`ResourceLoader`**；`System.IO` 只允许内核，且由组合根把【字符串】喂进去（内核不接触路径）；**组合根是唯一相接处**。
- 取证：`Select-String 'File\.ReadAllText|DirectoryInfo'` ⇒ `scripts/ui` 与 `scripts/gameplay/scene` **必须 0 命中**。

## 9. 参考真机六条纪律

1. 只看格式/目录结构/数值组织方式——不抄文本、数值、美术、音频、动画资源。
2. 真机用 Spine/FMOD 等商业中间件 ⇒ 素材一律不碰。
3. 学三问：它解决什么问题？我们有同一个问题吗？照抄会破坏我们的分层吗？
4. 凡"借鉴"必须落成【我们自己的字段/文件】，契约写明【与真机差异及理由】。
5. 真机是参考不是规范：已拍板设计不因"真机这么做"而改（走新决策先提请策划）。
6. 已确认结论：**效果项数组 + 按名分发 + 加载级白名单**与中国侧 `ConsumedEffectNames` 同构；**拓扑生成 × 房间内容表分两层**（`*.mash.darkest` = `hall/room + .chance + .types`）；**本地化 = 每语言文件 + 每域 string_table**（数据存 key）。

## 10. 窗口投递 / 回执模板

```markdown

- **我做了什么**：<≤3 行，镜像了什么 / 转了哪些 O-nn>
- 🔴 **需要你做什么**：<逐条、可执行>
- **阻塞 / 待裁定**：<有就写；无写「无」>
- **权威在哪**：<doc/ 具体文件 + 章节>
```

```
【架构回执】vX.XX
· 已镜像：<清单>
· 待策划补（架构侧不代写）：<文件/章节 + 具体项>
· 提请裁定：<O-nn + 候选 + 各自后果>
· 接口基线：<有 / 无变化>
```
